### Medium

**F2 — `TestTheSkillIndexFitsItsBudget` measures the machine, not the tree** · test · pass 1 · Confirmed
`internal/agent/prompt_index_test.go:20-43` prices the skill index as `len(BuildSystemPrompt(Skills)) − len(BuildSystemPrompt({}))` over skills extracted into `t.TempDir()`, so the byte count includes each line's absolute path length. Parent-verified: the index measures **1919 B** on a standard path (the recorded "measured exactly 1 980" in the test comment and SPECS §15 does not reproduce — 1980 − 1908 = 72 = 6 lines × 12 B of longer base path) and the pin **fails red outright** with a ~133-char `TMPDIR` (2429 B > 2150 ceiling).
**Fix:** normalize the path out of the measurement (fixed-shape sentinel extraction dir, or subtract `6·len(base)`); re-record the normalized figure in the test comment and SPECS §15.

**F3 — `skills.Fork`'s failure cleanup can delete a directory it did not create** · code · pass 2 · Confirmed (code path; race not reproducible at CLI granularity)
`internal/skills/fork.go:59-68`: `Lstat` refuses a pre-existing dst, but a dst created inside the Lstat→copy window makes `copySkillTree` (:76-113) *merge* (per-file `O_EXCL` fails on first collision), and the error path then runs `os.RemoveAll(dst)` over everything at dst — including files the fork did not write. Unlike `seedOne` (`internal/skills/seed.go:228-270`: temp dir + rename + planted-first fallback) there is no rename step, and unlike the auth/trust/config writes no `internal/flock`. 50 concurrent-fork trials at CLI granularity produced 0 deletions (the window is narrower than process spawn), but the hazard is pinned by a `copySkillTree`-onto-pre-existing-dst probe.
**Fix:** copy into a temp dir and rename into place (the `seedOne` shape), or re-verify dst contents before any `RemoveAll` and remove only what this copy wrote; delete the unconditional `RemoveAll`; pin with a test that a dst appearing mid-copy is never destroyed.

**F4 — reuse checker: an obfuscated duplicate plus a test-only helper reference passes all four arms** · evals · pass 2 · Confirmed (rc=0)
`test/evals/reuse/check.sh:29-36`: arm 4 greps `human\.Bytes(` over `./cmd ./internal --include='*.go'` — `_test.go` files count, so a production duplicate formatter with `human.Bytes` referenced only from a test file satisfies the arm whose comment says it "catches a deleted helper". Arm 2's divisor regex (`1024|1048576|<< 10|>> 10`) misses `1<<(5+5)`. Verified: a runtime-identical duplicate (renders the pinned `1.5 KiB`/`2.0 MiB`) with a `_test.go`-only `human.Bytes` reference passes every arm.
**Fix:** exclude `_test.go` from arm 4 (and arm 2's scan); consider keying arm 4 to the file that produced the verified rendering; add the leak case as a selftest row.

**F6 — `-p` does not reserve `/remember`; TUI and ACP do** · code/contract · pass 2 · Confirmed (probe + code)
`cmd/moca/oneshot.go:157` calls `skills.ExpandCommand` with no `/remember` special-case; `internal/acp/commands.go:191-197` reserves it unconditionally and `internal/tui/commands.go:36` lists it as built-in. The divergence is introduced by this range (the `-p` expansion is new in `51f7738`).
**Fix:** move the remember reservation into the shared path — ideally into `skills.ExpandCommand` so the three surfaces cannot drift — or at minimum into `runOneShot`; update SPECS §3.

**F11 — Guard false-refusals and bypasses around the first-backtick cite rule** · code/security-adjacent · pass 2 · Confirmed (probe-confirmed end-to-end through `ValidateSkill`)

## Improvement proposals (non-defect)

1. **House rule candidate:** any byte-count pin that includes an absolute path must normalize path length — F2's root cause is a recurring class, not a one-off.
2. `copySkillTree`'s symlink refusal (`internal/skills/fork.go:87-88`) has no test; one case would pin the command's traversal-safety story.
3. `moca update skills` rewrites the bundle files of a user-customized seeded skill without backup (documented intent, SPECS §12); consider a one-line `--dry-run` reminder or a `.bak` sibling for replaced files.
4. A doc-sync pin for "record X is carried by file Y" cross-references — the mirror test catches byte drift, not dangling references; a cheap grep-style test over CHANGELOG/plan/BASELINE would have caught F1.
5. A CI check enforcing §16 same-commit SPECS updates for commits touching `internal/` or `internal/skills/builtin/` — mechanical instead of review-caught. (Two §16 deviations found in the range: `c194ca9` documented its debt-skill behavior change four commits later, and `594dd10`'s SPECS text landed in the release docs commit.)
6. `UpdateSeedSkills` has no rollback on a mid-loop I/O failure (mixed old/new bundle until the next refresh converges) — document, or make the loop two-phase.
7. `cmd/moca/oneshot.go:131-133` builds the session slug from the raw prompt before the `/name` expansion at :157 — slug from the expansion so `moca -p "/review src"` sessions are discoverable by what actually ran.
8. `internal/agent/system-prompt.md:26-27`: one clause — "a `shortcut:` marker documents a limit; it never licenses the never-cut list" (the `/debt` skill currently labels a marker "a decision", the exact reading the bound was meant to prevent); define what "Trivial changes need none" covers.
9. BASELINE.md's "newest section" parenthetical would be better kept in sync by the same touch that adds a section (see F20).
10. Commit-record clarity: the `403fc1f` squash (PR #89) contains three logical changes — the rtk/graphify refresh, a graph refresh, and the `moca update skills` feature — but the title names only the first; the body compensates, but the title under-describes a new user-facing subcommand.
