# codemode — implementation plan, v6

**Status:** implementation-ready proposal. Decisions D1–D3 and D6 approved by the maintainer on 2026-11-22; Tasks 1–6 are authorized to start. No runtime, benchmark result, spend or release is approved by this document. Supersedes [v5](2026-11-22-codemode-v5.md); reviewed against plan head `6540248` with v5 at `7cb15ef` (no product-code delta from `81fc50d` — `git diff --stat 81fc50d HEAD -- . ':!docs'` is empty). Recheck the baseline before capturing goldens.

**Goal:** let an agent inspect and reduce workspace data with a short, disposable JavaScript program. A multi-file join sends one bounded result instead of forty file bodies; an ordinary one-file search does not get more expensive. Both claims have controls.

**Architecture:** one custom QuickJS-NG reactor, embedded in the Go binary and run by wazero. A fresh guest per script; one process-wide execution slot. Exactly three synchronous read-only workspace operations — `tools.read`, `tools.search`, `tools.ls` — reached through a Go bridge anchored at the workspace with `os.OpenRoot`, independent of permission mode. No container, shell, external interpreter, admin privilege or runtime download on Linux, Windows or macOS. The guest has no filesystem; the bridge is the only file authority. This is not an OS sandbox for moca or its shell tool.

**Tech stack:** `go 1.27` / `toolchain go1.27.4` unchanged. One new direct dependency, `github.com/tetratelabs/wazero v1.12.0` (Apache-2.0, pure Go; `x/sys` already indirect). QuickJS-NG is a shipped MIT artifact, not a Go module; its toolchain is maintainer-only.

**Sequencing:** Tasks 1 and 2 in parallel; both must pass before Task 3. No billed call before Tasks 1–6 pass. Task 7 decides whether to ship; Task 8 closes the PR. Spec edits stage with the behavior they describe. No commit, publish or charge without separate approval.

## Decisions

**D1 — opt-in precedence follows the repo's own resolver.** `ResolveCodemode` mirrors `ResolveSelfManagedSkills` (`internal/config/config.go:125–150`) exactly: on only when the **user** config says `true` and a trusted project file does not say `false`. A project `true` alone warns and does not enable; an untrusted project contributes nothing. A project `true` cell that enabled the tool would be a one-cell change plus its resolver test, not a new design. **Approved 2026-11-22.**

**D2 — steering.** No new nested call after steering is observed at admission. Already-admitted I/O may unwind; CPU-only JS is bounded by its deadline. In a batch containing a codemode call that returned `steered`, unstarted outer siblings are skipped and paired with a not-executed result; the message is delivered once, ahead of the repeat-stop. Controlled by one constant, `skipSiblingsOnSteer = true`, so the weaker behavior (stop nested calls only, run siblings) is a one-line change. **Approved 2026-11-22.**

**D3 — the steering seam is a function on `Env`, not an import.** `internal/tools` never names `agent`. `Env.Admit func() bool` (nil = admit) is set by `agent.build()` to `a.admitNested`, which takes `a.mu` — the same mutex `Agent.Steer` uses (`control.go:223–226`) — for the admission decision only, never across I/O. The adapter also sets `tools.Result.Steered`, a typed field the agent reads instead of parsing guest-controlled content. **Approved 2026-11-22.**

**D4 — dependency and footprint costs are measured separately from benefit.** All six release packages, default-off startup, cold and warm latency are reported whether or not adoption looks good. No automatic runtime switch, budget increase or paid rerun on a failed gate.

**D5 — one path, no fallbacks.** Interpreter only; no compiler auto-switch. Official WASI module only; no hand-written stub module in v1. If a gate fails, the plan stops and revises — it does not silently degrade.

**D6 — native CI cost model.** The macOS/Windows matrix lives in a `workflow_dispatch` workflow that must pass before merge, not an always-on runner: the repo's standing CI stays a single ubuntu job. Promoting it to permanent is a follow-up decision, not part of this plan. **Approved 2026-11-22.**

### ABI

```
export  qjs_init(mem_limit_bytes: i32, stack_bytes: i32) -> i32          // 0 ok, -1 fail
export  qjs_run(src_ptr, src_len, out_ptr, out_cap, out_len_ptr) -> i32  // status; out_len always set
export  qjs_destroy() -> void
import  moca.invoke(req_ptr, req_len, res_ptr, res_cap) -> i32           // bytes or -1 too large, -2 host error
```

`qjs_run` status: `0` ok, `1` syntax, `2` throw, `3` out of memory, `4` job limit, `5` output too large, `6` internal. The result envelope is `{"value":…,"texts":[…],"logs":[…],"error":{"class","message","line"}}` in the out buffer; on a trap or a closed instance there is no epilogue, so the host keeps accepted events in Go.

Guest→host frames distinguish `{"op":"inspect","name":"read|search|ls","args":{…}}` from `{"op":"text","value":…}` and `{"op":"log","line":…}`. Events are not tool lookups. Request ≤64 KiB, response ≤320 KiB **encoded UTF-8 JSON**, built with a bounded incremental encoder (no marshal-then-check). The host copies owned bytes before guest memory can change. No nested registry dispatch, no `Ask`, no state stamps, no parallel calls, no nested spill.

### Lifecycle

Lazy process-wide `wazero.Runtime` and `CompiledModule`; `WithMemoryLimitPages(512)` (32 MiB), `WithCloseOnContextDone(true)`; `_initialize` called explicitly, no `_start`; one non-blocking slot (`busy`, no queue); a fresh instance per script, closed on every exit. The per-execution dispatcher is carried in the **call context** (`context.WithValue`), never in a process global, because the host module is registered once per runtime. `qjs_init(12<<20, 1<<20)`.

### Failure ABI and result

Host-owned capture keeps accepted `text`/`log` events and coverage while the script runs; a trap loses only the guest epilogue. Bounded on both sides: ≤200 text events, ≤200 log records × ≤1 KiB, ≤32 KiB combined capture, ≤2,000 Unicode characters for the entire model result with **≥512 reserved** for status/notices, ≤5 coverage examples.

Outer result, one `tool_result`:

```
completed | steered | failed: <class>|<line>
<value and texts>
<console_output>…</console_output>            ← only when used
[codemode: N calls; gaps: …]                  ← only when gaps; ≥1 line even on failure
```

Overflow spills the outer bounded capture through `tools.Spill` (`internal/tools/overflow.go:21`) and names the file; if spilling is off or fails, it reports truncation without promising a file. Timing lives in `Summary`. Classes: `syntax`, `script`, `limit`, `oom`, `timeout`, `cancelled`, `busy`, `steered`, `crash`, `refused`. Host paths in guest errors are masked; host notices use a prefix that guest output cannot forge.

### Bridge

`internal/codemode` is a leaf: stdlib + wazero, no `internal/...` import (test matches the **module's** prefix `github.com/adeotek/moca/internal/`, not a bare `internal/`). `internal/tools` owns the adapter, the collectors and a read-only workspace interface:

```go
type Inspection struct {
    Root   *os.Root        // os.OpenRoot(env.Root), one per Execute, closed after
    Budget *InspectBudget  // counters above
    Ctx    context.Context
    Admit  func() bool
}
func (i *Inspection) Read(path string, offset, limit int, cursor string) (ReadPage, error)
func (i *Inspection) Search(pattern, path string, filesOnly, hidden bool) (SearchResult, error)
func (i *Inspection) Ls(path string, hidden bool) (LsResult, error)
```

Every nested open, stat, enumeration, ignore-file load, search start and cursor re-read goes through `Root`. Enumeration is `Root.Open(dir)` then `(*os.File).ReadDir(128)` until `io.EOF` — `os.Root` has no `ReadDir`. After `Root.Open`, `File.Stat()` must report `Mode().IsRegular()` for a read candidate; this is the mitigation for `os.Root` not blocking `/proc` or bind mounts (documented, not denied). Absolute, device, volume and `..` names are rejected before resolution; workspace-relative names only. `os.Root` follows symlinks only within the root; no fallback to an unrestricted open on any platform. No host write API exists in the bridge. An in-tree readable file can still hold secrets: this is a workspace boundary, not secret detection.

`InspectBudget` is a value with `chargeBytes/chargeEntry/chargeHit` methods returning a reason when exhausted; exhaustion sets `complete:false` and a reason and never silently drops a gap. The executor's deadline interrupts WASM; a syscall already in flight may return later, so the slot and root are released only after all host work unwinds (no detached goroutine, no pool return), tested with a controllable reader that holds a callback past cancellation.

### Payloads, paging, coverage

Success returns a plain object — `lines:[{n,text,clipped}]`, `matches:[{path,line,text,clipped}]`, `paths`, `entries:[{name,kind}]` — plus `complete` and `reasons:[]`. Invalid or denied inspections raise a bounded typed JS error and still record coverage. Unknown `tools` properties throw. A direct `read` may skip a long line and print a later one today (`read.go:118–134`); v6 fixes that in Task 3 (see below) so display and nested paging share one rule: **stop at the first row that does not fit**.

Paging: nested `read` starts at `offset` (default 1), returns an opaque execution-local `next` cursor for the first unread line. `tools.read({next})` is mutually exclusive with `path/offset/limit`; both → `invalid_cursor_args`. The cursor binds `{path, next, digest}` where `digest` is SHA-256 over the bytes of the page just returned; a continuation re-reads and re-digests the same span under the same budget, and a mismatch returns `changed` and retains the gap. Search and `ls` carry **no** `next`. Only consecutive same-version continuations through EOF close a gap; a clipped line, a denied candidate, a changed digest, a skipped page, a budget stop or an unpaged limit stays incomplete. `complete` describes the requested scope only. The host ledger is capped by the attempt count and reports a count plus ≤5 bounded examples.

### Harness (Task 1)

- **Two-turn trial:** a scenario with `followup.txt` runs `moca … -p "$first"`, records the session id8 and the transcript byte length, then `moca … --continue -p "$second"` in the same cwd, config and XDG dirs; one row per trial. `--continue` exists (`cmd/moca/cli.go:132`); `run.sh` does not use it today.
- **Row schema 2** (JSONL, one per trial): `{"schema":2,"scenario":"…","label":"…","trial":3,"turns":2,"arm":"cm-on","session":"ab12cd34","pass":true,"steps":0,"tokens":0,"carry":0,"cost":0.0,"ms":0}`. A row without `schema` is schema 1. `evalstats -compare` errors on schema-2 rows; `-compare-carry` requires schema 2 and no duplicate `(scenario,trial,arm)`.
- **Arms:** `-c cm-on` / `-c cm-off` with `config.cm-on.jsonc` / `config.cm-off.jsonc` per scenario. `on`/`off` are forbidden for the pilot: `test/evals/config.on.jsonc` is the corpus **skills** arm. `run.sh`'s `scenario_config` falls back to the corpus config when a scenario has no `config.<variant>.jsonc`, so a pilot run must **fail** in preflight when `VARIANT` starts with `cm-` and the scenario lacks that file — otherwise the baseline config runs under an arm label. Scenario `check.sh` stays arm-agnostic (`--selftest` invokes it with `VARIANT=on`).
- **Carry:** the sum of moca's token estimates for the UTF-8 content of retained tool-result blocks of **all** tools in the first outbound work request of process two, after reconstruction, trim/elision/compaction; excludes summaries, classifier and retry duplicates. Measured by a build-tagged hook (`//go:build codemodecarry`, one call in `agent.go` before streaming, writing `{session,trial,turn,carry}` to `$MOCA_CARRY_OUT`; the untagged build is a no-op). Cross-checked by decoding the actual serialized request at a scripted provider, including a compaction case, an elided result, a real zero, a retry and a missing observation.
- Task 1 does **not** run `moca` with `codemode` configs: the key does not exist until Task 5 and strict decode would reject it. The arm-config diff assertion belongs to Task 6.

## Risks and stop conditions

| Risk | Stop condition |
|---|---|
| Someone "fixes" the SDK pin back to the `.deb` digest | `build.sh` verifies size **and** hash and names the `.deb` trap in a comment |
| 32 MiB/12 MiB still does not fit representative data | Task 2's measured-fit gate stops before integration |
| The reactor needs an import outside the allowlist | Task 2 fails closed; revise the C, not the allowlist |
| A syscall outlives cancellation | slot/root released only after unwinding; blocked-callback test required |
| `os.Root` limitations are read as secrecy guarantees | disclosed in SECURITY/SPECS; regular-file gate only |
| The gate can be satisfied by a no-op | fixture-derived answer, observed inspection count, negative controls |
| A larger binary or prompt costs more than the feature saves | off-path cost reported; no merge on an inconclusive pilot |
| Scope creeps into general scripting | no write/edit/shell/web/mcp, VM state, host modules, `dataFiles`, second language, parallel calls or default-on; effectful calls need their own opt-in, journal/undo and steering review |
