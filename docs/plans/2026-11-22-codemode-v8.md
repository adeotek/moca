# codemode — implementation plan, v8

**Status:** implementation-ready proposal. v1 (Tasks 1–8) is unchanged from [v7](2026-11-22-codemode-v7.md) except one seam (Task 4's capability map); v1.1 (Tasks 9–12) adds the network capability behind a second, separate user switch. D1–D3, D6 and D7–D11 are approved; D4–D5 are measurement and scope rules, not switches. Task 7's pilot and Task 11's Stage-B pilot each need their own spend approval. No runtime, benchmark result, spend or release is approved by this document. Supersedes v7; reviewed against plan head `fc2b7a3` (no product-code delta from `81fc50d` — `git diff --stat 81fc50d HEAD -- . ':!docs'` is empty).

**Goal:** let an agent inspect and reduce workspace data with a short, disposable JavaScript program — and, when the user separately opts in, the same program may also search and fetch the public web. A multi-file join or a search-then-fetch sweep sends one bounded result instead of many bodies; an ordinary one-file search or one-page fetch does not get more expensive. Every claim has a control.

**Architecture:** one custom QuickJS-NG reactor, embedded in the Go binary and run by wazero. A fresh guest per script; one process-wide execution slot. The guest reaches the host through one import, `moca.invoke`, and the host exposes a **capability table**: `tools.read`, `tools.search`, `tools.ls` always; `tools.web.fetch`, `tools.web.search` only when the network switch is on. Workspace I/O is anchored with `os.OpenRoot` at the workdir, independent of permission mode. Web I/O reuses the existing `web` tool's collectors and SSRF classification; private, loopback, link-local and metadata targets are **denied, never asked**, inside a script. No container, shell, external interpreter, admin privilege or runtime download on Linux, Windows or macOS. The guest has no filesystem and no sockets; the bridge is the only file and network authority. This is not an OS sandbox for moca or its shell tool.

**Tech stack:** unchanged — `go 1.27` / `toolchain go1.27.4`; `github.com/tetratelabs/wazero v1.12.0`; QuickJS-NG as a shipped MIT artifact.

**Sequencing:** v1: Tasks 1 and 2 in parallel, both green before Task 3; no billed call before Tasks 1–6 pass; Task 7 decides whether v1 ships; Task 8 closes the v1 PR. v1.1 starts only after v1 is merged and its pilot returned a signal: Task 9 → Task 10 → Task 11 (gate, then Stage B pilot with fresh approval) → Task 12. Spec edits stage with the behavior they describe. No commit, publish or charge without separate approval.

## Decisions

**D1 — opt-in precedence follows the repo's own resolver.** `ResolveCodemode` mirrors `ResolveSelfManagedSkills` (`internal/config/config.go:125–150`): on only when the **user** says `true` and a trusted project does not say `false`; a project `true` alone warns; an untrusted project contributes nothing. **Approved 2026-11-22.**

**D2 — steering.** No new nested call after steering is observed at admission; already-admitted I/O may unwind; CPU-only JS is bounded by its deadline. A batch containing a codemode call that returned `steered` skips unstarted siblings, pairs each with a not-executed result and delivers the message once, ahead of the repeat-stop. `skipSiblingsOnSteer = true`. **Approved 2026-11-22.**

**D3 — the steering seam is a function on `Env`.** `Env.Admit func() bool` set by `build()` to `a.admitNested`, which takes `a.mu` (the `Agent.Steer` mutex, `control.go:223–226`) for the check only; the adapter sets `tools.Result.Steered` from typed state, never text. **Approved 2026-11-22.**

**D4 — dependency and footprint costs are measured separately from benefit.** All six release packages, default-off startup, cold and warm latency, with or without adoption.

**D5 — one path, no fallbacks.** Interpreter only; official WASI module only; if a gate fails the plan stops.

**D6 — native CI cost model.** The macOS/Windows matrix is a `workflow_dispatch` job in the existing `ci.yml`, dispatched against the candidate ref, required for the exact candidate SHA. **Approved 2026-11-22.**

**D7 — network is a second switch, not a widening of the first.** `codemode.enabled: true` grants workspace inspection only. `codemode.network: true` grants public web access and is meaningful only with `enabled`. A user who never sets it never acquires egress. A trusted project may veto either (`false`); a project `true` alone only warns. **Approved 2026-11-22.**

**D8 — private targets are denied inside a script, never asked.** The direct `web` tool asks per host for private/loopback/link-local/metadata targets; inside a script the same classification returns a typed `denied_private` error and **no** `Ask` is reachable. Rationale: a script can loop, and a prompt-per-attempt path is both an approval-storm and a social-engineering surface. **Approved 2026-11-22.**

**D9 — the egress list is part of the result contract.** Because one codemode call hides the individual URLs that a sequence of direct `web` calls would show in the transcript, the outer result names the counts, distinct hosts (≤5, then `+N more`) and byte totals. A user who wants every URL visible should leave network off and use `web` directly; SPECS says so. **Approved 2026-11-22.**

**D10 — two specs, two budgets, no retroactive capability.** The spec/description is selected from the session header, so the wire matches the stored prompt. A session that started with network and is now off keeps the network spec and refuses `tools.web.*` with `network_disabled`; a session that started workspace-only never gains `web`. **Approved 2026-11-22.**

**D11 — the hermetic gate proves policy, not reachability.** `test/codemodegate` never performs a public fetch: it asserts the capability table, private-target denial, `network_disabled`, the resume directions and the egress shape, against a local stub target. A successful public fetch is proven only by Task 11's live `web-sweep` under its own spend approval; a network capability that passes the gate but not Stage B does not ship. **Approved 2026-11-22.**

### Policy, registration, prompt

Both the user config and a trusted `.moca/config.jsonc` accept `"codemode": {"enabled": true, "network": true}`. Both keys are `*bool`; absence is not explicit false; decode is strict. No CLI flag or environment opt-in. The sample comments the block out.

| User `enabled` | Trusted project unset | project `false` | project `true` | Untrusted project |
|---|---|---|---|---|
| unset | off | off | off, **warn** | off |
| false | off | off | off | off |
| true | on | off | on | on |

| User `network` (with `enabled` on) | Trusted project unset | project `false` | project `true` | Untrusted project |
|---|---|---|---|---|
| unset / false | workspace only | workspace only | workspace only, **warn** | workspace only |
| true | network | workspace only | network | network |

`network` is ignored when `enabled` is off. Registration is unchanged: the ninth tool last, `Builtins()` and the eight-schema golden untouched.

### Tool schema and description

Schema (both variants): `{"type":"object","properties":{"code":{"type":"string"},"timeoutSeconds":{"type":"integer","minimum":1,"maximum":30,"description":"Guest deadline; default 10s. Host I/O may finish later."}},"required":["code"],"additionalProperties":false}` — **239 B** minified.

Descriptions, measured with `json.Marshal` + `separators=(",",":")`:

- workspace (**168 B**): `Run read-only workspace JS. Await tools.read({path}) or tools.read({next}), tools.search({pattern}), tools.ls({path}). Return your answer; bare expressions return null.`
- network (**248 B**): the same with `; with network enabled also tools.web.fetch({url}) and tools.web.search({query})` before `Return your answer`.

Whole spec: **453 B** (workspace) and **533 B** (network). `TestCodemodeSpecBudget` pins 512 and 640 respectively. Two frozen goldens: `codemode-schema.golden.json`, `codemode-web-schema.golden.json`. `TestCodemodeWireDelta` (`internal/provider/wire_delta_test.go`) asserts the first eight serialized entries are byte-identical with the ninth appended, for both variants, in all three families, and that each delta is positive and <1 KiB. A description edit resets the prompt cache for enabled sessions: batch such edits.

### Failure ABI and result

Unchanged, plus the egress line. One `tool_result`:

```
completed | steered | failed: <class>|<line>
<value and texts>
<console_output>…</console_output>            ← only when used
[codemode: N calls; web: F fetches, S searches, H hosts (a, b, …), X KiB; gaps: …]
```

The third line appears only when the batch actually used the network; it is inside the ≥512-character notice reserve and bounded to 200 characters. Classes gain: `network_disabled`, `denied_private`, `invalid_url`, `web_timeout`, `web_error`. A truncated fetch is not an error: `{text, bytes, truncated:true, reason}`.

### Budgets

The v7 table stands. Additions:

| Limit | Value | Notes |
|---|---|---|
| web calls | 10 per script | counted inside the 50 inspection attempts; attempt 11 refused and latched |
| network bytes | 8 MiB wire per script | charged per fetch and per search response; stop before the buffer grows |
| fetch output | 20,000 chars (`webOutputMax`) | truncated with a reason; **no nested spill** — the guest never receives a spill path |
| fetch timeout | `min(10 s, remaining guest time)` | the web tool's own 1–120 s argument is not exposed to scripts |
| search results | `maxResults` 1–10, default 5 | snippets capped at 300 chars by the existing collector |

### Network capability (v1.1)

The bridge reuses the direct tool's code through two collectors, so both paths share parsing, SSRF classification and provider handling:

```go
// internal/tools/web.go (refactor)
type WebPage struct { URL, Title, Text, Format string; Bytes int; Truncated bool; Reason string }
type WebHit struct { Title, URL, Snippet string }
type WebResults struct { Hits []WebHit; Provider string }

type webPolicy struct { Approve func(ctx context.Context, target, from *url.URL) error } // nil Approve => deny

func collectWebFetch(ctx context.Context, pol webPolicy, rawURL, format string, timeoutSecs int) (WebPage, error)
func collectWebSearch(ctx context.Context, env *Env, query string, max int) (WebResults, error)
```

- The direct `webTool.Run` builds `webPolicy{Approve: askPrivate}` and renders today's display text byte-identically (its existing tests are the golden; no new direct golden).
- The nested dispatcher builds `webPolicy{}` — `collectWebFetch` returns `denied_private` for `webPrivateHost(host)` **before any dial**, and the SSRF dialer's IP hook (which catches DNS rebinding to a private address) calls the same policy, so a public name resolving to `127.0.0.1` is denied without an ask.
- The guest never sees the search provider, its key, or a spill path. `tools.web.search` uses the resolved `web.search` config; a missing exa key returns the same typed error the direct tool shows.
- Redirects keep the direct tool's rules; a hop to a private target is denied, not asked.
- The egress ledger is host-side: fetch/search counts, distinct hostnames (lowercased, deduped, ≤5 named, `+N more`), wire bytes, truncations. It is appended to the outer result and to `Summary`, never to the guest frame.
- `tools.web` exists only in the **network** prelude. With the network variant selected but the switch now off, the global is present and every method returns `network_disabled`, so the stored prompt and the schema still agree (D10).

## Risks and stop conditions

| Risk | Stop condition |
|---|---|
| One call hides the URLs a direct `web` sequence would show | egress list in the result and `Summary`; SPECS tells a user who wants per-URL visibility to leave network off |
| A script reads a workspace secret and sends it out | workspace + network is an exfiltration path inside one call; documented, not mechanically prevented; the egress list names hosts, and network is off by default |
| A private target is reached through a redirect or rebinding | one policy hook on both the pre-dial check and the dialer's IP check; denied, never asked; tested |
| A fetch outlives the guest deadline | per-fetch `min(10 s, remaining)`; the guest deadline still wins; the slot is released only after unwinding |
| The network description breaks the prompt budget | 533 B spec / 640 ceiling measured; an edit that exceeds it fails `TestCodemodeSpecBudget` |
| `web-sweep` is live and flaky | checker grades against a live oracle with invariants; a failed run is a failed run, never averaged away; Stage B has its own ceiling |
| Scope creeps into general scripting | no write/edit/shell/mcp, VM state, host modules, `dataFiles`, second language, parallel calls or default-on; `mcp` remains a separate proposal because it can mutate |
