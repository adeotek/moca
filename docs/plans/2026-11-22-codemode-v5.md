# codemode — implementation plan, v5

**Status:** proposal; no runtime, benchmark result, spend or release is approved by this document. Supersedes [v4](2026-11-22-codemode-v4.md); reviewed against plan head `6540248` (no product-code delta from `81fc50d`). Recheck the implementation baseline before capturing goldens. The checkboxes below are work to do, not claims about the branch today.

**Goal:** let an agent inspect and reduce workspace data with a short, disposable JavaScript program. A multi-file join should send one bounded result back to the model instead of forty file bodies. An ordinary one-file search should not get more expensive. Both claims have controls below.

**Architecture:** one custom QuickJS-NG reactor, embedded in the existing Go binary and run by wazero. A fresh guest per script; one process-wide execution slot. Exactly three synchronous, read-only workspace operations: `tools.read`, `tools.search`, `tools.ls`. No container, shell, external interpreter, administrator privilege or runtime download on native Linux, Windows or macOS. The WASM guest has no filesystem; the Go bridge is the only file authority. This is not an OS sandbox for moca or its direct shell tool.

**Tech stack:** keep `go 1.27` / `toolchain go1.27.4`. Add one direct Go dependency, `github.com/tetratelabs/wazero v1.12.0` (Apache-2.0, pure Go; its `x/sys` dependency is already in the graph). QuickJS-NG is a separate, MIT-licensed *shipped artifact*, not a Go module. The build toolchain is maintainer-only. Start with the wazero interpreter; don't add three platform-specific execution backends.

**Spec and sequencing:** [SPECS](../specs/SPECS.md) remains normative. One candidate feature PR, no version bump. **Tasks 1 and 2 can start in parallel. Both must pass before Task 3; no billed call before Tasks 1–6 pass.** Task 7 decides whether to ship; Task 8 closes the same PR. Stage spec edits alongside the behavior they describe, not in a later release. Do not commit, publish or incur charges without separate approval.

**Three product decisions are settled:**

1. **Opt-in:** explicit user `false` wins everywhere. Otherwise a *trusted* project may enable or veto; an untrusted project contributes nothing. Use the same resolver on resume. The session header preserves what was advertised, not a permanent grant to execute.
2. **Steering:** no new nested call after steering is observed at admission. Already-admitted I/O may unwind; CPU-only JS is bounded by its normal deadline, not instantly interrupted by a message. In a batch containing an active codemode call, **skip unstarted outer siblings when steering is pending at or after that call**, including an edit. Pair each skipped ID with a not-executed result, then deliver the message once. Do not change ordinary batches without codemode.
3. **Dependency cost:** measure costs paid by *everyone* (all six release binary/package deltas, default-off startup) separately from cold compilation/instantiation and warm per-script latency. Require a correctness gate and evidence of benefit. No automatic switch to another runtime, budget increase or paid rerun if a gate fails.

## Design contract

### Policy, registration and prompt

Both user config and trusted `.moca/config.jsonc` accept `"codemode": {"enabled": true}`. `enabled` is optional/tri-state; absence is **not** explicit false. Default sample should *comment out* the example rather than install a veto. Decode strictly; no CLI switch, environment opt-in, adjustable quotas or changes to `skills.selfManaged`.

| User `enabled` | Trusted project unset | Trusted project `false` | Trusted project `true` | Untrusted project, any value |
|---|---|---|---|---|
| unset | off | off | on | off |
| false | off | off | off | off |
| true | on | off | on | on |

| Session | Advertised specs / behavior | System prompt |
|---|---|---|
| Fresh, effective off | 8; no adapter or engine initialization | Baseline bytes |
| Fresh, effective on | 9; live adapter, engine still lazy | Enabled bytes |
| Resumed, header missing/false, either policy | 8; never grant retroactively | Stored verbatim |
| Resumed, header true, effective on | 9; live | Stored verbatim |
| Resumed, header true, effective off | 9; same schema, refusal only, no VM or file access; suggest direct tools | Stored verbatim |

Trust withdrawal disables a **project-only** grant, not a surviving user grant. Conversely, removing a trusted project veto can restore a user grant only for a session that started on. Keep `Builtins()` and `internal/tools/testdata/schemas.golden.json` unchanged. Register the ninth schema last, separately frozen. Use a known template slot in place of the existing batch rule (`internal/agent/system-prompt.md:13`), not an unconditional extra bullet. Off expands to the identical original line; on explains direct batching vs. codemode for a multi-file reduction, and still says ordinary dependent calls need separate turns. Pin both against the actual empty-input ceilings: **51 newlines and 6,200 bytes** (`internal/agent/prompt_test.go:11–31`). Record the measured enabled delta; shorten the line rather than raising the ceiling.

### Guest, ABI and results

- **Source and build:** [QuickJS-NG `v0.18.0`](https://github.com/quickjs-ng/quickjs/tree/v0.18.0), commit `d7215b0ad3fc2c562e8317fd9bca058fd4863804`. Use the [WASI SDK 29.0 release](https://github.com/WebAssembly/wasi-sdk/releases/tag/wasi-sdk-29), `wasi-sdk-29.0-x86_64-linux.tar.gz`, published SHA-256 `87d1d1a2879d139cdc624b968efad3d4a97b8078cdff95e63ac88ecafd1a0171`. Verify on download; unpack into scratch (no OS install required). Use upstream core list `dtoa.c`, `libregexp.c`, `libunicode.c`, `quickjs.c` plus our shim. No CLI `qjs.c`, upstream reactor, `quickjs-libc.c`, nonexistent `cutils.c`, `--export-dynamic`, or `js_std_init_handlers`. Plain `JS_NewContext`, no custom context, module loader, helpers or `std`/`os`/`bjson`. Standard JS intrinsics are not host capabilities. Treat the exact successful compiler/linker invocation, license notices and artifact hash as outputs of the spike; do not substitute a guessed build command or the upstream release asset's hash/size.
- **Surface:** strict `{code, timeoutSeconds?}`; reject blank, unknown/trailing fields, noninteger or out-of-range timeout. Code ≤64 KiB UTF-8; 1–30 seconds, default 10. Evaluate our fixed `prelude.js` separately with its own filename. Evaluate the user's source as an async-function body in global script mode, with a newline-free opening wrapper and newline before its closing delimiter. Pin user line numbers; support `await` and explicit `return` (`undefined` → `null`); no auto-return of a bare expression. Pump ≤10,000 jobs and fail an unsettled promise with no runnable jobs. Test *awaited rejection* of dynamic import, not absence of the `import` syntax.
- **Lifecycle:** lazy process-wide runtime and compiled module; nonblocking single slot (`busy`, no queue), fresh instance per call, close on all exits. Bind per-execution dispatcher/capture to that call, never mutable process-global session state. Use `WithMemoryLimitPages(256)`, `WithCloseOnContextDone(true)`, explicit reactor `_initialize` (no `_start`), no preopens/host environment/stdio inheritance. WASI services must follow a reviewed function+signature allowlist; stub/deny or eliminate unnecessary imports. No filesystem or network grant just to make the linker happy. Guest linear ceiling 16 MiB; JS heap cap initially 12 MiB, WASM linear stack 2 MiB, JS stack limit initially 1 MiB. Measure combined fit including module data, guest frames, serialization and allocator overhead. A known JS OOM is `oom`; an unclassified trap is `crash`, not guessed to be OOM. If representative fixtures cannot fit with margin, stop and revise the layout before adding features.
- **ABI:** export exactly `memory`, `_initialize`, `malloc`, `free`, `qjs_init`, `qjs_run`, `qjs_destroy`. One non-WASI import `moca.invoke(req_ptr,req_len,res_ptr,res_cap) -> i32`; pin types as well as names. In guest→host frames distinguish `inspect` (literal names `read|search|ls` only) from bounded output events (`text`/`log`); events are not a tool lookup. Host validates all lengths, bounds and envelopes before copying or calling anything. Max request 64 KiB, max response 320 KiB **encoded UTF-8 JSON** including metadata; use an incremental bounded encoder, not marshal-then-check. Copy owned bytes before guest memory can change. No nested registry dispatch, `Ask`, state stamps, parallel calls or nested spills.
- **Failure ABI:** `qjs_run(src_ptr,src_len,out_ptr,out_cap,out_len_ptr) -> status`; initialize length to zero, set it on every normal return including failures. Success envelope holds the bounded return value; recoverable failure envelope holds bounded `{class,message,line}`. A trap/closed instance has **no readable epilogue**. Keep previously accepted `text()`/console events and coverage on the host while the script runs; no final guest read required to preserve them. Bound event serialization on both sides; cap messages, event count/bytes and result size, including temporary copies. After capture fills, latch truncation, drop further output locally; bound host frame handling independently even if guest code does not cooperate. Do not replace all prior output with an oversized final value. No raw guest bytes in diagnostics.
- **Outer result:** one `tool_result`. First line `completed`, `steered`, or `failed: <class>` (headless stderr uses that line). Include bounded value/text, optional console section, then host coverage/truncation information. Max **2,000 Unicode characters for the entire model result**, 32 KiB combined UTF-8 capture, 200 log records, ≤1 KiB per record; bound `text` events independently (≤200). Reserve ≥512 characters for status/notices; shorten labels or show counts if five examples and the spill pointer won't fit. Never drop an unresolved-gap count, even on failure. Overflow uses `tools.Spill` on the outer bounded capture only; if off/failed, report truncation without promising a file. The overflow file is for a *direct* read, not a new guest root. Timing belongs in `Summary`, not cacheable content. Error classes distinguish `syntax`, `script`, `limit`, `oom`, `timeout`, `cancelled`, `busy`, `steered`, `crash` and unavailable/refused. Mask host paths in guest errors; host notices must be distinguishable from untrusted guest output.

### Workspace bridge, budgets and coverage

`internal/codemode` is a leaf (stdlib + wazero); it declares structural dispatcher/hooks and imports no `github.com/adeotek/moca/internal/...` package. `internal/tools` owns the adapter, typed collectors and a **read-only** interface backed by `os.OpenRoot` on the session workdir. A checked string followed by unrestricted `os.Open` is not a boundary. Perform every nested open/stat/enumeration, including search start, ancestors' ignore files, children and cursor rereads, through the rooted handle. Expose workspace-relative names only; reject absolute/device/volume inputs and outside traversal, check actual handle types, don't open special files as ordinary input. No added config/skills/prompts/temp/spill roots in any mode. An in-tree readable file can contain sensitive data; this is a workspace boundary, not secret detection. `os.Root` doesn't prohibit mounted filesystems or hard-linked regular files already in the workspace. Don't claim protection from a hostile OS or a privileged actor mounting data there. No host write API is present in the bridge.

| Per-script limit (fixed, nested only) | Enforcement |
|---|---|
| 50 attempted inspections, including malformed/denied requests reaching the bridge | Count before validation; attempt 51 is refused and latches `limit`. Log attempted vs admitted vs successful separately in tests; no way to reset via JS. |
| 256 MiB total source bytes; 4 MiB per text candidate; 64 KiB per ignore file | Charge actual reads, sniffing, repeated pages, content digests, and ignore parsing. Read in ≤64 KiB chunks, check context between them. Bound regex input/pattern and ignore-rule bytes/count/depth; don't multiply a per-file rule list across an unbounded traversal. No read-to-EOF just to report a total after a limit. |
| 20,000 entries examined **across** all calls; 1,000 entries returned per `ls`; 100 hits per nested search | Count hidden/skipped entries too. Enumerate by bounded batches (≤128), not `os.ReadDir`/`WalkDir` on an unbounded directory. Sort only bounded results; don't claim a partial list is the global first N. No 5,000-hit direct spill in the guest. |
| 16 MiB cumulative encoded bridge traffic in **each** direction; per-frame limits above | Charge attempts, error frames and output events. Stop before growing a buffer beyond a limit; large escaped text, long names and Unicode count on the wire, not by Go/JS character count. Record gaps for anything omitted. |

The guest deadline interrupts WASM; a Go syscall already in progress may return later. Check context before each admission, chunk, directory batch and reply. Do not return a live callback to a pool or release the slot/root until **all** host work has unwound. No detached goroutine to fake a hard deadline. Test with a controllable reader that can hold a callback past cancellation: no subsequent dispatch, concurrent invocation gets `busy`, releasing the barrier closes handles, next call succeeds. This does not promise a hard process-RSS ceiling or a wall-clock bound on a stalled filesystem.

**Data, not rendered strings.** Share parsing/inspection primitives with direct tools; give direct and nested callers separate policies and renderers. Direct results, stamps, hints and spill behavior stay intact. Only the direct path calls `Reads.Record`, sets `Searched`/`TestSeen`/`FailingTest` or records evidence. Success returns a plain object with `lines:[{n,text,clipped}]`, `matches:[{path,line,text,clipped}]` or `paths` (for `files_only`), or `entries:[{name,kind}]`; include `complete`, `reasons:[]` and `next` (cursor or null). For example, `return (await tools.ls({path:"src"})).entries.map(e => e.name);` returns names, not a listing to parse. Invalid/denied inspections raise a bounded typed JS error; the host records unsuccessful coverage even when the script catches it. Unknown `tools` properties throw rather than resolving to an ambient host function. Empty results imply full coverage only when enumeration finished within the documented filters. Denied/unreadable candidates, clips, budget exhaustion and unfinished enumeration are not clean negatives.

**Paging rule:** nested `read` starts at the requested offset (default 1); stop at the *first* row that will not fit. Return an opaque execution-local `next` cursor for the first unread line, not direct read's `last+1`. The JS-only continuation form is `tools.read({next})`, mutually exclusive with fresh-read args; direct `read` schema is unchanged. Bind the cursor to the opened workspace-relative path, content digest, scope and next line. Digest the bounded file bytes used for that page; reread/hash under the same budget on continuation. If bytes change, return `changed`, invalidate the chain and retain the gap; no mixing versions or claiming a snapshot across files. Unknown total is `null`. Maintain a host ledger per inspection chain: only consecutive, same-version continuations through EOF close a paging gap; a clipped line, denied item or unpageable search/list limit remains incomplete. Cap ledger size by attempts; show count plus up to five bounded examples. `complete` refers only to the requested scope, not conclusions the script draws from it.

## Risks and non-goals

| Risk | Decision / stop condition |
|---|---|
| A WASM cap is mistaken for a cap on moca or the kernel. | Separate guest/host budgets and disclose stalled-kernel-I/O limits. If hard process-wide containment is required, stop and scope a separate process design. |
| Old QuickJS/WASI code becomes invisible maintenance debt. | Version, licenses, ABI manifest and reproducible rebuild live with the artifact; rerun native, memory, footprint and callback tests on every dependency update. Do not ship if the minimal build needs ambient file authority. |
| A larger binary or longer prompt costs more than a niche feature saves. | Report the off-path cost even if adoption looks good; keep the feature off by default and do not merge an inconclusive pilot. |
| Scope expands into general-purpose scripting. | No nested effects (`write`, `edit`, `shell`, `web`, `mcp`), persistent VM, host modules, raw `dataFiles`, second language, parallel nested calls or default-on switch. Revisit only for a demonstrated workload the read-only surface cannot serve. Effectful calls require a separate opt-in, journal/undo/crash policy and steering review; positive read-only results are not approval. |
