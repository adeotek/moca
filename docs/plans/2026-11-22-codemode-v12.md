# codemode — implementation plan, v12

**Status:** needs review. This is v11 patched with the verified R37–R60 findings below; it is not yet an implementation-ready approval. D1–D3, D6 and D7–D11 remain approved only as previously scoped; the changed interfaces and test gates in this revision need review. Task 7's pilot and Task 11's Stage-B pilot each need their own spend approval. No runtime verification, benchmark result, spend, commit, publish or release is claimed or approved by this document. Supersedes [v11](2026-11-22-codemode-v11.md). v10 was reviewed at plan head `473d99c`; since that review the plan branch has been **rebased onto current `origin/main` `f280955`** (HEAD `e30bedb`, F23's gate green), so the implementation baseline is live. The branch history retains the pre-rebase plan commits.

**Goal:** let an agent inspect and reduce workspace data with a short, disposable JavaScript program — and, when the user separately opts in, the same program may also search and fetch the public web. A multi-file join or a search-then-fetch sweep sends one bounded result instead of many bodies; opt-out runs stay byte-identical to today's, and enabled ordinary-case costs are reported, not promised (R45). Every claim has a control.

**Architecture:** one custom QuickJS-NG reactor, embedded in the Go binary and run by wazero. A fresh guest per script; one process-wide execution slot. The guest reaches the host through one import, `moca.invoke`, and the host exposes a **capability table**: `tools.read`, `tools.search`, `tools.ls` always; `tools.web.fetch`, `tools.web.search` only when the network switch is on. Workspace I/O is anchored with `os.OpenRoot` at the workdir, independent of permission mode. Web I/O reuses the existing `web` tool's collectors and SSRF classification; private, loopback, link-local and metadata targets are **denied, never asked**, inside a script. No container, shell, external interpreter, admin privilege or runtime download on Linux, Windows or macOS. The guest has no filesystem and no sockets; the bridge is the only file and network authority. This is not an OS sandbox for moca or its shell tool.

**Tech stack:** unchanged — `go 1.27` / `toolchain go1.27.4`; `github.com/tetratelabs/wazero v1.12.0`; QuickJS-NG as a shipped MIT artifact.

**Sequencing:** establish F23's clean, current-`origin/main` baseline before Tasks 1 and 2. v1: Tasks 1 and 2 in parallel, both green before Task 3; no billed call before Tasks 1–6 pass; Task 7 decides whether v1 ships; Task 8 closes the v1 PR. v1.1 starts only after v1 is merged and its pilot returned a signal: refresh the F23 baseline, then Task 9 → Task 10 → Task 11 (gate, then Stage B pilot with fresh approval) → Task 12. Spec edits stage with the behavior they describe. No commit, publish or charge without separate approval.

## Decisions

**D1 — opt-in precedence follows the repo's own resolver.** `ResolveCodemode` mirrors the function `ResolveSelfManagedSkills` in `internal/config/config.go`: on only when the **user** says `true` and a trusted project does not say `false`; a project `true` alone warns, including when the user explicitly said `false`; an untrusted project contributes nothing. A user `true` plus trusted project `false` returns a `Note`, and `prepare` emits `Warning`/`Note` exactly as it does for the precedent. **Approved 2026-11-22 for the precedence; F20 corrects the message parity.**

**D2 — steering.** No new nested call after steering is observed at admission; already-admitted I/O may unwind; CPU-only JS is bounded by its deadline. A batch containing a codemode call that returned `steered` skips unstarted siblings, pairs each with a not-executed result and delivers the message once, ahead of the repeat-stop. Delivery keys on observed/pending steering, never on a skip count (R37): a batch whose *final* call returned `steered` delivers too, with all issued call ids paired. `skipSiblingsOnSteer = true`. **Approved 2026-11-22.**

**D3 — the steering seam is a function on `Env`.** `Env.Admit func() bool`, with **nil = admit**, is set by `build()` to `a.admitNested`, which takes `a.mu` (the `Agent.Steer` mutex, `control.go:223–226`) for the check only; the adapter sets `tools.Result.Steered` from typed state, never text. `agent.New` normalizes a nil `Admit` to an admit function before any batch path, and the tools adapter also treats nil as admit; `build` then replaces the normalized function with `a.admitNested`. **Approved 2026-11-22; F24 makes the nil contract executable.**

**D4 — dependency and footprint costs are measured separately from benefit.** All six release packages, default-off startup, cold and warm latency, with or without adoption.

**D5 — one path, no fallbacks.** Interpreter only; the official wazero WASI implementation plus the pinned custom reactor only; if a gate fails the plan stops.

**D6 — native CI cost model.** The macOS/Windows matrix is a `workflow_dispatch` job in the existing `ci.yml`, dispatched against the candidate ref, required for the exact candidate SHA. **Approved 2026-11-22.**

**D7 — network is a second switch, not a widening of the first.** `codemode.enabled: true` grants workspace inspection only. `codemode.network: true` grants **nested** public web access and is meaningful only with `enabled`. A user who never sets it never acquires nested egress; the already-existing direct `web` tool gains no switch and keeps its behavior except for F13's explicit `0.0.0.0/8` classifier completion. A trusted project may veto either (`false`); a project `true` alone only warns. **Approved 2026-11-22.**

**D8 — private targets are denied inside a script, never asked.** The direct `web` tool asks per host for private/loopback/link-local/metadata targets; inside a script the same classification returns a typed `denied_private` error and **no** `Ask` is reachable. Rationale: a script can loop, and a prompt-per-attempt path is both an approval-storm and a social-engineering surface. **Approved 2026-11-22.**

**D9 — the egress list is part of the result contract.** Because one codemode call hides the individual URLs that a sequence of direct `web` calls would show in the transcript, the outer result names logical fetch/search attempts, redirect count, distinct **actually contacted** hosts — issued requests, not proposed destinations (R28) — including redirect targets actually issued and the search provider (≤5 named, then `+N more`), accepted response-body bytes and truncation count. It deliberately does not include URL paths/query strings or search text. A user who wants every URL visible should leave network off and use `web` directly; SPECS says so. **Approved 2026-11-22; F15/F16 define the accounting and its limits.**

**D10 — two specs, two budgets, no retroactive capability.** The spec/description is selected from the session header, so the wire matches the stored prompt. A session that started with network and is now off keeps the network spec and refuses `tools.web.*` with `network_disabled`; a session that started workspace-only never gains `web`. **Approved 2026-11-22.**

**D11 — the hermetic gate proves policy, not reachability.** `test/codemodegate` never performs a public fetch or relies on public DNS: it asserts the capability table, private-target denial, `network_disabled`, the resume directions and the egress shape, against literal/private stub targets. A successful public fetch is proven only by Task 11's live `web-sweep` under its own spend approval; the scenario's selftest uses F22's recorded oracle. ### Failure ABI and result

Unchanged except the fully specified egress line. One `tool_result`:

```
completed | steered | failed: <class>|<line>       ← status always present
<value and texts>
<console_output>…</console_output>                 ← only when used
[codemode: N calls; web: F fetches, S searches, R redirects, H hosts (a, b, …), X KiB read, T truncations; gaps: …]
```

The ledger line appears iff **the outer call failed, coverage has gaps, or at least one web operation reached the host dispatcher**. A syntax failure with zero calls therefore still has `[codemode: 0 calls]`; a successful workspace-only call with no gaps has no ledger. The `web:` segment appears iff `F+S>0`, whether the attempts later succeeded or failed. `network_disabled` short-circuits in the prelude before `moca.invoke`, so it is not a host-dispatched attempt and creates no `web:` segment.

`R` counts redirect hops, `H` counts distinct hosts actually contacted — a request issued over the wire that reached its host; a redirect target whose follow was denied or a dial that never connected is attempt metadata and never a contact (R28) — `T` counts every truncation event — body caps, output cuts, and limit stops (the redirect cap and budget exhaustion; R51) — and `X` counts accepted response-body bytes, not request headers, raw TLS/TCP traffic or discarded redirect bodies. The in-flight hop's entry is committed only when the request is actually issued and discarded on denial (R28); a dial that fails after connection setup never adds a host (R29); the contact event is `httptrace.ClientTrace.WroteRequest` with a nil error, and the first request of a chain whose later hop is denied remains a contact (R52); ledger subjects are origin-only, so a blocked `userinfo@host:port` URL cannot leak user info (R30). Hosts are lowercased and deduped before rendering; name at most five, each capped at 24 UTF-8 bytes on a rune boundary, then `+N more`. Omit empty subfields such as `R`, `T` and the host list when zero. The formatter preserves all counters first, then adds gap/host examples only while they fit: it may show fewer than five hosts and must elide either example list with `…` rather than exceed the line cap. The line is inside the ≥512-character notice reserve and bounded to 200 characters, including the five-long-hostname plus long-gap case. Classes gain: `network_disabled`, `denied_private`, `invalid_url`, `web_timeout`, `web_error`, and `limit` (a nested limit stop — redirect cap or budget exhaustion — is class `limit`, never a bare `web_error`; R51). A truncated fetch is not itself an error: `{text, bytes, truncated:true, reason}`.

### Budgets

The v7 table stands. Additions and corrections:

| Limit | Value | Notes |
|---|---|---|
| web calls | 10 logical calls per script | counted before validation inside the 50 inspection attempts; attempt 11 refused and latched; redirect hops do not masquerade as extra logical calls, but remain capped by `webRedirectMax` per fetch and appear in the ledger |
| accepted response bytes | 8 MiB per script | decoded response-body bytes admitted for conversion/JSON decoding, shared by fetch and search; request lines/headers, TLS/TCP framing and discarded redirect bodies are not claimed by this budget |
| fetch body read | 2 MiB (`webReadLimit`) | preserved from direct `web`; body-cap truncation has a reason |
| search body read | 1 MiB (existing `webDoJSON` cap) | preserved and now reported instead of being hidden in a decode error |
| fetch model output | 20,000 UTF-8 bytes (`webOutputMax`) | rune-boundary snapped, with a reason; **no nested spill** — the guest never receives a spill path |
| search snippets | 300 UTF-8 bytes | normalized once in the shared result construction, not left in the direct renderer |
| nested fetch/search timeout | `min(10 s, remaining guest time)` | the direct fetch's 1–120 s argument is not exposed; direct search's fixed 30 s client remains unchanged |

The per-script `webAccount` charges accepted response bytes while bodies are read, before conversion or decode. Each bounded reader caps allocation at the remaining budget plus one byte for overflow detection; an over-budget response returns `limit`, latches the budget failure and never returns partial page/results as a complete answer. The byte cap concerns admitted processing bytes, not a fictional exact count of all network traffic. On the **nested** path only, status is checked before any error body is read (R50): a failed nested fetch or search reads at most `webErrorBodyMax` body bytes for the typed error, so an unbounded error body is never admitted uncharged; the direct path keeps today's read-then-status order, its error text and its debug-log byte count unchanged. The search reader reads `1 MiB + 1` and treats the overflow byte — not JSON validity — as the truncation signal (R44): an overflowing response is `limit`/`web_error` whether or not its prefix parses, and the red tests pin both a mid-object cut and a parseable padded prefix. A nested limit stop (redirect cap, budget exhaustion) is class `limit` and increments `T` (R51).

## Risks and stop conditions

| Risk | Stop condition |
|---|---|
| One call hides the URLs a direct `web` sequence would show | egress list in the result and `Summary` includes operations, actual contacted hosts and redirects; SPECS tells a user who wants per-URL visibility to leave network off |
| A script reads a workspace secret and sends it out | workspace + network is an exfiltration path inside one call — including a URL path/query, a search query, or a hostname sent to DNS; origin-only errors/logs and the ledger omit path/query/fragment/userinfo **but do log the hostname itself** — the hostname is the visible egress signal, not a hidden channel (R41); documented, not mechanically prevented; network is off by default |
| A private target is reached through a redirect or rebinding | private pre-dial/redirect denial plus the independent `okIPs`-aware dialer arm; denied, never asked; fake-resolver and direct-`Control` tests required |
| Redirects escape accounting | every redirect host and hop is recorded, the five-hop per-fetch cap stands, and a redirect test proves the ledger sees more than the initial host |
| A fetch or search outlives the guest deadline | both use `min(10 s, remaining)`; the guest deadline still wins; the slot is released only after unwinding |
| Response buffering exceeds the script budget | shared `webAccount` bounds admitted body bytes before conversion/decode; over-budget responses fail and latch instead of becoming partial complete answers |
| The network description breaks the prompt budget | exact 254 B description / 539 B whole spec frozen; 640 B ceiling enforced by `TestCodemodeSpecBudget` |
| `web-sweep` is live and flaky | selftest uses a recorded oracle with good/bad/cautious arms; only approved Stage B uses the live oracle; a failed live run is a failed run, never averaged away; Stage B has its own ceiling |
| Scope creeps into general scripting | no write/edit/shell/mcp, VM state, host modules, `dataFiles`, second language, parallel calls or default-on; `mcp` remains a separate proposal because it can mutate |
