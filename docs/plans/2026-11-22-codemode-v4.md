# codemode — implementation plan, v4

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans`. Steps use `- [ ]`.

**Status:** proposal, not implemented. Supersedes `docs/plans/2026-11-22-codemode-v3.md`. Product-code baseline `81fc50d` (`v0.8.4-4-g07727fe`); no release or version bump is implied.

**Goal:** an opt-in `codemode` tool: the model writes a short read-only JavaScript program that runs in an in-process sandbox and calls `read`/`search`/`ls`, so a multi-file inspection executes as one call and a large result is filtered before it reaches context.

**Architecture:** one vendored QuickJS-NG WASI reactor — **built by us from a pinned tag** with exactly one non-WASI import (`moca.invoke`) — executed by wazero (pure Go, no cgo). `internal/codemode` compiles the module once and **instantiates per script**; it imports no internal package. `internal/tools/codemode.go` is the adapter and implements `codemode.Dispatcher` over the live `*Registry` surfaces and `*tools.Env` (jail + read policy). `read`/`search`/`ls` gain structured collectors in `internal/tools/inspect.go`; both the existing display strings and the script payloads are rendered from those collectors, so no display text is ever parsed. Opt-in resolves exactly like `skills.selfManaged`. One outer `tool_result` per script.

**Tech Stack:** Go 1.27 (unchanged pin). One new direct dependency: `github.com/tetratelabs/wazero` v1.12.0 (Apache-2.0, no cgo, only `golang.org/x/sys` transitively — already indirect in `go.mod`). The `.wasm` is a build artifact vendored in-repo (~1.5 MB embedded); the compiler toolchain is not.

**Spec:** `docs/specs/SPECS.md` is normative and updated in the same PR (§16). This plan amends §1, §2 (gate list), §4, §6.5, §10, §11.0, §13.5, §14, §15 and §16.

**Sequencing:** Tasks 1–7 build the feature on one branch (`feat/codemode`); Task 8 is the billed benefit pilot and the merge gate; Task 9 writes the prose only if Task 8 returns a signal. Task 1 and Task 2 are strictly before Task 4; Task 3 is strictly before Task 4.

## Decisions

**D1 — v1 scope is read-only.** Scripts may call `read`, `search`, `ls` and nothing else. `write`, `edit`, `shell`, `web`, `mcp`, `codemode` are absent from the dispatch table **by construction**. Effectful nested calls remain a separate proposal with the gates v2 listed (journal, undo, crash-`unknown`, steering barrier); this plan does not build dormant write paths.

**D2 — the sandbox artifact is ours.** We build a reactor from QuickJS-NG `v0.18.0` plus `moca_host.c` with a pinned WASI SDK, and vendor the result. The upstream release asset cannot host a Go callback (its only import module is `wasi_snapshot_preview1`), so "vendor the release asset unchanged" and "inject host functions" were mutually exclusive in v3. The build recipe, patch, license text and sha256 live beside the artifact.

**D3 — package direction is structural.** `internal/codemode` imports stdlib + `wazero` only, and declares the interfaces it needs:
```go
type Dispatcher interface{ Call(ctx context.Context, name string, args json.RawMessage) Reply }
type Hooks struct{ ShouldStop func() bool }
```
`internal/tools/codemode.go` implements `Dispatcher` over `*Registry`-independent code (`env.Paths`, the collectors) and passes `Hooks`. Nothing in `codemode` names a moca type. Pinned by `TestCodemodeImportsNoInternalPackage` (`go list -deps ./internal/codemode`).

**D4 — compile once, instantiate per script.** One `wazero.Runtime` per process (lazy), one `CompiledModule`, one instance per `Execute`, closed in `defer`. This is forced: the reactor keeps `static JSRuntime *reactor_rt`, `qjs_init` refuses a second init, wazero closes the module on context-done, and `api.Function.Call` is not goroutine-safe. A single active script per process (atomic slot, non-blocking `busy` error) keeps memory and CPU bounded and makes the ACP multi-session case deterministic.

**D5 — `await` and `return`, not module eval.** The host evaluates `(async()=>{` + src + `\n})()` in script mode (the prefix carries no newline, so line numbers match the user's script), then pumps `JS_ExecutePendingJob` until the promise settles (bounded at 10 000 jobs). Top-level `await` works because it is inside an async function; top-level `return` works for the same reason. Bare-expression results are **not** supported and the tool description says so — one rule, one error mode.

**D6 — nested reads never touch the tracker.** The dispatcher calls `env.Paths.Resolve` and then the typed collectors; it never calls `readTool.Run`. Therefore no `env.Reads.Record` (`internal/tools/read.go:90`), no `TestSeen`, no `FailingTest`, no `Executed` entry — the class of bug v2 identified cannot occur, instead of being save/restored around. Pinned by `TestNestedInspectLeavesEnvStateAlone` and by the codemodegate's "edit after script read still needs a direct read" leg.

**D7 — steering is admission control.** `env.Steered func() bool` (new `Env` field) is set by `build()` to `func() bool { return a.PendingSteering() > 0 }` (`internal/agent/control.go:230`). The dispatcher checks it before every call; after it fires, no further call dispatches and every later request returns `{kind:"steered"}`, so a script that catches the error still cannot make progress. The outer result carries status `steered`; the agent's existing batch-end `applySteering` then delivers the message once.

**D8 — structured data, not display text.** `internal/tools/inspect.go` owns three collectors; `read`/`search`/`ls` render today's display strings from them (byte-identity pinned by a golden captured **before** the refactor), and the dispatcher returns their typed JSON. Coverage is explicit: `complete` plus a machine-readable `reason` plus `next` for `read`. A script that ignores `complete` cannot present a partial sweep as exhaustive — the adapter appends the gaps to the outer result as host notices.

**D9 — caps are build constants.** Script 64 KiB; timeout 10 s default, 30 s ceiling (`timeoutSeconds` 1–30 is the only model-set value); nested calls 50 attempts, fixed (attempts, not successes); result 2 000 chars with the full 32 KiB capture spilled through `tools.Spill` (`internal/tools/overflow.go:21`); console 200 records × 1 KiB, 32 KiB total; guest memory 256 pages (16 MiB) with `JS_SetMemoryLimit` at 12 MiB so QuickJS raises its own OOM before the WASM trap; request frame 64 KiB, response frame 320 KiB in fixed guest buffers. No config layer and no call argument can weaken a cap.

**D10 — resume is a table, not a probe.** `session.Header.Codemode bool` is stamped at creation. Resume reads the bit; the config's current value only decides whether a started-on session still executes (refusal-only adapter when it does not). Fresh sessions ignore the bit's absence, as every existing header field does.

**D11 — the benefit gate is real.** The deterministic gate proves correctness, containment and byte-identity. The pilot proves the feature earns its prompt bytes: a cross-file join, on/off arms, predeclared thresholds, "no signal ⇒ leave the candidate unmerged" recorded in `test/evals/BASELINE.md`.

**D12 — one prompt line, off-path byte-identical.** `PromptInput` gains `Codemode bool`. When on, one bullet is inserted immediately after the batch rule in `internal/agent/system-prompt.md`:
*"`codemode` runs a short read-only JavaScript program that calls read/search/ls and returns one bounded answer — use it for a multi-file join or to filter a large result; for one or two files a direct call is cheaper."*
Off renders byte-identically to today (test compares rendered bytes, not the template).

## Design

### Tool surface

```json
{"code":"const r = await tools.search({pattern:\"DeprecatedCall\"}); const f = [...new Set(r.matches.map(m=>m.path))]; const out=[]; for (const p of f) { const d = await tools.read({path:p}); out.push([p, d.lines.filter(l=>l.text.includes(\"DeprecatedCall\")).length]); } return out;"}
```

- `code` — required, ≤64 KiB UTF-8, one async arrow body: top-level `await` and `return` allowed, bare expressions are not.
- `timeoutSeconds` — optional, 1–30, default 10. The only model-set value in the schema.
- Frozen schema: `{"code","timeoutSeconds"}`, `additionalProperties:false`, `internal/tools/testdata/codemode-schema.golden.json`.

Globals inside the sandbox (defined by `prelude.js`, nothing more):

| global | behaviour |
|---|---|
| `tools.read(args)` | `{lines:[{n,text,clipped}], next, total, complete, reason}` |
| `tools.search(args)` | `{matches:[{path,line,text,clipped}], paths, complete, reason}` (`files_only` returns `paths`) |
| `tools.ls(args)` | `{entries:[{name,kind}], complete, reason}` |
| `text(v)` | append one result item (string, or `JSON.stringify(v)`) |
| `return v` | one serialized value; `undefined` → `null` |
| `console.log(...)` | one line per call, capped |

Any other `tools.<name>` throws `ReferenceError` at property access. `process`, `require`, `fetch`, `os`, `std`, `print` and dynamic `import()` are absent (no module loader is installed).

### The artifact (Task 1)

`internal/codemode/testdata/reactor/moca_host.c`, compiled with the pinned QuickJS-NG sources:

```c
__attribute__((import_module("moca"), import_name("invoke")))
extern int32_t moca_invoke(uint32_t req_ptr, uint32_t req_len, uint32_t res_ptr, uint32_t res_cap);

__attribute__((export_name("qjs_init")))
int     qjs_init(int32_t mem_limit, int32_t stack_size);   // 0 ok, -1 fail
__attribute__((export_name("qjs_run")))
int32_t qjs_run(uint32_t src_ptr, uint32_t src_len, uint32_t out_ptr, uint32_t out_cap);
__attribute__((export_name("qjs_destroy")))
void    qjs_destroy(void);
```

- `qjs_init`: `JS_NewRuntime` + `JS_SetMemoryLimit` + `JS_SetMaxStackSize` + `js_std_init_handlers` (for `Date`/`Math.random` only) + `JS_NewContext`; registers one C function `__moca_invoke_json(string)→string` that copies the request into a fixed 64 KiB buffer, calls `moca_invoke`, and `JS_ParseJSON`s the 320 KiB reply.
- `qjs_run`: stacks `prelude.js` + `(async()=>{` + src + `\n})()` (prefix newline-free), evaluates with `JS_EVAL_TYPE_GLOBAL`, pumps `JS_ExecutePendingJob` (≤10 000), then writes `{"value":…,"texts":[…],"logs":[…],"error":{"class","message","line"}}` into the host-supplied buffer. Return codes: bytes written, `-1` syntax, `-2` throw, `-3` out of memory, `-4` job limit, `-5` output too large, `-6` internal.
- No module loader, no `std`/`os`/`bjson` injection, no `--eval`, no file preopens. WASI imports are linked by wazero but never given a filesystem.

Exports of the built module: `memory`, `_initialize`, `malloc`, `free`, `qjs_init`, `qjs_run`, `qjs_destroy`. Import modules: `wasi_snapshot_preview1`, `moca`. Both sets pinned by test.

### Sandbox lifecycle (Task 2)

```go
rt := wazero.NewRuntimeWithConfig(ctx, wazero.NewRuntimeConfigInterpreter().
    WithMemoryLimitPages(256).WithCloseOnContextDone(true))
wasi_snapshot_preview1.MustInstantiate(ctx, rt)              // clock + random only; no FS config
mod, err := rt.InstantiateModule(ctx, compiled, wazero.NewModuleConfig().
    WithName("codemode").WithStartFunctions().WithStdout(cap).WithStderr(cap))
```

Then `_initialize` (wasi reactor semantics), `malloc` for the two buffers, `qjs_init(12 MiB, 1 MiB)`, `qjs_run`, drain, `qjs_destroy`, `mod.Close`. Errors map to `ErrSyntax`, `ErrScript`, `ErrTimeout` (ctx deadline), `ErrCancelled` (ctx cancelled), `ErrOOM`, `ErrCrash`, `ErrBusy`, `ErrSteered`, `ErrLimit`. A Go panic inside a host function is recovered in `Execute` and returned as `ErrCrash` — `runRecovered` (`internal/tools/tool.go:424`) is the backstop, never the plan.

### Dispatcher (Task 4)

```go
func (d *codemodeTool) Call(ctx context.Context, name string, args json.RawMessage) codemode.Reply
```

1. `name` ∈ {read, search, ls} — literal map; anything else is `unknown_tool` (no registry lookup, so a future ninth tool cannot leak in).
2. `d.hooks.ShouldStop()` → `steered`, and the dispatcher latches.
3. count attempts (not successes); over 50 → `limit`.
4. `args` decoded strictly; `env.Paths.Resolve(path,false)` for `read`/`ls` and for `search`'s root (the jail call every direct tool uses, `internal/permissions/jail.go:199`).
5. call `collectRead`/`collectSearch`/`collectLs`; serialize the typed payload.
6. record coverage gaps for the outer result; never touch `env.Reads`.

The adapter (`Run`) enforces the script cap and timeout, formats the result, appends at most five distinct coverage notices, spills the full captured text over 2 000 chars, and sets `Summary`.

### Result shape

```
completed
<texts and return value>
<codemode: 12 calls, gaps: 1>        ← only when there were gaps
<console_output>
…
</console_output>                     ← only when console.log was used
```

`failed` keeps the partial output, then `error: <class>: <message>` with the script line number. No timing in the content (identical results stay byte-identical for prompt caching); `Summary` is `codemode completed · 12 calls · 1.2s`.

### Config and resume

```jsonc
// user layer and project layer, same shape
"codemode": { "enabled": false }
```

`config.ResolveCodemode(cfg) CodemodeState` mirrors `ResolveSelfManagedSkills` (`internal/config/config.go:128`): on only when the user says `true` and a trusted project file does not say `false`; a project `true` alone warns and does not enable; an untrusted project contributes nothing.

| session | specs / adapter | prompt |
|---|---|---|
| fresh off | 8 / none | byte-identical today |
| fresh on | 9 / full | today + one bullet |
| resume, header `false` | 8 / none | stored bytes verbatim |
| resume, header `true`, now on | 9 / full | stored bytes verbatim |
| resume, header `true`, now off/untrusted | 9 / **refusal-only** (same schema; every call returns a bounded "codemode is disabled in this session; use read/search/ls directly") | stored bytes verbatim |

## Out of scope (v1)

- **Effectful nested calls** (`write`, `edit`, `shell`, `web`, `mcp`). A separate capability with its own opt-in, journal, undo, crash-`unknown` semantics and the non-negotiable steering barrier. v1 builds no dormant path for it.
- **Bindings / `dataFiles` / a script file surface.** The inspection tools are the file surface; a user-reported need for raw bytes goes through `read`.
- **A second language surface**, `models.*`, durable VM state, host modules, async/parallel nested calls.
- **Default-on.** No layer can turn it on except the user's own config.

## Risks

| Risk | Mitigation |
|---|---|
| The custom reactor drifts from its recipe | `BUILD.md` pins tag + SDK + exact commands; `TestFixturePinned` pins size + sha; re-vendoring is a deliberate edit to both |
| The interpreter is slow | `timeoutSeconds` caps wall time, 50 calls cap work, output caps what can be produced; `NewRuntimeConfigCompiler()` is a one-line switch on amd64/arm64 if a benchmark ever demands it |
| A script inspects more than the model would have | It cannot mutate: the allowlist is three read-only names, no `Ask` exists, the jail resolves every path, and the read tracker is untouched (so no later edit is authorised) |
| A partial sweep reads as exhaustive | Every payload carries `complete`/`reason`; the adapter appends the gaps to the outer result even when the script ignores them |
| A user's steering is ignored mid-script | `Env.Steered` is checked before each dispatch; the outer status is `steered`; the message is delivered once after the result |
| 16 MiB is still too small for a big read | `read`'s own 50 KiB window bounds a single payload; `JS_SetMemoryLimit` fails first, as a classified `out of memory`, and the outer result names it |
| The feature costs prompt bytes and earns nothing | Task 8's predeclared pilot is the merge gate |
