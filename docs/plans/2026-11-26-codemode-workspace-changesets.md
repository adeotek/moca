# Codemode redesign: workspace changesets — implementation plan

**Status:** Proposal for review, not a release commitment. Based on moca `1985b853203d1d9d79c13291864ae95c19545a63`. No implementation, default change, or paid experiment is authorized by this plan.

**Goal:** Let a user ask for a bounded, data-dependent change across a repository and get the correct edits, an inspectable record of what changed, and a real verification run, with fewer model round trips than ordinary moca. Keep one-file work just as easy as it is today.

**Recommendation:** Keep the embedded QuickJS-NG/wazero engine. Change what a program can accomplish: discover → read → decide → **stage exact edits** in one call. Go validates and applies the staged changes after the program succeeds. Tests still run through the ordinary `shell` tool. Keep direct tools available. Do not build another compulsory read transport, a general-purpose shell inside JS, or a new VM.

## 1. What the evidence does and does not establish

I built this checkout to a scratch binary and ran `MOCA=<scratch-binary> bash test/codemodegate/run.sh`: **all eight top-level tests passed**, including the four permission-mode subtests. That proves execution against a scripted provider, capability refusals, budget latching, recovery, resume behavior and the gate's leak check. The provider supplies the program. It cannot show that a model will choose a useful program, save a request, or produce the right patch on a user's task.

| Evidence | Result | Design consequence |
|---|---|---|
| Additive v1, six recorded rounds | More trials used the tool (2/6 initially; 8/10 in the last round); none beat the control on steps. Refusing a second script **added** work: 7.2 → 9.5 mean steps in the last round. | Neither adoption, a better hint, nor forcing fewer scripts is the product benefit. No repeat of this experiment. |
| v2 `sweep-bulk`, 10 assigned pairs, transport vs off | Less turn-1 carry in 7/10 pairs, median paired ratio **0.778**; the predeclared bars were **8/10 and ≤0.5**. Mean steps **16.1 vs 15.8**. Verdict: **inconclusive; no transport promotion**. | Hiding `read/search/ls` is not evidence of faster work. The code exists, but opt-in transport is not our starting recommendation. |
| Same pilot, additive budget 400 vs 50 | Median paired carry ratio **0.376**; mean steps **14.0 vs 19.7**. Both surfaces now default to 400 when enabled. | Keep the dial; do not compare against the obsolete 50 default to manufacture a win. |
| Pilot oracle | 11 of 12 failures were untracked files, which the prompt had not forbidden. Some off runs solved the join using shell. Prompt and checker were fixed *after* measurement. | The 9/10 vs 4/10 pass counts are **not** a capability comparison. Keep shell available in the main evaluation. Grade the requested change, not the route to it. |

Historical protocol, arm table, caveat and follow-up: [`test/evals/BASELINE.md`, v2 pilot](../../test/evals/BASELINE.md#codemode-v2-pilot--sweep-bulk-four-arms-the-transport-question-2026-11-24). The previous stopping decision stands. This proposal tests a different capability on different tasks, not round seven of the read-only prompt experiment.

## 2. What OpenCode and Pi actually implement

Source comparison, **not** a comparative performance benchmark. These are pinned upstream snapshots, not claims about every installation or provider. In particular, the earlier moca plan's statement that both expose *every* direct tool inside JS is incorrect.

| | OpenCode | Pi coding-agent | Decision for moca |
|---|---|---|---|
| Execution | `execute` runs a JS-like language implemented by **psychoscript**. Programs start fresh. The host supplies capabilities; there is no ambient Node environment. The ordinary and `full_codemode` paths differ (the latter also describes Bun file APIs and jobs). | A built-in extension lazily loads a QuickJS/WASM executor. The model supplies an async function body. Independent calls can be composed; output and return values are separate from inner tool responses. | Keep our single-binary, fresh VM and bounded synchronous host bridge. No promise scheduler or background edits. The saving under test is model round trips, not parallel disk reads. |
| Which tools? | Only exact paths in the code-mode catalog or returned by `search` are callable inside `execute`. Other tools remain direct. Catalog summaries distribute space across namespaces; instructions can deliver updates. | Active direct tools **can overlap** with script-callable tools. `codemode` and `deferred` exposures need not occupy provider declarations. `only` can hide direct declarations; `codemode` itself is model-only to prevent recursive scripts. Budgeted declarations plus `searchTools`/`describeTool` help with large catalogs. | Keep all eight direct tools. Give the adapter a short, fixed catalog derived from real host registrations. Four local reads and one proposed edit primitive do not need a search engine. |
| Nested dispatch | Gives an inner call its own ID, scopes permissions to its parent, calls the host tool executor, and collects progress, changed files and call metadata independently of the script's `return`. | `ctx.executeTool` goes through normal validation and hooks, including permission hooks. Declared structured outputs reach JS as data; other results as text. A blocked call isn't a successful empty result. | Copy **policy parity and host-owned receipts**, not generic dispatch. Structured inspection stays structured; staged edits must go through the *same* mutation policy and snapshot machinery as a direct edit, or a stricter one. |
| Output and state | Shell-sized intermediate responses need not become separate model messages. Explicit `return` is preferred; there is a last-expression fallback. Host extensions can supply permission-checked HTTP. | Return/text output is model-facing, nested details are available for rendering. Successful `store`/`load` updates are session entries scoped to a branch; failure does not commit them. | Adopt explicit return and discard-on-failure for staging. No general session store, HTTP, or serialized VM. A new process must never replay a pending change. |

## 3. Where moca is different

- [`internal/tools/tool.go`](../../internal/tools/tool.go) separates `Registry.Specs()` (provider declarations) from `Names()` (registered tools). [`SPECS §10.6`](../specs/SPECS.md#106-codemode-v2-code-mode-as-transport) defines off/eight, additive/nine and transport/six. In transport the four workspace primitives are still callable in JS; `glob` was never a direct tool. Eight built-in wire schemas are frozen.
- [`prelude.js`](../../internal/codemode/prelude.js) sends synchronous frames through one import. [`codemodeTool.Run` and `bridge.dispatch`](../../internal/tools/codemode.go) construct a per-call `Inspection` and a table of **read/search/ls/glob only**. Clean results omit the gap ledger. `await` does not make these operations concurrent. A nested read records freshness/investigation state in transport, not additive. Today a program can calculate *which* files need edits but cannot perform those edits. In additive it can also pay for another direct read before editing.
- Two inconsistencies merit independent repairs, not a new performance claim. `codemodeSpec(true)` advertises web calls with no matching host handler. In [`inspect_root.go`](../../internal/tools/inspect_root.go), the grant builder opens a file grant's parent, stores the parent as its matching path, and the matcher accepts descendants. That representation loses the exact-file restriction intended by [`agent/start.go`](../../internal/agent/start.go). Fix both before widening any capability. Do not use live config files to test grant boundaries.
- [`internal/mcp/tool.go`](../../internal/mcp/tool.go) already puts arbitrary servers behind **one** frozen `mcp` schema and `search/describe/call`. Porting Pi's discovery UX does not yield a forty-schema saving here. Similarly, `agent.go` already accepts multiple direct tool calls in one assistant message. Saving eight call records is not necessarily saving eight model requests.

## 4. Proposed user and model contract

**Example user task:** “Use the version in each service's release manifest to update its deploy manifest, but only for enabled services with an old pin. Leave comments and disabled services alone. Run the repo's verification.” A blind replace is wrong: target paths and replacements depend on joining two sets of records. A one-file rename remains an ordinary `edit`.

The model may use one `codemode` call to enumerate manifests, read and join them locally, and call the proposed `tools.stageEdit({path, old_string, new_string})` once per changed file. This returns `{staged:true}`, **not** “file changed.” Reads see the original files throughout the program; no writable overlay. A normal explicit program return ends collection, Go applies the validated set, and the next model request gets the actual host outcome. A later **direct** test invocation is required when the user asks for verification. A JS assertion, a diff, or a guest string saying “tests passed” is never verification.

| Session | Provider surface | Script authority |
|---|---|---|
| Off / existing additive / existing transport | As today; legacy resumes preserve the stored declaration surface | As today, minus incorrect advertising and overbroad grants. No legacy session acquires mutations. |
| New `codemode.exposure: "workspace"`, `enabled: true` | Eight unchanged direct schemas plus `codemode` last | `read/search/ls/glob` with structured coverage and same-descriptor read parity. Workspace-relative only in this new surface. No external read grants. |
| Same, plus proposed user `codemode.workspaceEdits: true` | Same ordered names; adapter description declares `stageEdit` | Staging and application only in a trusted workspace and an editing mode. No file creation, deletion, move, arbitrary command, MCP, HTTP, model call or recursion. |

**Permission rules:** Both new settings are user choices. Reject `workspaceEdits: true` outside enabled workspace exposure; refuse `network: true` with workspace exposure rather than silently accepting it. Project config cannot opt in or raise a cap; trusted project may veto. Plan mode never admits staged writes (even a plan file must use direct `edit`). Auto/yolo do not widen this catalog. In `-p`, ordinary eligible in-jail edits can proceed under the explicit grant; an operation that would prompt is denied, not auto-approved or deferred. No prompt inside a loop. With no grant, use direct tools. Document this permission at opt-in: a successful script can change several files **without a per-file dialog**. If that policy is not approved, stop at read-only; do not benchmark a different consent model under the same name.

**New writes are deliberately narrow.** Existing regular workspace text files only; relative normalized paths, no links or aliases, hidden control directories, VCS metadata, project instructions/config, secrets/credential files or special files. Define and test the protected-path policy in one host predicate; deny any target with a dot-prefixed component, any repo instruction filename (`AGENTS.md`, `CLAUDE.md`), and existing moca-protected paths; do not claim filename filtering detects arbitrary embedded secrets. No skill/prompt authorship, no temporary-root rights. Require a complete same-execution read of each target, including all pages without coverage loss, and an exact, unique, nonempty old string. Reject no-op edits, repeated targets, and ambiguous matches; no fuzzy reindent, replace-all, or implicit creation. Preserve untouched bytes, line endings and mode. Direct tools keep their current behavior.

**Budgets and failures (proposed):** Keep `inspectAttempts` and the existing source/entry/script/VM bounds. Charge staging attempts too; cap at 32 distinct targets, 32 KiB per staged request, 256 KiB of retained edit input and 2 MiB of aggregate pre/post images. Reject before allocating over budget. Refusals, invalid stages or exhausted limits latch the changeset invalid, even if JS catches the error. An incomplete read used as a target is invalid; unfinished enumeration must not silently certify whole-tree coverage. Script error, timeout, steering or cancellation before apply ⇒ discard every staged edit. Do not start apply after the overall deadline. Mid-apply stop ⇒ finish the current guarded file operation, then stop; never detach a worker. The next script starts empty.

**No fictional transaction.** Validate *all* targets before the first write; then recheck path, mode, current admission and same-file content stamp at each write. Apply serially in canonical relative-path order. Known preflight failure ⇒ zero changes. A late race or I/O failure can leave a prefix applied; return `partial`, name applied/failed/not-attempted paths, and never silently retry or auto-roll back over user edits. A write can land before snapshot persistence or read-tracker refresh fails (`session/snapshot.go`, `tools/write.go`): report `outcome_unknown` for that file if the durable outcome cannot be established. Verify disk state before suggesting recovery. `/undo` retains its **per-file** semantics; clean tracked files may yield git restore guidance, not an automatic multi-file rollback.

**Crash and resume:** Before the first write, persist a host-only changeset-start entry keyed by the outer call ID, with the ordered relative paths and pre/post digests. If this append fails, write nothing. Append per-file outcomes and a final status; if an append fails after a write, stop. On reopen, an unfinished start entry is reported as interrupted, not executed again. Compare the recorded paths to the pre/post digests to distinguish observed original/expected/other content; an observed match is not proof of authorship. Leave conflicting or missing files alone. Test by killing the child between two writes and reopening with a second binary process; the second process must perform zero writes. This is a recovery record, not a promise of crash-atomic filesystem transactions.

**Receipt is part of the feature.** The provider gets one bounded result: host status (`inspected`, `applied`, `discarded`, `partial`, `outcome_unknown`), counts, coverage/truncation flags, changed paths and a separately labeled guest return. Reserve space for status even when output overflows. TUI expands one call into a file list and diffs; ACP exposes the same locations and actual changes under the parent; headless stdout remains the final answer and uses the existing diagnostic channel for summaries. Store bounded host metadata separately from model-visible text so replay and evals need not parse prose. No raw intermediate manifests in history, no source/args/diffs in application logs, no unbounded captured output. Never allow a caught exception, printed receipt or guest-supplied `complete:true` to override host status.

## 5. Implementation sequence and exit tests

New symbols, keys and files below are proposals. Land behavior and its normative SPECS change together only after approval. Preserve old plans and results. No version bump per phase.

1. **Repair the existing boundary independently.** In `internal/tools/inspect_root.go` retain grant kind and exact filename separately from the opened root; derive kind from the configured purpose, not a file's existence. Thread typed grants from `internal/agent/start.go` / `internal/permissions/jail.go`. In `internal/tools/codemode.go` and `internal/codemode/prelude.js` generate advertised capabilities from the live table for fresh sessions; retain a typed refusal for a legacy frozen promise. Update only the affected adapter golden. Test a synthetic exact-file grant, denied sibling, absent then created grant, directory grant, and other-session spill denial. Assert advertised methods succeed with valid fixtures and revoked methods fail closed. Gate: `go test -race ./internal/tools ./internal/permissions ./internal/agent ./internal/codemode` plus the existing binary gate. Ship a necessary fix independently of any pilot.
2. **Build the grader before the feature.** Add `test/evals/changeset-pins/` (manifest join as above) and `test/evals/changeset-registry/` (migrate only implementations referenced by active registry entries; preserve similarly named inactive ones). Use deterministic fixture variants, ordinary languages/text and verification commands available on the target host. Grade exact final bytes, untouched decoys, requested tests actually run *after* the last edit, and final answer; grader computes expectations independently, from initial fixture data outside the worktree. Allow scratch outside the repo; state any clean-tree requirements. Mutate the reference: global replace, missing target, lost comment, extra file, verification before last edit, plausible answer with no patch. Each must fail for its own reason. Keep `bugfix` and `reuse` as ordinary-task controls. Extend `test/evals/_lib/trial.sh` and `test/evals/evalstats/`: count work requests/outer calls/host operations separately, calibrate batched direct calls, failed calls and forged receipt text, distinguish zero from missing. Run `bash test/evals/run.sh --selftest` before billing.
3. **Wire the new surface, initially read-only.** Extend `internal/config/config.go` (`ResolveCodemode`), `internal/agent/start.go` (`planCodemode`, holder), `internal/agent/resume.go`, `internal/agent/prompt.go`, `internal/session/entry.go` and strict config fixtures. Header records workspace ABI and whether edits were originally declared; admission is the intersection with current live policy. Enabling later never widens an old session. For a revoked grant in a workspace session keep a refusing method and direct alternatives; preserve existing transport mismatch diagnostics. A new session gets the current catalog. Pin provider wire names/order, off-prompt bytes, no eager VM, project veto, old headers, revocation, mode changes during a call, `/clear` and second-process resume with no pending work. Gate: `go test -race ./internal/config ./internal/session ./internal/agent ./cmd/moca`.
4. **Implement stage and apply as distinct host phases.** Add `internal/tools/changeset.go` and `changeset_test.go`; wire `stageEdit` in `internal/tools/codemode.go` and `internal/codemode/prelude.js` via the existing host-frame import. The `bridge` owns targets, coverage and budget; it dies at end of call. At `codemodeTool.Run`, call apply only after `eng.Execute` succeeds and admission is still live. Extract shared validation/commit helpers from `internal/tools/edit.go`, `editapply.go`, `write.go`, `readtracker.go`; retain snapshot, edited/unverified state and investigation rules. Do **not** call `Registry.Run` recursively: it resets per-call state and emits unrelated hints. Keep the runtime package independent of `tools`; Go owns files, not JS. Refactor the guarded writer where necessary so the actual commit is workspace-root-relative and cannot follow a changed ancestor; a prior path check plus `os.WriteFile(abs, …)` is not that guarantee. Use same-directory replacement for one file, preserve permissions, reject unsupported filesystem/link cases; never claim cross-file atomicity or isolation from an external writer. Require an actual snapshotter; propagate write vs post-write failure distinctly. For the recovery record, inject a narrow `Begin/Record/Finish` journal interface through `tools.Env`, bound by `agent.build` to the session writer. Carry the outer call ID from the registry invocation, not a script argument. If the journal is unavailable (including an unpersisted session), refuse edits before apply; reads still work. Keep `internal/tools` free of session imports. No second dispatcher exposing all tools.
5. **Make results visible and prove failure behavior.** Extend `tools.Result`, `internal/agent/events.go` and the existing result→session path, `internal/tui/toolsummary.go`, `internal/acp/toolcall.go`; read metadata on replay, never execute it. In `test/codemodegate/codemodegate_test.go`, drive a real script against generated rows with a changed seed; compare real bytes to the independent oracle. Assert one provider tool result, no intermediate sentinel in its next request, accurate paths/counts, a direct green verification *after* edits, and second-process replay without edits. Unit-inject stale data on the last preflight, a late failure on target two, snapshot append failure, and steering before/during apply. Check exact disk prefix and receipt, unchanged unrelated files, duplicate/aliased paths, BOM/CRLF, caps, clean/dirty undo, plan and headless denials, slot reuse. Prove a guest that says `applied` cannot create a receipt. Run `make vet && make test && make build`, `bash test/codemodegate/run.sh` on the native CI matrix, and `bash test/acpgate/run.sh`; cover the expandable TUI row in a real terminal. Update doc counts/goldens with their owning tests. A green mock-provider gate is a prerequisite, **never** a benefit verdict.
6. **Prove feasibility before buying model runs.** Run a handwritten reference through the real binary/VM on each target fixture with production caps. Require correct changes within one script, no privileged paths and one ordinary verification. Run a competent ordinary-moca trajectory too: allow multiple direct calls per response and a permitted shell program. Record requests, elapsed time, carry, and bytes written. Also try a plain host-side list of explicit exact edits using the same commit routine in a test harness. If the workload has no data-dependent work that JS removes versus that list, prefer the simpler list; if shell already fits the same request floor on both fixtures, stop rather than suppressing shell. This is an upper-bound check, not evidence about what a model will choose.
7. **One separately approved, predeclared live campaign.** Protocol below. If it passes, document user opt-in with the real task/diff, update README/CHANGELOG/SPECS and the operator rollback path. If it fails, keep the evidence and independent fixes, not an advertised capability. The evaluation can reject the entire changeset design.

## 6. The release decision

**Question:** Does allowing the model to compute *and apply* a bounded repository change save user-visible work, relative both to real moca and to the same JS inspections without edits?

- **Three arms, same tagged binary:** A = codemode off; B = workspace inspection only, 400 attempts; C = B + `workspaceEdits: true`. B and C share catalog generation, receipt mechanism and read parity. Intentionally do not hide direct tools. Freeze binary digest, exact configs, checker, prompts, fixture seeds, model `opencode-go/deepseek-v4.1-flash`, reasoning, permission/shell rules and limits before launch. No hints to use a particular tool; all arms can use the same shell and direct editors. No implied portability to other models.
- **Assignment:** ten matched triples per fixture, two target fixtures and two ordinary controls; randomized balanced arm order within blocks, `-j 1`, fresh tree and isolated session/XDG dirs. Count every assigned run, including shell-only, failed and never-adopted runs. No replacing inconvenient rows. No live run now: present the trial count, cost estimate and proposed hard ceiling for separate owner approval. One `-cap-scope` ledger for all arms; pre-reserve a verified worst-case trial cost or use a provider-enforced ceiling. A guard over completed spend alone is not a hard cap.
- **Primary:** work requests to reach a checker-valid result, including failed/repaired work. Count actual model round trips, not fixed user messages or tool-call IDs. Predeclare a 30-work-request trial limit, scoring an incomplete/incorrect trial at 31; also report raw steps and correctness separately. On **each** target fixture C must beat A **and** B in at least 8/10 assigned pairs per comparison and have median paired request ratio ≤0.75 against each. Ties are not wins. These are practical decision thresholds, not a claim of population significance.
- **Vetoes:** C must pass at least 9/10 on each target, lose no passes vs either comparator on any fixture, and show no unauthorized or unreported change. On each ordinary control C's median work requests must be ≤ A + 1. Across the assigned campaign, C's median paired elapsed-time and billed-cost ratios vs A must each be ≤1.10 (measure actual usage; missing prices are not zero). Report input/output/cache tokens and retries, turn-1 carry where a follow-up exists, no-op/failed/successful staging, partial results, approvals, shell use and direct verification. Require passing C trials with real host-confirmed staged edits in ≥8/10 on **each** target; analyze adopters separately only to explain the outcome. If C wins by shell alone, codemode did not earn the credit.
- **Verdict:** all conditions met ⇒ offer **opt-in workspace changesets** for the measured class, not a global default. Any unauthorized change ⇒ stop immediately. Correct data but a missed bar ⇒ do not promote; prefer direct tools. Missing costs/telemetry, incomplete blocks, broken oracle or exhausted ceiling ⇒ inconclusive, also no promotion. Archive protocol, rows, paired ratios, representative success/failure traces and verdict in `test/evals/BASELINE.md`; no post-hoc metric swap or paid rerun on the same tasks. Rollback means disabling the workspace grant for future executions, not undoing user files or invalidating old transcript reads.

## 7. What not to build on this evidence

| Temptation | Why not now / what would reopen it |
|---|---|
| Hide all direct reads or insist on one script per turn | Both were investigated; neither established fewer steps. Preserve the fast path for “show me this function.” |
| Wrap shell, arbitrary MCP or HTTP | Different permission and egress problems. MCP already has a small declaration. Reopen **read-only MCP composition** only with a real cross-server join where direct proxy calls, not schema size, dominate; require per-server user opt-in, host-side authorization and egress receipts. Never trust a server hint as a new local grant. |
| Add persistent JS state, worker pool, TypeScript, or Bun | None removes the measured inspection→edit boundary. Reopen state only with a repeated expensive join across user turns; reopen concurrency only after timings identify blocked independent I/O. Neither is required for a correct first shipment. |
| Promote on a synthetic best case | A one-script reference demonstrates feasibility. Only uncoached model runs with ordinary tools still available can justify a claim to users. If a small native batch achieves the same outcome, ship the simpler mechanism instead. |
