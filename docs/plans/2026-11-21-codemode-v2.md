# codemode — implementation plan, v2

**Recommendation:** build the benchmark first, prove worker containment, then ship opt-in **read-only inspection** if it beats moca's best ordinary tool use. The useful result is a correct answer with fewer model round trips **or** less tool output carried into the next request. Neither a fast wrong answer nor a smaller transcript that costs more to produce is a win.

**Goal:** let the model discover, inspect and reduce many tool results in one program, sending only a bounded answer back into the conversation. A successful scripted sweep needs one assistant tool call and one subsequent answer request; it still performs the underlying file reads. This is a target for a controlled test, not a promised speedup on arbitrary tasks.

**Status:** proposal, not implemented. Supersedes [the original plan](2026-11-21-codemode.md); product-code baseline `81fc50d` (`v0.8.4-1-g81fc50d`); `746950e` adds the reviewed v1 document without changing product code. No release or version bump is implied. **Platform contract decided after review (finding 1, branch A):** Linux with a delegated cgroup v2 memory controller and Windows with a Job Object; macOS and undelegated Linux are out of contract — see §2. It also **reverses v1 decision 4** (every tool but `codemode`): the release scope is the three inspections, and effectful nested calls are the separate proposal in the last section. For implementation, work through the unchecked steps in order; a failed gate means stop, not silently relax it.

**Architecture:** one disposable goja worker per script, one synchronous host call at a time. The parent owns tools, permissions, evidence, budgets and cancellation. Two packages, so the boundary is structural rather than a review convention: `internal/codemode` (wire, host, VM) imports no other internal package; `internal/codemode/tool` is the adapter and may import `tools` and `llm`; **`tools` imports neither**. A deps test (`go list -deps ./internal/codemode` must not mention `internal/tools`) keeps the "no moca objects in the VM" claim true by construction. The VM/protocol files expose no moca objects to JS. `agent` registers the adapter; `cmd/moca` routes the worker. One static Go binary on the existing six release targets, no cgo or external JS installation.

**Release scope:** scripts may call exactly `ls`, `search` and `read`, under the active policy. All eight direct tools remain available as before; inspection may be followed by ordinary, separately visible edits. Read-only means no script-requested workspace mutations, commands, network or MCP calls; normal session bookkeeping still happens. Nested `write`, `edit`, `shell`, `web` and `mcp` are a separate proposal with their own workload, safety gates and opt-in. Passing the inspection gate does not approve them. No default-on decision in this train. **Platforms:** the supported set is Linux with a delegated cgroup v2 memory controller and Windows with a Job Object memory limit; macOS and any Linux where the controller cannot be created (containers, non-systemd hosts) are unsupported, and on those hosts the tool is never advertised — eight tools, no prompt line, one warning, direct tools unchanged.

## Design contract

### 1. What the model gets

* Input: `script` (nonblank JS function body, ≤64 KiB UTF-8), optional integer `timeout` **in seconds**, default 120, valid 1–300. Reject out-of-range values, non-objects, unknown fields and trailing JSON before spawning; do not silently clamp. A `StopLength` response still executes nothing. Freeze the conditional tool's description/schema separately from `internal/tools/testdata/schemas.golden.json`.
* `tools.<name>(args)` returns plain JSON data, synchronously. Success: `{ok:true, data, complete, next, reasons}`. Failure: `{ok:false, error:{kind,message}, complete:false, next:null}`; no rows are implied. `ok` means the operation ran, **not** that it enumerated everything. `complete` describes coverage of the requested file/query under documented filters. Excluded hidden/binary files are outside a text search's domain; unreadable candidates, size skips, clipped requested text and exhausted budgets are not negative matches. Emit bounded machine-readable reasons, never a spill filename as a cursor. No Go objects, diagnostic `Detail`, host credentials or setup paths cross this interface.
* **Inspection data.** `ls`: `entries:[{name,kind}]` (no `/` or `@` appended). `search`: `matches:[{path,line,text,truncated}]`, or `paths:[…]` for `files_only`; `read`: `lines:[{number,text,truncated}]`, no `N|` prefixes or footer. Preserve names, punctuation and empty lines as data. Return the empty array with `complete:true` only for a genuinely empty result in scope. Input argument schemas and direct tool outputs stay frozen. Use one underlying implementation for each inspection, with separate direct-display and JS projections; do not rerun the operation to get metadata. The JS projection collects at the 5,000-hit `searchSpillCap`, not the 100-hit display cap — a script has no spill file to read — and every cap, `>4 MB` skip, unreadable candidate or clipped line sets `complete:false` with a machine-readable reason; `files_only` follows the same rules.
* **Continuation:** `next` is `null` unless the host supports resuming that request. Start with `read`'s existing offset/limit: return the next *contiguous* offset, not the highest line that happened to fit. An irrecoverably clipped line remains incomplete even on the last page. Bind a chain to the same resolved file and verified file stamp; discard the chain as stale if it changes. `ls`/`search` may initially return `complete:false,next:null` with a reason to narrow the request. Do not invent a cursor over a changing directory or turn a search cap into end-of-results. The parent tracks unresolved inspected pages, failures and terminal limits, clearing a page gap only when its verified continuation covers it. Report outstanding gaps outside the JS return even if the script ignores them. This is coverage of **requested inputs**, not proof the script chose all relevant files or computed the right answer.
* Publish only `ls`, `search` and `read` on a JS object without inherited tool methods. An absent method is a JS error. Independently check the same explicit allowlist in the parent before registry dispatch; reject recursion, forged frames and newly registered tools. No proxy fallback through `mcp` or `shell`.
* `return` a string or JSON-serializable value; no return/`undefined` means JSON `null`. Use JS JSON semantics, not Go reflection over arbitrary object graphs. Cycles, unsupported return types (including a Promise/thenable), or serialization exceptions give a bounded `runtime` error. No async contract, timers, Node loaders, filesystem/network bindings or persistent globals. Finish/serialize once, under the **same** limits as execution; close the host-call channel when the synchronous body ends so late jobs/serialization hooks cannot cause new effects. Test that order with a benign stub.
* `console.log` accepts bounded diagnostics, not a second result channel. Render host status, counts by tool, failures/refusals and coverage gaps outside the delimited untrusted return/log section. A partial sweep must not be rendered as a successful exhaustive answer. Do not turn script text into trusted hints or evaluate tool output as code. Include a short usage example in the enabled tool description showing how to inspect `data`, follow `next`, and handle terminal incompleteness. The model should not have to guess the JS interface or fetch developer docs to use it. If `search` already answers the question, use `search`.

### 2. Worker, resource and transport boundaries

| Limit (proposed shipping defaults) | Enforcement and externally visible result |
|---|---|
| Lifetime: requested wall deadline; 2 s reap grace | Parent starts deadline before handshake and includes parsing, JS, inspection waits and rendering. On expiry or user cancel, stop admitting requests, cancel the context passed into the **nested tool**, close pipes, kill/reap the child independently of the run goroutine. User cancel stays an abort; script deadline is a tool error. Already-started OS/file operations may finish; do not return while another goroutine can still touch `Env`. |
| Memory: 512 MiB worker budget; at most one active worker per moca process initially | Acquire a process-wide, nonblocking slot before spawn (concurrent ACP sessions included); a taken slot is a bounded `busy — another script is already running in this moca process` tool error before anything is spawned, never a queue (waiting would consume the outer deadline invisibly); release only after reap. Verify a kernel-enforced process/group budget before handing over the script. Soft heap limit and `SetMaxCallStackSize` are additional guards, not evidence of RSS containment. The parent and any already-authorized external tool have their own existing limits. |
| Calls: 500 attempts/script; zero nested approval or classifier requests | Parent counts attempts, not just successes. No 501st dispatch; stop on the repeat-stuck threshold or pending steering. The three admitted inspections resolve paths under the live jail; refusal never escalates to another tool or an approval. Direct calls keep their existing policy. |
| IPC: ≤1 MiB **encoded** per frame; ≤16 MiB in either direction cumulatively per script | Length-prefixed UTF-8 JSON, validate declared length before allocation and shape before dispatch. Budget includes escaping and all frames, not just successful calls. Reject a tool argument that cannot fit; an oversized result is `limit`, never silently a complete read. If the call already ran, report that fact. |
| Output: 12 KiB model result; 64 KiB bounded capture; ≤200 log records, ≤1 KiB per record (whichever of the record count, the per-record size and the capture binds first) | Apply byte/UTF-8-safe caps while producing and receiving, including error messages, status, logs and value. Reserve space for host notices. Spill **only the bounded capture** using `tools.Spill`; mark omitted bytes/records, or truncation without a pointer if spilling is off/fails. Reject a final value that exceeds the frame budget instead of buffering a limitless “full result” in the parent. Repeated suppressed logs must not emit unbounded frames. |

**Memory feasibility is a decision, not a TODO after release.** The containment contract is **Linux with a delegated cgroup v2 memory controller, or Windows with a Job Object memory limit**, established unprivileged: a cgroup the user's session already delegates (systemd user scope or a delegated cgroupfs subtree) or a Job Object the worker's creator can own and set `JOB_OBJECT_LIMIT_PROCESS_MEMORY` and `KILL_ON_JOB_CLOSE` on — no root, no `Delegate=` edit, no administrator rights, no `taskkill` dependency. **macOS is out of contract**: there is no unprivileged hard RSS limit (`RLIMIT_AS` bounds the address space Go reserves rather than what it touches), so an address-space rlimit must never be used as one. Probe once per process at start by creating and destroying a throwaway limit at the shipped 512 MiB, and cache the verdict: on failure the tool is not registered, not prompted and not written to the header, one warning names the missing capability, and the direct tools stay intact. Record exactly what each leg measures, including room for Go runtime reservations. If a boundary cannot be established at a spawn after a passing probe, refuse execution before evaluating code, warn once and leave direct tools working. Do not ship a best-effort monitor under a hard-limit claim. Exercise pressure only in an externally constrained test environment; use a small test quota, never intentionally exhaust a developer host.

**Protocol:** exact worker argv, absolute executable, private empty cwd, non-nil minimal allowlisted environment (only platform essentials), no inherited extra files, ordinary logging/config disabled, stderr discarded or reduced to bounded diagnostic categories. TTY or wrong argv → usage error; stdin/stdout reserved for protocol. A versioned hello/ack precedes the script; verify protocol/build compatibility because a later spawn by pathname can select a replaced binary. No matching ack → no host dispatch. On success: `start` (script, permitted names, limits) → zero or more `log` or `call(seq,name,args)` → exactly one `reply(seq,…)` per admitted call → one `done` or `failed` and clean exit. One outstanding call, monotone IDs, one frame type per message. Bad length, early EOF, wrong version/sequence, duplicate terminal, extra data, missing exit or invalid JSON is a worker failure; **never retry a call or a script automatically**. Parent counts attempts/dispatches/completions even if the final frame is missing. A terminal frame is provisional until the process exits. Only the pump on the run goroutine may dispatch; transport/watchdog goroutines own pipes, timers and process handles, not tools or UI.

The bounded kill guarantee is about the **worker**. `readTool.Run` (`internal/tools/read.go:40`) does not currently consult its context. Check cancellation before every dispatch and at bounded intervals in cooperative tool loops, including `stampOf` (`internal/tools/readtracker.go:30–46`). The IPC budget does not meter disk work: charge a nested-only aggregate source-byte budget (proposed 256 MiB) for scanning, ignore files, repeat pages and hashing; charge as bytes are read, before unbounded allocation. Bound directory entries examined as well as returned; walk in chunks with cancellation instead of `os.ReadDir` of an unbounded directory (`internal/tools/ls.go:39`). If enumeration stops early, mark it incomplete; don't promise a globally sorted full listing from an unexamined remainder. No unbounded inner spill. Direct-tool **output** stays unchanged; the context check is new for direct calls too, so a cancelled run unwinds a read earlier — that is the honest behaviour, not a regression. A blocked OS call cannot promise a hard end-to-end deadline: test that no subsequent call runs, a cancellable operation unwinds, the child is reaped and the session remains usable.

### 3. Permissions, state and history

1. **Use the live policy and shared dispatch.** Pass the parent-owned registry and the actual `*tools.Env` to the registered inspection, never a copied checker, bypass path or second registry. Apply admission, validation, panic recovery, jail, resource accounting and ordinary inspection state exactly once. Preserve the direct renderer and hints byte-for-byte; deliver eligible host guidance once in the outer result, not JS data. Keep per-call flags local or save/restore them. Count nested failures once, bound their keys, and leave `MaxRepeat` available for normal wrap-up. A wrapper is not a shell command, verification, write or new run. **A nested read never records the edit stamp.** `read.go:90` calls `env.Reads.Record(abs)` before the window is chosen and `edit.go:54`/`write.go:40` only `Check` it, so a script read would authorise a direct `write` of a file the model has never seen. Save each inspected path's tracker entry before the dispatch and restore it afterwards — absent stays absent, an earlier direct read keeps its own stamp — which also removes the two-tier rule (the direct tool records on any successful open, so "incomplete" cannot mean the same thing nested). The confirmed paths the parent needs for compaction elision (§3.3) are tracked separately: one tracker, two consumers, never conflated.
2. **Steering is not cancellation.** The parent checks the agent's pending-steering state at every nested admission (`internal/agent/control.go:223–233`). Serialize the admission decision with steering enqueue: if steering wins, do not start that call; if already admitted, let it unwind, then admit no more. Do not hold the queue lock while doing I/O. End the script with host status `steered`, counts and any observed gaps; a script cannot catch this and retry. Suppress unstarted siblings in the same outer batch with an explicit not-executed result for each. Persist all required outer results **before** applying the queued user message once. An explicit cancel still aborts; a deadline is still a timeout. No inner messages are injected between provider tool use and result.
3. **Keep evidence small.** `Agent.result` persists one outer pair. Store bounded parent-observed counts, coverage and inspected paths linked to the outer transcript entry ID, not nested tool bodies, script assertions or fabricated provider calls. For compaction project confirmed reads (never changed files) through `internal/agent/compaction.go` on normal and fallback cuts. Show one outer activity in TUI/ACP; replay facts without running JS or restoring a read stamp. If a crash loses the final summary, report interrupted/coverage unknown, never complete. Read-only inspection does not need a write-ahead effect journal or `/undo` integration.

### 4. Configuration and compatibility

Use `"codemode": {"enabled": true}` in the user file; both layers decode a `CodemodeConfig` block, with optional `Enabled *bool`. No CLI flag or environment switch. Reject a bare boolean and unknown subkeys. The user setting alone opts in; trust controls whether the **project layer** is read, not whether a user's opt-in works in `-p`. In a trusted project: `false` vetoes user `true` with a note; `true` plus user absent/false warns without enabling; remaining combinations follow the user's value. An untrusted project contributes neither values nor warnings. Name the actual `StartOptions.ConfigPath` when overridden.

| Session | Conditional schema / worker | System text |
|---|---|---|
| Fresh off / fresh on | 8 / 9, with `codemode` appended only on | Off is byte-identical; on adds one short usage instruction explaining when direct search/batching is better. Replace/qualify the direct-call dependency rule **only when enabled**, not with a contradictory second instruction. |
| Resume with missing/false header bit | 8; never grant retroactively | Stored bytes verbatim. If currently enabled, note that a fresh session is needed. |
| Resume started on, currently enabled and usable | 9; live adapter | Stored bytes verbatim. |
| Resume started on, now disabled, vetoed or known unavailable | 9; same schema, **refusal-only implementation**, no executable lookup, spawn or dispatch | Stored bytes verbatim. Warn once; a call explains why it is unavailable and suggests direct tools. A fresh off session has only eight. |

Persist an optional `codemode` boolean in `session.Header` at fresh start. Resolve eligibility once for prompt, header and registration; account for the §2 platform contract before advertising — an unsupported host is never advertised. A failure discovered only at spawn produces a bounded unavailable error, not a fallback interpreter. Use `prepare`/`Start`/shared `build` for TUI, ACP and one-shot; mode changes between runs use the live policy, no mid-session feature toggle. Enabled users pay for the extra schema, instruction, script and bounded answer. Disabled users pay no extra **request bytes** for the feature, not zero installed bytes. Classifier calls and tools that do external work retain their ordinary costs.

## Separate proposal: when would effectful scripts earn their place?

The inspection release ends at Task 7. Do not build dormant write paths, an effect journal or new approval plumbing for it. Revisit individual capabilities only with a representative workload the three inspections plus ordinary direct tools do poorly; do not expose all five remaining tools as a bundle.

* **Independent value test:** for example, repair out-of-policy manifests while leaving exempt services, unrelated files and formatting intact. Compare (A) shipped inspection returning proposed edits followed by normal direct edits, versus (B) the same inspection plus narrowly admitted nested edits. Allow normal batching and shell equally. Grade the exact final tree and verification, not whether the model wrote a loop. Predeclare adoption, correctness, cost, elapsed time and benefit criteria before billed confirmation. A read-only join win is not evidence for B.
* **Independent safety gate:** require a separate explicit opt-in and persisted capability version; old sessions and read-only opt-ins never gain effects. Enforce the actual direct permission/plan/snapshot/skill checks for each admitted call; count actual questions and classifier requests, not merely calls. Keep the inner subject visible under the outer activity ID. Record intent before dispatch, outcome before reply; a crash in between means *unknown*, not “nothing changed”. Do not infer absence of side effects from an error or retry automatically. Preserve normal per-write undo; never promise transactional shell/MCP rollback.
* **Non-negotiable steering test:** in an isolated fixture, complete edit A, enqueue “leave B alone” before admitting edit B, then verify A landed once, B was never dispatched and remains byte-identical, the host summary reports the partial effects, and the user message arrives once after the outer result. Also cover cancellation or a crash after A; replay must not perform either edit. No extension without both the workload and the safety evidence.

Still out of scope: async/parallel tool calls, hiding direct tools, durable VM state, host modules, image/model APIs and blanket script approvals. The first implementable batch remains the oracle, not a new dependency.
