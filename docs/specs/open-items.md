# Open items from the v0.7.0 branch review

> Last updated: 2026-10-19 · source: the review pass over `chore/self-managed-skills-plan` (multibyte/case-fold, generic-runner and C5b fixes landed in the same change this doc ships with)

These are findings the review pass verified but deliberately left unchanged — each needs a policy or design call rather than an obvious one-line fix, or is cosmetic. None blocks the branch. The guard's real holes (the `-C`/`cd` generic-runner bypasses, the named-rule skip, the fold escapes, the dead C5b guard, the same-day ×1 → ×2 bump, the steering-loss on append failure) are **fixed and pinned**, not listed here.

For the standing open item on allowlisted interpreters writing skill files (python/node/npm/pytest/docker and friends) — still unapproved but reachable — see SPECS §15's `TestGenericRunnerAllowRules` pin; nothing below re-opens that.

## Open

1. **Bare-word override values still name commands — `permissions` generic-runner guard.** `make test GORUN=bash` passes: `plainMakeValue` accepts any plain alphanumeric word, and a bare word resolved from PATH (or consumed by a recipe variable) can be a command, not data. Distinguishing `VERSION=1.2.3` (inert) from `RUNNER=rm` (code) statically would refuse legitimate word overrides this repo relies on. Needs a fail-closed policy call: either a denylist of recipe-command-looking values, restricting allowed values to numeric/version shapes, or accepting the residual risk and pinning it as a §15-class open item in the probe test.
2. **`rm -rf .moca` (the skills dir's parent) wipes every auto skill unvalidated.** `skillTarget` covers the dir itself and below; the parent is just an in-workdir path, auto-allowed in auto mode for literal operands. Same trust class as any in-workdir `rm`, but the wipe strips the user's accumulated project knowledge in one command; a guard for paths *above* the skills dir (or at least the skills roots) is worth considering.
3. **`hygieneSummary` under-reports when a skill both loses rules and becomes empty.** `PruneAutoSkills` counts removed rules in `RulesRemoved` but names only surviving skills in `Touched`; the summary's count row requires `Touched` non-empty, so removals that emptied a skill leave only "removed empty moca-x". Cosmetic — the print stays truthful; fix is reporting the count even when no skill survived (or a joint clause).
4. **Prune ages anchor to UTC midnights.** `PruneAutoSkills` computes `now.Sub(r.Last)` as elapsed 24 h durations from a date string; in UTC− timezones a rule can be pruned hours before it is 90 local calendar days old, and in UTC+ zones pinned-age notices surface late by the same margin. Sub-day wobble; if calendar-day semantics are the intent, either compare `.Format`-derived calendar dates or leave a comment stating the skew is accepted.
5. **The ×2 refusal for an undatable stored rule quotes a zero date.** `autoskill.go`'s change-refusal message renders `old.Last` (zero time) as `(×1, 0001-01-01)` for a stored rule with absent/undatable provenance, and there is no in-contract way to add provenance to such a line (`old.HasProv` gates the bump) — rewording the rule is the only escape. Message craft + a possible documented escape for back-filling provenance.
6. **ACP `/remember` with the rule only in an attachment errors the whole request.** `textBlocks` correctly excludes resource blocks, so `splitCommand` yields empty args and `Agent.Remember` returns its usage error as the prompt's error result — the TUI prints a usage line instead. Acknowledged in the `server.go` comment; consider mirroring the TUI's per-prompt usage-note shape.
7. **A user template named `remember` shadows differently per surface.** In the TUI the built-in always wins (even with the feature off); in ACP's `expand`, with the feature off the template runs. Cross-surface inconsistency only; pick one precedence and note it in §9/§12.
8. **SPECS §15 test-count drift.** This change adds 10 top-level tests (make-guard walk/cd/named pins, the case-variant skill refusal, the multibyte fold pin, the reaching-C5b untrusted-resume guard, the same-day bump, the steering re-queue); §15's established-count line should be refreshed at the branch's next bookkeeping pass per house rule (one count update per PR, not per push).

## Non-goals (recorded, not planned)
