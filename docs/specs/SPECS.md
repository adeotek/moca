## 1. Overview

moca is a minimal, token-efficient, provider-agnostic coding agent. Go 1.27.1 (pinned once in `go.mod`'s `toolchain` directive, which mise reads), stdlib + one parsing dependency (`mvdan.cc/sh/v3`). Module `github.com/adeotek/moca`, binary `moca`.

**Implemented:** phase 1 — streaming via three hand-rolled protocol codecs, JSONC config, catalog, retry, registry. Phase 2 — the seven frozen tools, symlink-resolving path jail + parsed shell analysis, approvals/trust/yolo, skills + AGENTS.md in a once-built system prompt, append-only JSONL sessions with pre-edit snapshots and undo, and the agent loop behind `moca -p`. Phase 3 — the interactive TUI (`moca` with no `-p`): inline immutable scrollback with numbered `▸`/`⋯` items and a pager, multi-line input with bracketed paste + chips, the status bar, steering during runs, interactive approvals, `!`/`!!`, and slash commands incl. cross-provider `/model` switching. Phase 4 — the context manager: token-denominated budgets with small-window scaling, a usage-anchored estimate, token-triggered compaction (structured summary + cumulative file lists, cut points that never orphan tool results, split-turn merge) with a loop guard, one compact-and-retry on provider overflow, `/compact` in the TUI, and `--resume <id8|last>` / `--continue` for both `-p` and the TUI (stored system prompt reused verbatim, model/effort restored from `model_change`, crash-repair for unanswered tool calls). Phase 5 — the MCP lazy proxy: `internal/mcp` (JSON-RPC 2.0 over stdio + streamable HTTP, a persisted name+description discovery index, a manager with lazy start / idle stop / restart, the real `mcp` tool with read-only/approve/session gating and 30K-truncated rendering), `Agent.Close` stopping server processes, the TUI `ctrl+a` persistence to `mcp.servers.<name>.approve`, and the `moca mcp import` / `moca mcp index` subcommands (§10.5). Phase 6 — the rtk/graphify/skills ecosystem: the shell analyser unwraps `rtk <cmd>` (`rtk` and the wrapped command are both classified; runners and shell strings fail closed), the built-in `rtk` skill is verified against the real CLI, SKILL.md / prompt-template files written for pi, Claude Code and OpenCode load unchanged (vendored corpus + `SOURCES.md`), and skill read-roots cover whole skill directories even when they appear after session start. Phase 7 — subscription OAuth behind the DESIGN §3 policy gate (verified live 2026-10-06, `docs/specs/oauth-verification.md`): **anthropic ships `api_key` only** (the policy refusal is a config error carrying the recorded reason); **openai ships OAuth** via Sign in with ChatGPT token sharing on the `openai-responses` route — dynamic client registration, PKCE S256, loopback + headless login, nonce/RS256/JWKS ID-token validation, a 0600 token store with cross-process locked rotating refresh, `moca login|logout`; the subscription route omits `max_output_tokens` and groups the seven tools in a namespace (§6.5). Plus the upstream `graphify install --platform moca` PR (Graphify-Labs/graphify#4174), version stamping from `git describe` + `make release`, `--help`, and the automated §14 ship gate (`test/shipgate/`) — checker + scripted rehearsal, and the live legs: consecutive green unattended runs on real `glm-5.3-flash` (2026-10-07) once the failing-test investigation protocol (§7) and provider robustness fixes (`§8`, bounded header wait) made the §14 loop's read/search steps structural.

**Not implemented yet:** a live `moca login openai` round-trip (needs a ChatGPT account) and the released `graphify install --platform moca` (PR pending upstream; manual copy in `docs/external-tools.md`). The §14 ship gate's live legs passed 2026-10-07 (§15); the current version is `v0.2.0-beta`.

## 2. Build, test, verify

```bash
mise install                      # provisions Go 1.27.1 from go.mod; `go` is not on the global PATH
export PATH="$(mise where go)/bin:$PATH"
make build                        # bin/moca, version-stamped from `git describe` (or: go build ./...)
make test                         # go test ./... -race -count=1
make vet                          # go vet ./... + gofmt -l . (both must be clean)
./bin/moca --version              # "moca v0.2.0-beta" / "moca <commit>" / "moca <commit>-dirty"
bin/moca update --check           # self-update: compare with the latest GitHub release
bash install.sh                   # install/update the binary from the latest release package
make release                      # dist/ cross-compiled (linux amd64+arm64, darwin amd64+arm64, windows/amd64)
bash test/shipgate/run.sh         # the §14 ship gate (needs the repo .env model key)
```

CI (`.github/workflows/ci.yml`) runs the same gate set — the gofmt check, `go vet`, `go build`, `go test ./... -race` — on every PR, every push to `main`, and manually; Go is pinned from `go.mod`, no secrets required. The ship-gate package is behind `//go:build shipgate`, so CI's plain `go test ./...` skips it.

Release packages (`.github/workflows/release.yml`): a manual `Release` workflow run (Actions → Release → Run workflow — pushing a `v*` tag deliberately does not trigger it) builds **linux/amd64, linux/arm64 and windows/amd64** with the same `-trimpath` + `-ldflags` version stamp as `make build`, packages each as `moca-<version>-<os>-<arch>.tar.gz` (`.zip` on Windows, `moca.exe` inside) plus a `checksums.txt` (sha256sum format), and publishes them as a GitHub Release (an existing release for the tag gets its assets replaced — re-runs are safe; a run from an **untagged** ref is a rehearsal and creates a **draft** instead — `moca update` and the installers ignore it until it is published by hand). Those asset names are the contract `internal/update` consumes for `moca update` (§3). `make release` remains the local five-target build — darwin included.

Install scripts (`install.sh` for Linux, `install.ps1` for Windows): pick the latest release (or a pinned `--version`/`-Version <v>`), fetch the platform package + `checksums.txt` (checksum enforced — a mismatch or a missing entry aborts with nothing installed; a release without checksums only warns), extract, and install into `--dir`/`-Dir`, else the directory of the `moca` already on PATH, else `~/.local/bin` / `%LOCALAPPDATA%\Programs\moca` (added to the user PATH on Windows). Re-runs are updates in place — already-installed is never an error; replacing a running binary is safe (write-beside + rename on Linux; rename-aside + next-run cleanup on Windows). `MOCA_API_BASE` overrides the API base (tests/mirrors).

- Version stamp: `config.Version`, set by the Makefile from `git describe --tags --always --dirty` via `-ldflags "-X github.com/adeotek/moca/internal/config.Version=…"`; a plain `go build` keeps the `"0.0.0-dev"` default.
- Repo flow: `main` is PR-only (local pre-push hook blocks pushes to `refs/heads/main`); one branch + PR per phase (`phase/N-<slug>`) or chore (`chore/<slug>`); conventional commits; one version bump per PR (current version: `v0.2.0-beta`).
- Gate scripts for the phase-1 style mock checks are not in the repo; a mock SSE server + a config pointing `baseUrl` at it reproduces them (see §10).
- The `make` targets are mirrored as mise tasks defined in `mise.toml` (`mise run build|test|vet|fmt|release|clean`); `make` stays canonical for machines without mise.

### Package layout (implemented)

```
cmd/moca/          main.go (entry, signals), cli.go (flags → Options), oneshot.go (-p agent path), tui.go (TUI path + trust), update.go (`moca update`)
internal/llm/      leaf types: Message, ContentBlock, ToolCall, ToolResult, Request, Usage, Event…
internal/config/   version, paths, JSONC pre-pass, typed config + validation, env indirection, AppendString (JSONC-preserving edit)
internal/update/   `moca update`: GitHub release fetch, semver compare over the describe stamp, checksum verify, atomic binary replace (leaf — no internal imports)
internal/compact/  token estimate helpers + compaction: budgets, cut points, lossy serialization, structured summaries (no provider import)
internal/provider/ SSE reader, error taxonomy, catalog, 3 protocol codecs, replay helpers,
                   retry wrapper, registry (incl. CheckCredential for model switches)
internal/tools/    Tool interface + registry, the 7 tools, ReadTracker, shell runner, ignore matcher
internal/permissions/ path jail, parsed shell analysis (+Windows best-effort), trust store, yolo checkers
internal/skills/   SKILL.md frontmatter/discovery, embedded built-ins, AGENTS.md/CLAUDE.md loader, prompt templates
internal/session/  JSONL transcript (entry/writer/rebuild/repair/find), snapshot store + undo
internal/mcp/      lazy MCP proxy: JSON-RPC core, stdio + streamable HTTP transports, SSE reader, persisted discovery index, lifecycle manager, the `mcp` proxy tool, the importer
internal/agent/    system prompt, events, the loop, compaction + resume, cross-provider transform + control surface, Start wiring
internal/tui/      Bubble Tea TUI: pure state (input/items/commands/status/format/sanitize/bridge) + glue (app/pager/trust)
```

Dependency direction: `llm`/`config`/`update` import nothing internal; `tools`, `permissions`, `session`, `skills`, `compact` never import each other (`permissions`/`session` satisfy `tools` interfaces structurally); `provider` imports `llm` + `config`; `mcp` imports `tools` + `config` + `llm` (the proxy tool is a `tools.Tool`; platform process-group helpers are shared with the shell runner); `agent` imports everything; `tui` imports `agent` + the pure packages but never the reverse; `cmd/moca` imports `agent` + `config` + `tui` + `mcp` + `update`. HTTP+SSE hand-rolled; non-UI dependency: `mvdan.cc/sh/v3` (shell parsing). UI dependencies (phase 3): `charm.land/bubbletea/v2`, `charm.land/bubbles/v2`, `charm.land/lipgloss/v2`.

## 3. CLI surface (as implemented)

```
moca                         opens the interactive TUI in the current directory (phase 3; see §3.5)
moca -p "<prompt>"            one-shot agent run; prompt also on stdin (`-p -`, trailing newlines stripped)
  --model <provider/model>    override config model for this run
  --effort <level>            off|minimal|low|medium|high|xhigh|max (validated; clamped per model)
  --approve | --no-approve    project trust for this run (default: no; `--yolo` implies yes unless --no-approve)
  --yolo | --no-yolo          override config `yolo`; yolo turns every permission check off (§11)
  --resume <id8|last>         resume a stored session (id must be the 8-hex suffix; `last` = newest by mtime)
  --continue                  resume the newest session started in this workdir (canonical-path match)
  --version
  --config <path>             dev/test: config file override (hidden from help text)
moca mcp import [--yes]       import MCP servers from Claude Code / OpenCode / Pi configs (never copies secrets)
moca mcp index                start every configured MCP server once to (re)build the discovery index
moca login <provider>         store a credential for the provider (§6.5)
  --api-key                  prompt for an API key instead of the OAuth flow
  --no-browser               headless OAuth: print the URL, read the pasted code from stdin
moca logout <provider>        best-effort revoke of a subscription session, then clear the stored token/API key
moca update [--check]         replace the binary with the latest GitHub release package (--check: report only)
--help | -h                   usage to stdout, exit 0 (handled before the config check)
```

`moca login` stores the credential in `~/.config/moca/auth.json` (§6.5). With an OAuth-capable provider (`openai`) it runs the SIWC flow unless `--api-key` is given; for every other provider it prompts for an API key (providers without an OAuth flow no longer exit 2 — `anthropic` prints the recorded policy reason and then takes a key). The API-key prompt is shown only when stdin is a terminal, so `echo -n "$KEY" | moca login <provider>` stores silently; a nil/exhausted stdin is a usage error naming `/login` and `providers.<p>.apiKey`. After the OAuth flow it offers to flip `providers.<provider>.auth` to `"oauth"` in the config (comment-preserving `config.SetString`); after storing a key while the provider's auth mode is `"oauth"` it prints a note that the key is ignored until the mode is switched back. An unknown provider exits 2 (`unknown provider "x"`). `moca logout` revokes a stored subscription session best-effort (bounded at 15 s) then deletes the provider's entry — token and API key alike.

`moca update` replaces the running binary with the newest GitHub release package (`internal/update`). It reads `releases?per_page=10` and takes the newest **published** release — prereleases included (moca ships alphas), drafts skipped (a rehearsal dispatch creates one); `GITHUB_TOKEN`/`GH_TOKEN`, when set, only raise the API rate limit, and are sent to the API host only, never to asset URLs — picks the `moca-<version>-<os>-<arch>.tar.gz` asset (a `.zip` on Windows; a release with no package for this platform — e.g. darwin — is exit 1), verifies the download against the release's `checksums.txt` when present (absent → a warning on stderr, the install proceeds; a mismatch or a missing entry → refused, nothing replaced), extracts the binary and swaps it in beside the running file — a same-directory rename (atomic on unix; on Windows the old image is renamed `moca.exe.old` and removed by the next update); a symlinked launcher is resolved first, so the target binary is replaced, not the link. It runs **before the config is loaded** — a broken config must not block an update — writes nothing but the binary, never touches sessions or credentials, and refuses a `go run` temp build (that file is deleted when the process exits). The comparison is semver over the `git describe` stamp: `v0.2.0-beta` > `v0.1.1-alpha-2-g0b9528d`; a development build past the tag, a `-dirty` build, or a local build newer than the release reports "not newer" and installs nothing; a stamp with no parseable version (a bare commit hash — built without `make`) is exit 1 naming the releases page. `--check` reports and never writes. `MOCA_UPDATE_API` overrides the API base (tests/mirrors). Exit: 0 (updated · already current · local build newer · `--check`), 1 (fetch/verify/replace failure or an unparseable local version), 2 (usage).

`--resume` and `--continue` are mutually exclusive (usage error, exit 2); an unknown/invalid id is exit 2 listing the 5 most recent ids. Resume works in both `-p` and the TUI: the stored system prompt is reused verbatim, the header's workdir becomes the jail root, model+effort come from the latest `model_change` (else the header), unanswered tool calls get `interrupted — moca exited before completion` results first, and yolo is **never** restored from the file. A provider key that is unset at resume time does not block the resume — the first request fails with the env-var error (exit 2 in `-p`); `--model` overrides the stored model (`SetModel`, recorded as `model_change`).

**`-p` output contract.** stdout = the final assistant answer text only, printed once when the run completes (`Outcome.Text + "\n"`); a hard error prints nothing to stdout. stderr carries the live trace: text of turns that called tools (indented two spaces), `▸ <tool> <summary>` per successful call / `✗ <tool> <first error line>` per failed call, `retry N/M · <wait>` notices, `warning: …` lines (skill discovery), the yolo banner, and the exit summary `tokens <in+cache>/<out> · $<cost>`.

**Exit codes.** `0` completed · `1` provider/runtime error, a final `length`/`refusal` stop (`response truncated (token limit reached)` / `model refused to answer`; the partial answer is still printed), or a failed run setup (data dir, session files, skills — `agent.StartError`) · `2` config, model or usage error (incl. unset `env:` vars, and an OAuth credential the user must fix with `moca login` — `ErrInvalidGrant`/`ErrInvalidClient`) · `3` maxSteps reached (the wrap-up summary is still printed) · `130` interrupted (SIGINT **and** SIGTERM cancel in-flight work). The TUI maps errors the same way (`exitFor`): SIGINT/SIGTERM → `130` (no message; the program runs with `tea.WithoutSignalHandler` — `main`'s signal context is the only handler, Bubble Tea's own raced it at shutdown and could hang), a recovered panic → `1`, ctrl+c/esc or SIGINT/SIGTERM at the trust prompt → `130`; a clean quit after `/clear`/ctrl+c is `0`.

### 3.5 TUI (`moca`, no `-p`)

Inline Bubble Tea v2 TUI (no alt-screen except the pager). Layout top→bottom: scrollback (immutable; finished output goes through `tea.Println`) · live region (the open partial response line; while a run, a `/compact` or a `!` command is in progress an activity row `⠋ working… 12s · esc to interrupt` — spinner, what is happening (`<tool>…`, `thinking…`, `compacting… · esc to cancel`, `$ <cmd>…`), elapsed time; replaced by the approval prompt, marked with a yellow `?`, while a question is pending, or by the `/`-dropdown panel while one is open) · a dim `press ctrl+c again to quit` row for the second after a `ctrl+c` on an empty draft · full-width dim rule · input box (no prompt prefix; 1 row when empty, one row per line of the draft up to the window height minus 8 rows, then it scrolls — it grows and shrinks with the draft, and the draft itself is never capped; a muted `Message moca…  (/help for commands)` placeholder while empty; no cursor-line highlight; the terminal's real cursor is parked in it) · full-width dim rule · two-line status bar. A session opens with the welcome lines at the top of the scrollback: `moca <version>` and `How can I help you today?` (the version is the git-describe build stamp, e.g. `v0.2.0-beta-1-gc392fac`; the product name renders in orange `#d97706` — one shade readable on light and dark backgrounds, since the welcome prints before the terminal reports its background). Submitted (`›`) messages (slate `#3d434c`, set off from the output above by a blank line) and streamed assistant responses (deep blue `#213b49`) carry distinct scrollback backgrounds spanning the full row — each line is padded to the terminal width with one cell of left padding, and longer lines are wrapped to the width minus the padding (word-wise, long words hard-wrapped) so every row keeps the band and the padding; tabs expand to 4 cells before padding is measured (a tab-indented code block must not push a row past the terminal width); the still-open partial response line renders with the same band, so completing a line does not change its look. Light/dark variants are chosen from the terminal background reported via `tea.BackgroundColorMsg` (dark is the default until it arrives; no reply keeps dark). Tool-usage, thinking and notice lines (`↳ queued`, `[interrupted]`, `copied…`, `new session…`, `resumed…`, `⋯ compacted…`) print in a muted gray (`#96a0a4`) with no background; `error:` lines print red and `warning:` lines yellow. **Shrinking frames**: when a frame gets shorter, Bubble Tea's inline renderer clamps its remembered cursor row to the new height; if that row was below the new frame (a tall draft was cleared or submitted, a long streamed line was committed) the move back to the frame top falls short and the old frame's top rows are stranded in the scrollback. `View` therefore (a) parks the terminal's real cursor in the input box, so the remembered row is the draft's cursor row rather than the frame's last row, and (b) never renders a frame shorter than the cursor row the renderer may still remember (`padForShrink`): the deeper of the last View before the current burst of Views and the deepest row in the burst — a gap of 60 ms between Views proves the earlier frame was flushed, while within a burst only the last frame gets drawn and the remembered row is still the pre-burst one (coalesced keystrokes over a tall dropdown are exactly this). The difference is blank rows below the status bar, dropped by a `settleMsg` ~120 ms later once the remembered row is safe (capped so a frame never exceeds the screen). **Scrollback order**: Bubble Tea runs each returned command on its own goroutine, so plain `tea.Println` commands from back-to-back updates can land out of order under a fast stream — output goes through a one-flush-at-a-time queue (`model.emit`: while a flush is in flight later lines queue and go out as one print when its acknowledgement `printedMsg` arrives), so the scrollback always matches emission order.

- **Trust**: `--approve`/`--no-approve` wins; else yolo → trusted; else the saved decision in `trust.json`; else, when the workdir has `.moca/`/`AGENTS.md`/`CLAUDE.md`, a one-time `[y/N]` prompt (saved). Project prompt templates load from `<workdir>/.moca/prompts` (trusted only) + `~/.config/moca/prompts`.
- **Status bar** (event-driven, bottom, two lines): line 1 `version · cwd · branch`; line 2 `provider/model · effort · ctx W · P% · in/out · $cost` (`sub` for OAuth; transient `retry n/m · t` replaces cost; red `YOLO` leads line 1 when yolo is on and is never dropped for width; line 1 drops cwd → branch, then truncates the version; line 2 drops in/out, then truncates the model; both lines hard-truncate as a last resort; content is sanitized before styling). Branch resolves at init, every TurnEnd, and run end (an unborn branch — `git init`, no commit yet — falls back to `git symbolic-ref --short HEAD`). Context `%` = `agent.Status().ContextTokens` (usage-anchored, §6) vs the catalog window. Shown as a whole number from 10% up, with one decimal below (`0.4%`; `<0.1%` for a sliver) so a small conversation in a 1M window does not read as a stuck `0%`; `in/out` are the session's cumulative input tokens (fresh + cache reads + cache writes) and output tokens.
- **Keys**: `enter` send · `shift+enter`/`alt+enter`/`ctrl+j` newline (a muted hint is printed **once per machine** — `hints.json` in the data dir — when the terminal reports no key disambiguation, and the placeholder then names `ctrl+j`; the view requests `ReportAllKeysAsEscapeCodes`) · `↑/↓` history at single-line buffer edges (in the `/`-dropdown: move its selection) · `esc` interrupt (approval visible → deny; `/`-dropdown open → dismiss it) · `ctrl+c` clear input / double-press ≤1s on empty quits (the first press shows the hint row; also inside the pager) · `ctrl+o` pager on the latest item (on the pending approval's whole command while a question is shown) · `alt+t` pager on the latest thinking block (printed thinking lines end with `· alt+t to read`; `/show <n>` opens any item) · `alt+p` toggle paste chips · `g`/`G`/`q`/`esc`/arrows/pgup/pgdn in the pager (alt-screen, soft-wrapped, closed by `q`/`esc`; its title row is clamped to one row and shows the scroll position `N% · q to close`). **Exit**: the final frame keeps the rule and the status bar (the input box and hints are dropped), and when the session holds anything (a run, a `!` note, a resume) `session <id8> · resume with: moca --resume <id8>` prints below it.
- **Pager**: scrollback output produced while the alt-screen pager is open is held (Bubble Tea's `Println` is lost in the alt screen) and printed shortly after it closes — a `releaseMsg` ~50 ms later, once the renderer has left the alt screen (a `Println` that beats the exit is written to the alt screen and lost).
- **Input**: pastes insert at the cursor (CR/CRLF normalized to LF); chips `[paste N lines #K]` for >50-line or control-byte pastes (content verbatim until send; unsafe pastes never expand); a broken marker sends literally; history stores expanded text and re-chips control-byte entries on recall; `esc` returns queued steering above the draft.
- **Runs**: numbered items shared across tools and thinking (`▸ #7 tool summary`, `✗` on error — the mark in red, `⋯ #6 thinking N lines · 12s` — `1 line` singular; bodies open in the pager); a thinking block's item line prints when the block **ends** — before the response text or tool item that follows it, never after — carrying the duration it streamed (`· <1s` under a second; omitted for a block not accumulated from deltas); streaming text commits completed lines to scrollback; the activity row shows the running tool (`<name>…`) or `thinking…`; thinking is never expanded outside the pager. A message sent mid-run is **steering** (queued, drained after the current tool batch; printed `↳ queued:` / `↳ sent:`); a no-tool-call turn appends it and continues.
- **Commands**: `/model [id]` (no argument: a modal picker, current model preselected, models of a provider with no credential marked `no key (/login …)`; with an id: switch; the switch is refused while running — a plain listing is printed instead; forfeits the prompt cache), `/resume [id8]` (a picker over this directory's other sessions — id · age · first user line — or `/resume <id8>`, which refuses an id belonging to another directory; the stored model/effort win as with `--resume`; the open session is untouched if the target cannot be resumed; refused while busy), `/sessions` (the session manager: a picker over this directory's stored sessions, newest first, at most 100 rows — the title reads `newest 100 of N` beyond that; the open one included and marked `(current)`, message-less ones shown as `(no messages)` — enter switches to one (the `/resume` rules), `ctrl+d` asks `delete session <id8>? [y] delete · [n] back` and on `y` unlinks the file through the single-writer lock (`session.Delete`; a session held open by another moca process → `open in another moca process`, nothing removed), then reopens the panel minus the row; the open session refuses deletion — `/clear` starts a new one; refused while busy; no sessions → `no sessions for this directory`), `/effort [level]` (also `shift+tab`: the next supported level, wrapping; refused where `/effort` is), `/hard` (modelHard + high ↔ saved pair), `/yolo` (between runs; red bar field), `/clear` (new session file; old stays resumable; keeps the current model/effort — hard mode exits to its saved pair — and the commands approved with `[ctrl+a]`; yolo resets to the startup flag), `/compact` (manual compaction: runs `agent.Compact` off the event loop on a cancellable context — `esc` or quit cancels it and prints `compaction cancelled` — with a `compacting…` transient; `nothing to compact` when the live window fits `keepRecentTokens`; prints `⋯ compacted: N → M tokens` on success; a run, `!`, `/clear`, `/model`, `/effort`, `/hard`, `/yolo` and another `/compact` are refused while it is in flight), `/cost` (`in T (fresh F · cache read R · cache write W) · out O · $cost`, token counts in the bar's compact form; `subscription` for OAuth), `/undo`, `/copy` (OSC 52 — the last assistant text; a final turn without text keeps the previous one), `/show <n>`, `/login [provider]`, `/logout [provider]`, `/help`, `/exit` (`/q`, `/quit` aliases — quits, unless a prompt template already has that name; an in-flight run/compaction is cancelled and recorded, same as `ctrl+c` twice); `/model`,`/effort`,`/hard`,`/yolo`,`/clear`,`/login`,`/logout` are refused **while a run or a `!` command is in progress**. Prompt templates: `/name args` with `$ARGUMENTS`/`$@`/`$1..$9`/`$$`; built-in names win; unknown → error. A starter `create-command` template is seeded into `~/.config/moca/prompts/` on the first TUI run (`skills.SeedUserPrompts`; an existing file is never overwritten): running it has the agent create or update a saved command — personal ones in the global dir (a write outside the workdir, so moca asks for approval) or project ones under `.moca/prompts/`. The prompt dirs are re-read when a run or `!` command finishes (`AppOptions.PromptDirs`), so a command written during a run is usable without a restart. `/`-escaped text: `//x` sends `/x`. A submitted command **echoes into the scrollback as a user message** (the same `›` band, blank line included) before it runs, so the transcript reads as everything the user sent — refusals and errors follow the echo; `/exit` quits after the echo lands.
- **`/`-dropdown** (autocomplete): while the draft is exactly `/<word>` (no space/newline yet, not the `//` escape) the live-region slot above the input rule lists the built-in commands plus the loaded prompt templates, prefix-filtered case-insensitively as the word grows (`/lo` → `login`, `logout`; built-ins win a name collision and are listed once). Rows are `❯ name  hint` (cursor row marked, hint dim, clamped to the width) — at most 8 rows (fewer on short terminals), the window follows the cursor, and the legend shows `n/N · ↑/↓ select · tab complete · esc dismiss` when the list overflows. `↑`/`↓` move the selection, `tab` completes the selection into the draft (trailing space, cursor parked at the end), `enter` completes a partial word and submits an exact name (the pre-dropdown behaviour), `esc` dismisses until the word changes; no matches hides the panel, as does a run/`!`/compaction/login wizard/pager/approval. The item list is derived from the draft on every lookup — the only stored state is the cursor and the dismissal.
- **`/login [provider]` / `/logout [provider]`** (credentials; §6.5) — a modal wizard rendered above the input rule (↑/↓ picks, `enter` commits, `esc`/`ctrl+c` backs out one level, then cancels — noted as `login cancelled`/`logout cancelled` in the scrollback). `/login` lists the configured providers with their methods (`... — API key`, `... — API key · subscription login`, `... — API key (subscription OAuth not permitted)`); an argument skips the picker. Providers with an OAuth flow get a method row (`API key` / `Subscription login`); everything else goes straight to key entry. The key is entered masked (`•••…`, capped at 40 dots with a char count beyond), is filtered of control bytes (paste included), is **never echoed or stored anywhere but auth.json**, and `enter` writes it via `store.PutAPIKey` — from the next request on the running session uses it (the credential is re-read per request). The OAuth row starts `provider.Login` in a command goroutine with the output bridged into the scrollback through the event pipe (so progress lines and the completion can never swap order); while it runs the panel says so, `enter` with text in the input box hands the pasted redirect URL/code to the flow (a blocked pipe write is spawned, released when the flow ends or is cancelled), and `esc` cancels the flow. After a successful OAuth login whose provider is not configured `auth: "oauth"`, the wizard asks `[y/N]` to flip `providers.<p>.auth` (`config.SetString`, comment-preserving) and reloads the config so the next `/clear` (or restart) picks the new mode up; `n`/`esc` leaves it unchanged. `/logout` revokes a subscription session best-effort (15 s bound, off the event loop) then clears the provider's token and API key; with no argument it picks from the providers that have a stored credential (`nothing stored — /login first` otherwise). Key material is never printed, and the login panel is sanitized like any other rendering.
- **`!cmd` / `!!cmd`**: user-initiated shell in the workdir (30s timeout, `ShellEnv` hygiene, output truncated 30K, `[exit N]`; `esc` kills a running `!` — `[interrupted — process group killed]`, and an interrupted command is not added to the transcript); `!` additionally appends `"$ cmd\n<output>\n[exit N]"` as a user message (bypasses the model-facing analyser, §7); `!!` is display-only. `!` is refused while a run is in progress, and a run/`/clear` is refused while a `!` is still executing (its note would land between a tool batch's results or in the wrong session; `!!` still runs).
- **Approvals**: shell/MCP questions render `allow \`x\`? [a] once [ctrl+a] always [d] deny` (`[ctrl+a]` only when `CanAlways`; `rm` never offers it) followed by the full command/args under a dim `│` gutter — up to 6 lines (fewer on short terminals), each clamped to the width, the rest counted as `… +N lines · ctrl+o shows the whole command` (the subject alone can hide what runs: an approved `python3` executes the heredoc below its first line) — `ctrl+a` persists the command into `config.jsonc` `shell.allow` via the comment-preserving `config.AppendString` (new files 0600, existing files keep their mode; `.bak` + atomic rename; a symlinked config is edited through the link) and adds it to the running session's allow list. The typed draft survives: `a`/`d` only answer after a 700 ms typing pause, and plain letters (a stray capital `A`, the first letter of "Add…") always go to the draft — prose can never answer a prompt that pops up mid-sentence, and never persist an allow-always; `esc` always denies; `enter`/`ctrl+c` keep their normal meaning while a prompt is shown.
- **Bridge/threading**: the agent runs in a goroutine; `Emit` delivers events through a FIFO pipe (`eventPipe`) — the run's completion (`runDoneMsg`) rides the same pipe so it can never overtake a streamed delta and flush a half-streamed line — because `Program.Send` blocks on an unbuffered channel and `Update` runs on the event-loop goroutine (a synchronous emit — e.g. `/yolo` — would deadlock); the asker blocks the agent on a reply channel. The agent guards its shared state with a mutex, so the TUI's `Status()` polling during a run is race-free.
- **Rendering safety**: model/user/tool/error text goes through `Sanitize` (C0 controls → `^[`-style, DEL → `^?`, C1 controls U+0080–U+009F → their ESC form, e.g. U+009B → `^[[`) before it reaches the terminal — including the approval prompt and the status bar (sanitized *before* styling); styled lines are printed without sanitizing.

## 4. Config

- Path `~/.config/moca/config.jsonc` (`$XDG_CONFIG_HOME` honoured); data dir `~/.local/share/moca` (`$XDG_DATA_HOME`). Missing file → built-in defaults. Strict decode: **unknown keys are rejected**; errors carry `line:col`.
- **JSONC pre-pass** (`config.Standardize`): comments (`//`, `/* */`) are recognised only outside string literals (escapes honoured) and replaced by spaces — output has the **same length** as the input, so error offsets still map to the original line:col. A trailing comma (`,` followed only by whitespace/comments before `}`/`]`) is blanked. Unterminated `/*` → error. The §12 example of DESIGN.md is the byte-exact fixture (`internal/config/testdata/example.jsonc`).
- **Keys** (camelCase): `model`, `modelHard`, `providers.<name>` (`auth` = `api_key|oauth`, `apiKey` — optional; `"env:VAR"` when set — `baseUrl`, `baseUrls` per protocol, `protocol`, `models.<id>` with `protocol`/`contextWindow`/`maxOutputTokens`/`cost`), `shell.allow`, `mcp.idleTimeout` + `mcp.servers.<name>` (command|url, args, env, headers, description, approve), `snapshot.retentionDays` (0 = forever), `context.reserveTokens|keepRecentTokens|maxSteps`, `providers.ollama` (local provider, §6), `tui.notify` (`osc9|bell|off`), `yolo`.
- **Defaults**: built-in providers `anthropic`/`opencode-go`/`openai` with `auth: api_key` and `env:ANTHROPIC_API_KEY` / `env:OPENCODE_API_KEY` / `env:OPENAI_API_KEY`; `shell.allow` = the 32-entry DESIGN §12 list; `mcp.idleTimeout` 600; `context` 16384/20000/40; `snapshot.retentionDays` 30; `tui.notify` `osc9`; `yolo` false.
- **Validation**: model ids must be `provider/model` (split at first `/`); provider must exist; an `apiKey` literal → rejected (must be `env:`), an omitted `apiKey` → accepted (a store-only provider, resolved from `/login`); custom providers need `baseUrl`(+`baseUrls`) and `protocol`; model-level `protocol` must be one of the three; custom models must declare `contextWindow`; `contextWindow < 16384` refused; context values and `retentionDays >= 0` checked; each MCP server must have exactly one of `command`/`url`; `mcp.idleTimeout` must not be negative (0 = the default 600); `tui.notify` must be `osc9`, `bell` or `off`; `auth: "oauth"` is rejected for a provider the §3 policy gate refuses (anthropic — the error carries the recorded reason, §6.5) and for any provider without an implemented OAuth flow (`config.OAuthProviders`, pinned against `provider.oauthProviders` by a test — "no OAuth support for this provider; set \"api_key\"").
- **Env indirection**: `env:VAR` resolved lazily — an unset variable errors **when the first request to that provider is built** (naming the variable, `*config.EnvError` → exit 2), never at startup; unused providers don't block. For `api_key` providers resolution is **store-first**: a key stored in auth.json (§6.5, `/login` or `moca login`) wins over the config's `env:VAR` reference; the error when neither exists names the variable and both login entry points. `config.EnvRefs` lists every referenced variable (used by phase 2's shell hygiene).
- **Custom providers** (vLLM/LM Studio/Ollama…): any name + `baseUrl` + `protocol` + models with `contextWindow`; usable through the same registry path.
- **`config.AppendString(path, keyPath, value, init)`** (phase 3) — comment-preserving JSONC edit: appends `value` to the string array at `keyPath` (creating missing objects / the file, 0600), no-op when present, everything else byte-identical (string-literal-aware `Standardize` + an offset-tracking scanner; trailing commas and `//`/`/* */` comments survive, also those containing commas). Writes `<path>.bak` then an atomic rename. Used by the TUI's allow-always and by MCP approvals (`mcp.servers.<name>.approve`).
- **`config.SetObjectEntry(path, keyPath, key, rawJSON)`** (phase 5) — inserts `"key": rawJSON` into the object at `keyPath` with the same guarantees as `AppendString` (missing parents/file, `.bak` + atomic rename, mode/symlink preservation, byte-identical elsewhere); an existing key is left untouched (`added=false`); a non-JSON value is refused before any write. Used by `moca mcp import`.
- **`config.SetString(path, keyPath, key, value)`** (phase 7) — replaces an existing string value in place (the same standardized-text offset scanner; `.bak` + atomic rename, mode/symlink preservation; falls back to `SetObjectEntry` when the key or path is missing). Duplicate keys resolve to the last occurrence — the value `encoding/json` keeps, so the edit lands where it takes effect; a non-string prior value is refused, never replaced. Used by `moca login`'s offer to flip `providers.<name>.auth` to `"oauth"`.

## 6. Providers & registry

`provider.NewRegistry(cfg, httpClient, notify)` builds the catalog (built-ins + config overrides/additions) and validates that `model`/`modelHard` resolve.

- **Default base URLs** — `anthropic` → `https://api.anthropic.com`; `openai` → `https://api.openai.com/v1`; `opencode-go` → anthropic-messages `https://opencode.ai/zen/go`, openai-* `https://opencode.ai/zen/go/v1`. **Precedence**: `baseUrls[protocol]` > `baseUrl` > built-in default.
- **Model overrides merge, not replace**: a config entry for a catalog model changes only the fields it sets; a new model under a custom provider needs `protocol` + `contextWindow` (config validation); a new model under a **built-in** provider needs `protocol` (model-level or provider-level) — otherwise `NewRegistry` fails fast with the exact key path to add.
- **Credentials resolve store-first** (§6.5): an `api_key` provider reads the credential store (auth.json, 0600) at request time — a key stored with `/login` (TUI) or `moca login <provider>` wins over the config's optional `env:VAR` reference, which is the fallback; neither → a clear error naming the variable and both login entry points (`*config.EnvError` → exit 2). Because the store is read per request, a key stored mid-session applies to the next request. `oauth` resolves through the store's token entry — the registry hands the adapter a store-backed credential that refreshes on demand, and a missing or revoked login errors with "run `/login` in the TUI, or moca login" (exit 2). Registry rule: an `oauth` provider resolves only for models whose protocol is `openai-responses` (the error names the protocol).
- **OpenCode Go routing header**: every `opencode-go` request carries a stable per-conversation `x-opencode-session` (a `crypto/rand` string generated per process — one process is one conversation today; phase 3+ sessions must rebind it per conversation) and every request from every provider identifies the client as `User-Agent: moca/<version>`. The Go tier rejects session-less requests with HTTP 400 `MissingSessionID` (verified live 2026-10-05, https://opencode.ai/docs/go/#where-can-i-use-it); zen pay-as-you-go (`/zen/v1`) does not require it.
- **Ollama (`ollama`, a local-provider)** — a local or LAN model server over its OpenAI-compatible endpoint (`openai-completions`, the existing adapter). `config.LocalProviders` = `[ollama]`: **opt-in** — it exists only when `providers.ollama` is present (an empty `{}` is enough: no `baseUrl`, `protocol`, key or model list needed; `auth` defaults to `api_key`) or when `model`/`modelHard`/`--model` names an `ollama/…` model (`Config.UseProvider`, which copies the Providers map). Nothing is probed for anyone who did not opt in.
  - **Base URL**: `providers.ollama.baseUrl` > `$OLLAMA_HOST` (the variable Ollama's own CLI honors) > `http://localhost:11434`. Any form people write is normalized (`nas` · `nas:8080` · `:11434` · `http://nas:11434` · `https://host/prefix/v1`): scheme `http` and port 11434 default in, `0.0.0.0` means `127.0.0.1`, and `/v1` is appended to a bare host (an explicit path is kept). LAN use: the *server* must listen beyond loopback (`OLLAMA_HOST=0.0.0.0`).
  - **No credential needed**: with no stored key and no `apiKey`, requests carry no `Authorization` header; a key stored with `/login ollama` (or an `env:` `apiKey`) is sent as a bearer token — for a server behind an authenticating proxy. A configured-but-unset `apiKey` env var is still an error.
  - **Model discovery** (`Registry.DiscoverOllama`, ≤ 4 s, best effort, run by `agent.Start`/`Resume` after `NewRegistry` and again by `/model`): `GET /api/tags`, then `POST /api/show` per model (8 in parallel). Embedding models and models without the `tools` capability are not offered (a failed `show`, or a server too old to report capabilities, keeps the model); `thinking` capability → `ThinkingMode openai` with levels `off`→`none`, `low`/`medium`/`high` (`reasoning_effort`); `MaxOutput` = window/4 clamped to 2048–16384; cost 0. A rediscovery replaces the previous ollama models (pulled ones appear, removed ones go). **Models declared under `providers.ollama.models.<id>` always exist and override what was discovered** (`contextWindow`, `maxOutputTokens`, `cost`); a declared-only model defaults to `openai-completions` and the assumed window.
  - **Context window**: the OpenAI-compatible endpoint cannot set `num_ctx` per request, so the real window is whatever the server runs with. moca takes `num_ctx` from the model's Modelfile parameters (`/api/show`); otherwise it **assumes 16384** (`config.MinContextWindow`). `agent.Start` emits a `Warning` when the *selected* model's window was assumed (set `OLLAMA_CONTEXT_LENGTH` on the server or declare `contextWindow` to match — a smaller real window silently truncates the prompt, and usage-anchored compaction never notices) or is below 16384 (too small for the system prompt and tools).
  - **Startup**: `NewRegistry` makes no network call and does not reject an `ollama/…` default/hard model; `Registry.Verify()` (after discovery) does, citing why — the server is unreachable, or `has no model "x" with tool support — pull it (ollama pull x) or declare it`. An unreachable server is *not* an error when the default model lives elsewhere.
  - **Failures**: a request that cannot reach the server (refused, no route, DNS, dial timeout) fails at once with `cannot reach ollama at <url> (<cause>) — is “ollama serve” running? …` — not retried (`ollamaGuard`, outside the retry wrapper; mid-stream resets still retry); HTTP 404 `model … not found` appends `pull it first: ollama pull <model>`; a `does not support tools` 400 suggests a tool-capable model; discovery answering 401/403 points to `/login ollama`.
- `Resolve("provider/model")` → `(Model, Adapter)`; the adapter is already wrapped in the retry policy. `Models()` returns the catalog sorted (for phase 3's `/model`).

## 6.5 Subscription OAuth (phase 7)

**Policy gate (DESIGN §3, binding).** Before any OAuth code for a provider ships, the vendor's current terms must permit third-party clients to use subscription credentials, and the registration path for a third-party client must be known; `unclear` counts as not permitted — no workarounds, no spoofed client identities. Record: `docs/specs/oauth-verification.md` (all URLs fetched live 2026-10-06). Outcomes: **anthropic — `api_key` only** (Anthropic does not permit third-party clients to use Claude subscription OAuth; `providers.anthropic.auth: "oauth"` is a config error naming the record); **openai — OAuth ships** via Sign in with ChatGPT (SIWC) open-source token sharing, and only on the `openai-responses` protocol.

- **Credential store** (`internal/provider/auth.go`) — `~/.config/moca/auth.json` (file 0600, dir 0700; the write forces 0600 even when a stale tmp file exists, and the rename deliberately replaces a symlink rather than following it). Two sections: `providers.<name>` holds the OAuth token — access/refresh tokens, expiry, account id, client id, id token, email, granted scopes — and `apiKeys.<name>` holds a provider API key stored with `/login` (TUI) or `moca login <provider>` (validated: empty values and control bytes are refused, so a credential can never smuggle a newline into a header). Atomic writes (temp file + rename). Every read-modify-write runs under a cross-process exclusive lock (`flock` on Unix, `LockFileEx` on Windows), so concurrent moca processes cannot clobber each other's rotated tokens; reads (including a per-request API-key lookup) are lock-free. **Migration**: a v0.1 store in the data dir is moved once at startup (`provider.MigrateLegacyStore`, called from `main`) — content and mode preserved, the old file only removed after the new one is in place, best-effort with at most one warning.
- **Login** (`moca login openai`, or `/login` in the TUI) — dynamic client registration (no client secret; the issued client_id is stored with the token), PKCE S256, state + nonce, loopback callback on `127.0.0.1` (the redirect host must be the loopback literal). The CLI opens the browser unless `--no-browser`; headless fallback prints the URL and reads the pasted code from stdin (one shared line reader serves the paste prompt and the later "switch auth?" prompt, so an unanswered paste read never swallows that answer; the loopback page reports a refused login with a 400, not "Login complete") (a pasted redirect URL that lost its scheme is recovered, and the state is verified in every form that carries one). The TUI wizard runs the same flow in a command goroutine with its output bridged into the scrollback, accepts the pasted redirect URL/code from the input box while it waits, and cancels on `esc`. Each login HTTP call (token exchange, JWKS) is bounded by a 30 s client timeout. The ID token is validated (RS256 against the provider JWKS with kid selection, issuer, audience, nonce) and the required scope (`chatgpt.tokens.use.direct`) must be present. An entropy failure aborts the login (state/nonce are never empty); a callback/paste race resolves first-wins on one shared channel. Refusals (`ErrInvalidGrant`/`ErrInvalidClient`) are usage errors → exit 2 with a login hint. Providers without an OAuth flow take an API key instead — `moca login <provider>` (prompt only on a terminal; piped stdin stores silently) or the TUI wizard's masked entry — written to `apiKeys.<provider>`.
- **Refresh** — access tokens ~1 h, refresh tokens rotate (~30 d). A refresh holds the store lock across read → refresh → write, so a concurrent process re-reads the fresh token instead of burning a rotated one; the lock wait honours the caller's context (polling, so Ctrl-C works) and the exchange is bounded at 30 s. `invalid_grant` keeps the stored entry (so `moca logout` still works) and errors "session expired … run `/login` in the TUI, or `moca login`" (exit 2). A transient failure (network, 429/5xx, timeout) is an `*HTTPError`/network error the retry layer retries, and while the access token still has time left it is used as is. `Registry.CheckCredential` (the `/model` and resume check) only confirms a login is stored — it never refreshes.
- **Wire use** — the subscription credential is a bearer on the Responses API with `store:false`; on this route moca omits `max_output_tokens` and sends the seven tools grouped in a single `{type:"namespace", name:"moca"}` group (the SIWC tool-shaping contract); the stream handling is unchanged.
- **`moca logout openai` / `/logout`** — best-effort revoke at the provider (bounded at 15 s — a stalled endpoint cannot hang the command), then deletes the provider's entry — OAuth token **and** stored API key. The TUI variant runs the revoke off the event loop and its argument-less form picks from the providers that have a stored credential.
- **Known limitation**: the client_id is registered per login (no shared app client id yet); no Anthropic OAuth by policy.

## 7. Protocol adapters (wire behavior)

All three: `post()` sends JSON with `Content-Type: application/json`, `Accept: text/event-stream`, `User-Agent: moca/<version>`; **a 2xx whose Content-Type is set and not `text/event-stream` is an error** ("unexpected … response, want text/event-stream: <body≤8KiB>", non-retryable) instead of a fake turn. Response bodies are closed on every path; stall timeout 90 s. Requests use a client with a 120 s response-header bound (`agent.defaultHTTPClient` clones `http.DefaultTransport` and sets `ResponseHeaderTimeout`; tests may inject their own) — the stall bound only covers the response body, so without it a provider that accepts a request and never answers could hang an unattended run (observed once in the live ship-gate runs).

**anthropic-messages** — `POST {base}/v1/messages`; headers `anthropic-version: 2023-06-01`, `x-api-key` (or `Authorization: Bearer` for OAuth tokens).
- Body: `system` as one text block; `tools` (last tool carries `cache_control`); `tool_choice`; messages; thinking per §5. Cache breakpoints: system end + last tool + **the last eligible block of the last message** (text non-empty / tool_use / tool_result — never thinking/redacted/empty-text; walks back; omitted if none). `NoCacheWrite` (compaction) removes every `cache_control`.
- Stream: `message_start` (usage in), `content_block_*` (text/thinking/redacted_thinking/tool_use; `input_json_delta` assembled per index), `message_delta` (stop reason + output usage), `message_stop`. Missing `message_stop` at clean EOF → `io.ErrUnexpectedEOF` (retryable). In-stream `overloaded_error` → `*HTTPError{529}`. HTTP 400 "prompt is too long" → `ErrContextOverflow`.
- Thinking capture: `Model` = request model, `Signature` from `signature_delta`; `redacted_thinking` → `Redacted=true`, opaque `data` in `Signature`, text `[Reasoning redacted]`.
- Stop mapping: `tool_use`→tool_use, `max_tokens`/`model_context_window_exceeded`→length, `refusal`→refusal, else end_turn.

**openai-completions** — `POST {base}/chat/completions`; `Authorization: Bearer`. Body: system first; per message, text joined, tool calls with `arguments` as a JSON string, tool results as `role:"tool"`; `stream:true`, `stream_options.include_usage`; `reasoning_effort` per §5. Thinking blocks from history are **never sent** (no wire slot). Stream chunks: `content`, `reasoning_content`/`reasoning` (→ thinking events), `tool_calls[]` assembled **per `index`** (id/name/args may be split across deltas), `finish_reason`, usage (`prompt_tokens − cached_tokens` → Input, `cached_tokens` → CacheRead). Terminal: `[DONE]` or any `finish_reason`; otherwise `io.ErrUnexpectedEOF`. `content_filter`→refusal, `length`→length, `tool_calls`→tool_use; calls present with a `stop`/missing reason → tool_use. Overflow: 400 with `context_length_exceeded` / `maximum context length`.

**openai-responses** — `POST {base}/responses`; `Authorization: Bearer`. Body: `input` items (message text in/out, reasoning items with `encrypted_content`, function_call/function_call_output), `store:false`, `include:["reasoning.encrypted_content"]` (stateless reasoning replay), `instructions` = system, tools as `{type:function,…}`, `reasoning` per §5. Stream: `response.output_text.delta`, `response.reasoning_summary_text.delta` (accumulated per `item_id` as a fallback for the final item's summary), `response.output_item.done` (reasoning → thinking block with `ThinkingID`+`Signature`; function_call → call), `response.completed|incomplete` (usage; `incomplete`+`max_output_tokens`→length), `response.failed` (context_length_exceeded → `ErrContextOverflow`; server_error/rate_limit_exceeded → retryable 500). Terminal: completed/incomplete; otherwise `io.ErrUnexpectedEOF`. On the subscription (OAuth) route the body differs (§6.5): `max_output_tokens` is omitted and the tools go in one `{type:"namespace", name:"moca"}` group; the stream is unchanged.

**Tool calls — kept, never dropped.** Arguments are assembled and kept **as received**, even when cut off mid-JSON (`{}` only when nothing arrived). This is the phase-2 contract: the agent loop attaches a §6 error result ("your output was cut off at the token limit… split the work") to **every** call of a `length`-stopped turn, and the tool registry rejects invalid JSON with its own error result. A `tool_use` block that never received `content_block_stop` is kept with a nil input (not emitted). Calls are emitted to the event stream in order (anthropic: at `content_block_stop`; the OpenAI protocols: after the stream ends, index order). The stop reason is **never** force-upgraded from `length`/`refusal`; `end`+calls → `tool_use`.

**History replay** (`replay.go`):
- Thinking replays **verbatim** (anthropic `thinking`+signature / `redacted_thinking`+data; responses reasoning item) only when `block.Model == request model` **and** `Signature != ""` (responses also needs `ThinkingID` and not redacted). Anything else degrades to a text block `[prior reasoning]\n<text>` (anthropic / responses-as-output_text); redacted or empty-text blocks are dropped. Rationale: signatures/encrypted payloads are bound to the producing model — replaying them elsewhere (or unsigned) is a 400 on every later turn.
- Tool input on replay: nil or invalid JSON → `{}` in all three adapters (invalid `json.RawMessage` would otherwise fail `json.Marshal` or send `"arguments": ""`).

**Usage normalization** (all protocols): `Input` excludes cache reads/writes; `CacheRead`/`CacheWrite` carried separately; `Usage.Add` accumulates.

## 8. Retry, errors, exit mapping

`WithRetry(adapter, DefaultRetryPolicy(notify))` — uniform across protocols.

- **Retryable**: HTTP 408/429/5xx (incl. anthropic 529) and HTTP 400 whose body is led by `"type":"server_error"` (the opencode-go gateway frames some upstream failures that way — the `[1210]` thinking-config flake; the server calls it a server error, so it is retried, bounded by the five-attempt budget); `ErrStall`; `io.EOF`, `io.ErrUnexpectedEOF`; `ECONNRESET`, `ECONNREFUSED`, `ECONNABORTED`, `EPIPE`; net timeouts; HTTP/2 GOAWAY / stream-reset (matched by error text — the stdlib types are unexported). **Not retryable**: other 4xx, `ErrContextOverflow`, `context.Canceled`, non-SSE 2xx.
- **Schedule**: 1/2/4/8/16 s (±20 % jitter), max 5 attempts, only while nothing has been emitted. `Retry-After` (integer, fractional or HTTP-date; ≤0 → 0) overrides the wait when larger; the wait is capped at 60 s.
- **Mid-stream failure** (anything already emitted): emit `EventReset` (consumers discard partial output), pause (jittered first delay, retry-after honoured — announced via `Notify` like any retry), retry the same request **once**; a second failure surfaces. This retry is outside the 5-attempt budget.
- **Stall**: no bytes for 90 s → `ErrStall` (aborts the attempt; retried).
- **Errors**: `*HTTPError{Status, RetryAfter, Body≤8KiB}`; `ErrStall`; `ErrContextOverflow` (wrapped by adapters); `*config.EnvError`; `provider.ErrInvalidGrant`/`ErrInvalidClient` (OAuth — user-fixable). `cmd` maps: `EnvError`→2, `ErrInvalidGrant`/`ErrInvalidClient`→2, cancellation/ctx→130, everything else→1.

## 9. `-p` run semantics

`-p` builds the full agent (§14): resolves the model, clamps the effort, and runs one conversation whose workdir is the process cwd. Trust for the run: explicit `--approve`/`--no-approve` wins, else yolo → trusted, else **no** (project `.moca/**` and `AGENTS.md`/`CLAUDE.md` are ignored). Session slug = first five words of the prompt. `--resume`/`--continue` replace the fresh start with `agent.Resume` (stored prompt/workdir/model; trust and slug apply to fresh sessions only). The run ends when the model answers without tool calls; `context.maxSteps` batches trigger one wrap-up request (`tool_choice: none`, tools still listed) and exit 3.

## 10. Tools (seven, frozen)

Schemas are frozen since phase 2 (`internal/tools/testdata/schemas.golden.json`; changing one is a v2 discussion): `read, write, edit, shell, search, ls, mcp`. Execution: calls of one turn run **sequentially in emitted order**; a failed call does not cancel the rest; every call gets exactly one `tool_result`. Unknown tool → error listing the available tools; invalid JSON arguments → error telling the model to split the work (§6).

- `read` — `N|content` lines + `[lines A-B of TOTAL]` footer (+ `use offset=B+1 to continue` when more remain); caps 2000 lines / 50K chars per call; lines >2000 chars truncated with `[… line truncated]`; NUL in the first 8K → refused with size + MIME guess; a directory → "use ls"; non-regular files (FIFOs, devices) and files >256 MB are refused; the window is streamed with a bounded reader (no whole-file load); every successful read records mtime/size/sha256 (ReadTracker, streamed hash). Reading any `*_test.go` sets `Env.TestSeen` and clears `Env.FailingTest` (investigation protocol below).
- `write` — creates files (parents created inside the jail); an existing file needs a prior read **and** must be unchanged on disk since; mode preserved (new files 0644); after writing, the file is recorded so consecutive edits don't need a re-read. Outside the workdir it resolves only through the jail's ask-write root (the global prompt templates) and only with the user's approval (see §11; the read guard runs before the prompt, and a denial returns a model-facing message naming `.moca/prompts/`).
- `edit` — the edit ladder (§5): exact unique match → replace; several exact matches → error listing the lines + suggests `replace_all`; `replace_all` replaces every exact occurrence (never falls back to fuzzy); no exact match → one whitespace-insensitive match accepted and `new_string` re-indented to the file's indentation; none/ambiguous → model-facing error (mentions `N|` prefixes when the text looks like pasted read output); empty `old_string` → "use write"; identical strings → error; CRLF and BOM preserved; non-UTF-8 refused. Result: unified diff + `changed lines …; file now N lines`; Summary `path [+a −d]`. While a failing test run is unresolved it refuses **before** applying, naming the missing investigation step (investigation protocol below).
- `shell` — stateless (cwd = jail root every call); `bash -c` (Unix) / `pwsh -NoProfile -Command` → `powershell.exe` fallback; stdin `/dev/null`; stdout+stderr merged; invalid UTF-8 bytes replaced; head+tail truncation at 30K chars with `[… N lines omitted]`; capture itself is bounded at 64K head+tail with a `[… N bytes omitted]` note; `cmd.WaitDelay` 2 s stops a straggler (e.g. a `setsid` descendant) holding the pipe from blocking after a kill; `[exit N]` always reported (`[timed out after Ns — process group killed]` on timeout); timeout 1–300 s (default 30) kills the whole process group; env = inherited minus every `config.EnvRefs` variable, plus `PAGER=cat GIT_PAGER=cat GIT_EDITOR=true GIT_TERMINAL_PROMPT=0`. A failing test run (a runner marker — `go test`, `pytest`, `rtk test`, … — in the command, and a failure signal: exit ≠ 0 or `fail` in the output, since piped runs mask the exit code) arms the investigation protocol: `Env.TestFailed` + `Env.FailingTest` (the `*_test.go` named in the output; generic `*_test.go` when unparseable); a green test run clears both.
- `search` — RE2 regex; respects `.gitignore`/`.ignore` from the workdir down to the search path (deeper files override); files >4 MB are skipped with a visible note; skips hidden + binary; `glob` matched against the basename (or the relative path when it contains `/`); 200-hit cap with a visible note; `files_only`; output `path:line:text` (text cut at 300 chars). Sets `Env.Searched` (investigation protocol).
- **Investigation protocol (phase 7, from the live ship-gate runs)** — while a failing test run is unresolved (`Env.TestFailed` and not both `Env.TestSeen` and `Env.Searched`), every tool result carries a registry-level banner naming the next step — *"tests failed: (1) read the failing test file (calc_test.go) with the read tool, (2) locate the cause with the search tool, (3) only then edit"*, then *"locate the cause with the search tool before editing"* once the test is read — and `edit` refuses with the missing step, so the §14 loop's read/search steps are structural, not advisory. The target model class treated equivalent actions (a test run, `cat`, `ls`) as satisfying tool-specific steps and ignored hints (two prompt iterations, then per-tool hints: live runs 2–7); the refusal messages were complied with immediately (live runs 8–11).
- `ls` — one directory level, sorted; dirs `/`, symlinks `@`; 1000-entry cap; hidden entries only with `hidden:true`.
- `mcp` — the phase-5 lazy proxy: frozen ~200-token schema (byte-identical `tools.MCPSpec()`), actions search/describe/call; server tool lists never enter the prompt (§10.5).

Approvals: allowlisted-but-unapproved → ask (AllowAlways persists via `Commands.Allow`); `rm` → ask every time (`CanAlways:false`, never allowlistable); a `write`/`edit` outside the workdir under the global prompt templates asks once, never persistently (`Kind:"write"`, `CanAlways:false`); `Ask == nil` (a `-p` run) = deny.

## 10.5 MCP proxy (phase 5)

`internal/mcp` — no SDK, hand-rolled JSON-RPC 2.0. Pieces: the message core + `transport` interface (`jsonrpc.go`), the stdio transport, the streamable-HTTP transport + SSE reader, the `client` (handshake, paged `tools/list`, `tools/call`), the persisted index, the lifecycle `Manager`, the `mcp` proxy tool and the importer.

- **Protocol** — `initialize` (`protocolVersion 2025-06-18`, `clientInfo {moca, <version>}`) then the `notifications/initialized` notification. `tools/list` follows `nextCursor` until exhausted (a repeated cursor or more than 100 pages is an error). `tools/call` sends `arguments` (`{}` when omitted or `null`).
- **stdio transport** — one JSON object per line on the child's stdin/stdout. A reader goroutine routes responses to pending calls by id (int64, or a quoted int64 echo), answers server→client `ping` requests with `{}` (anything else `-32601`), ignores notifications, and logs non-JSON stdout lines plus stderr into a 4 KiB ring. stdout is read from a pipe moca owns (not `cmd.StdoutPipe`, whose read end `Wait` closes under the reader), and the exit handler lets the reader drain (bounded to 500 ms, also `cmd.WaitDelay`, so a grandchild holding the pipes cannot stall it) before failing anything — a reply written just before an exit, or a fatal message printed to stdout, is never lost. A process exit fails every pending call with `server <name> exited (<status>): <ring tail>` (the error keeps its `errTransportDead` sentinel, `errors.Is`-visible to the manager) — an early exit can never hang a call (also when the write itself fails, which surfaces the recorded exit error rather than a bare EPIPE). `Close` (idempotent) kills the process group via the shell runner's exported `tools.SetProcessGroup`/`KillProcessGroup` and waits for the exit with a 5 s bound (a child stuck in uninterruptible sleep must not hang shutdown). Env: `PATH HOME USER LANG TERM TMPDIR XDG_*` from moca (on Windows compared case-insensitively, plus `SystemRoot`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `TEMP`, `TMP`, `PATHEXT`, `COMSPEC` and a few more the OS needs to run a process) plus the server's explicit `env` entries (literal or `env:VAR` resolved at start; unset → error naming the variable; an explicit entry replaces the inherited variable of the same name, since duplicate names resolve platform-dependently).
- **Streamable HTTP transport** — one POST per message (JSON body, `Accept: application/json, text/event-stream`, configured `headers` with `env:VAR` resolution); `Mcp-Session-Id` captured from the initialize response and echoed on every later request; `MCP-Protocol-Version` sent once negotiated. A JSON response is matched by id; a `text/event-stream` response is read until a `data:` event carries the response with our id (server→client requests/notifications and other ids are ignored); 202 is accepted for notifications; a 404 once a session exists → `session expired`; non-2xx → error with a ≤4 KiB body (the status is checked on notifications too); `Close` sends DELETE (best-effort, bounded to 3 s — it runs under the server lock). Without an injected client the manager builds `&http.Client{Timeout: 15m}` (`defaultHTTPTimeout`) — the TUI's run context is unbounded, so a server that accepts a POST, answers `text/event-stream` and wedges must not hang a call forever.
- **Index** (`~/.local/share/moca/mcp-index.json`, 0600, unique temp file + atomic rename; `Save` merges with what is on disk so concurrent moca processes keep each other's servers) — `{server: {configHash, tools:[{name, description, annotations}], updatedAt}}`; tool **schemas are not persisted** (describe fetches them live). `ConfigHash` = sha256 over command/args/env/url/headers only, so editing `description`/`approve` never re-indexes. Missing/corrupt file → empty (search then starts servers to index them). Refreshed on every server start; an entry is valid only while the hash matches. `Rank` (search): lowercase word tokens (non-alphanumerics, `_`/`-` included, are separators); +3 per token equal to a name token, +2 contained in the name, +1 in the description; ties by server then tool name; zero-score hits dropped; empty query lists up to 20.
- **Lifecycle** (`Manager`) — **zero servers start at session start** (index present or not), and no server process is spawned except through the manager's `ensure` (start + initialize + tools/list), which only `search` (index miss), `describe`, `call` and `moca mcp index` reach. Per server: `search` serves from a valid index entry or starts the server once to (re)index; `describe`/`call` ensure (start + initialize + listTools + index refresh) on demand. The idle timer (`mcp.idleTimeout`, default 600 s) arms at start and after every call; it stops a server only with no call in flight (`busy` counter under the server lock guard, a call holds `busy` across the RPC and re-arms the timer at its end — a timer firing between two calls can never kill one). A stopped server stays discoverable via the index and restarts on demand. A call failing with a transport-dead sentinel — the stdio process exited (the error carries the stderr tail), or an HTTP response ended without our id / the session expired — drops the dead transport (the next use restarts it) and is **replayed once only when that cannot run it twice**: the request never left (`errNotSent`: the transport was already dead or the write failed), the session had expired (the server rejected it unprocessed), or the tool is read-only and non-destructive. Any other dead-transport failure is returned as `… (the call may have executed before the connection failed; check before retrying)`. Start + initialize + `tools/list` are bounded by a 60 s handshake timeout and each `tools/call` by a 15 min call timeout (a timed-out server is stopped; a caller's own cancellation is not a server failure). `search` remembers a failed start for 2 minutes instead of spawning a broken server on every query, and names every server it could not index — and an index it could not save — in bracketed notes after the hits (`describe`/`call` always retry the start); the predicate is `errors.Is` on the transports' own sentinels, never a text match on server-supplied error messages (a tool error containing "exited" must not restart a healthy server). `Close` marks the manager closed first: a call failing during shutdown never respawns a server nothing would stop. Unknown server name → error listing the configured names; unknown tool → `server x has no tool "y"; use action=search`.
- **The tool** (`mcp`) — `Spec()` returns `tools.MCPSpec()` byte-identically (phase-2 golden stays green); the system prompt carries only the phase-2 roster lines (`- name: description`), never tool lists. `search` → `server/tool — description` (whitespace-collapsed, rune-safe cut at 160 bytes) per hit + `[describe before calling]` footer; no hits → `[no matching MCP tools]`. `describe` → `server/tool`, description, `annotations: readOnly=… destructive=…`, pretty-printed input schema. `call` → text blocks joined with `\n`; every non-text block (`image`, `audio`, `resource`, `resource_link`…) → `[<type> omitted]`; the joined text is truncated at 30K chars (`tools.Truncate`); `isError` from the server passes through; Summary `server/tool`. All errors are model-facing result strings, not Go errors.
- **Gating** — a call runs without asking iff the tool declares `readOnlyHint == true && destructiveHint != true`, or it is named in `mcp.servers.<name>.approve` (the list may contain `"*"` to trust the whole server), or it was allowed-always earlier in this session. Otherwise the asker is consulted (`tools.Question{Kind:"mcp", Subject:"server/tool", Detail: <args>, CanAlways:true}`): deny or no asker (`-p` without `--yolo`) → error `refused: <server>/<tool> is not marked read-only and is not in mcp.servers.<server>.approve; the user did not approve it`; AllowOnce runs once; AllowAlways adds a session allow and (TUI `ctrl+a`) persists the tool name into `mcp.servers.<server>.approve` via `config.AppendString`, updating the `/clear` restart copy too. No name-pattern heuristics. Yolo needs no MCP-specific code (`Env.Ask` is `tools.AutoAllow` → every gated call runs, also in `-p`).
- **`moca mcp import [--yes]`** — discovery (`mcp.DiscoverSources`): `~/.claude.json` (top-level `mcpServers` + `projects[<cwd>].mcpServers`), `<cwd>/.mcp.json`, `~/.config/opencode/opencode.{json,jsonc}` (`mcp`), and Pi's files per pi-mcp-adapter's documented layout with the Claude-compatible shape: `~/.config/mcp/mcp.json`, `~/.agents/mcp.json`, `~/.agents/mcp/mcp.json`, `~/.pi/agent/mcp.json`, `<cwd>/.pi/mcp.json`. Shapes: claude `{command,args,env}` | `{type:http|streamable-http, url, headers}`; `type:"sse"` skipped (legacy SSE unsupported, noted); `enabled:false` / `disabled:true` skipped; opencode `{type:"local", command:[cmd, …], environment}` | `{type:"remote", url, headers}`. **Secrets are never copied**: a whole-value `${VAR}`/`$VAR` → `env:VAR` (nothing to export); an `env`/`headers` key matching `(?i)key|token|secret|password|auth`, a value matching `Bearer/Basic <tok>` or a known prefix, or a value that *embeds* a credential under any key (URL userinfo such as `postgres://user:pw@host`, a credential-shaped token anywhere, a `password=…` pair) (`sk-`, `ghp_`, `gho_`, `github_pat_`, `glpat-`, `xox[abp]-`, `AKIA`) → `env:MOCA_MCP_<SERVER>_<KEY>` (upper-cased, non-alnum → `_`) plus an export hint naming the source tool (never the value); other values stay literal. A credential-shaped literal **outside** env/headers (in `command`, `args`, or URL userinfo) skips the server with a note instead of copying it, and so does a server whose keys would collide on one export variable name. First source wins a duplicate name; names already configured are skipped; notes explain every skip. The preview prints each server's JSONC block + the export lines + notes; without `--yes` a `[y/N]` confirm on stdin; accepted servers are written one by one with `config.SetObjectEntry(…, ["mcp","servers"], name, <compact JSON>)`, and the summary separates written from already-present-kept.
- **`moca mcp index`** — builds a Manager over the configured servers and calls `IndexAll` (starts each once, indexes it, then `Close` stops them), printing `name: N tools` per success and the error to stderr otherwise; exit 1 if any server failed. Both `mcp` subcommands load config but need no model (they route before the model check).
- **Scope notes** — the path jail does not apply to MCP tools (a server's own scope is its own); MCP calls/results are ordinary tool calls/results for sessions, snapshots and compaction. No sampling, elicitation, MCP OAuth or legacy SSE (DESIGN §10.5 non-goals).

## 11. Permissions

- **Path jail** — root + read-only roots canonicalized once (abs + symlink resolution; a read root that does not exist yet is kept — the global skills directory often appears mid-session); relative paths join the root; `~` expands to `$HOME`; the target resolves symlinks on the deepest existing ancestor and re-appends the non-existent tail; reads are allowed inside the root or a read-only root, writes only inside the root — except the **ask-write root** `~/.config/moca/prompts` (the global slash-command templates): `Jail.Approvable` resolves a refused write there (also a read root, so a command can be read before it is updated) and the `write`/`edit` tools ask the user before using it (`Kind:"write"`, `CanAlways:false` — a plain approval question, never persisted; a denied or absent asker — `-p` — keeps the refusal, whose message points at `.moca/prompts/`). The shell's redirect/`tee` check does not use the ask-write root; a symlink out of it resolves outside it and stays refused. Windows comparison is case-insensitive and slash-normalized. Refusals name the jail ("outside the workdir … symlinks resolved").
- **Ask-write contract in the tools** — `Env.Paths` may implement `tools.ApprovablePaths` (`Approvable(path) (string, bool)`); the refused-path helper in `write`/`edit` first runs the read guard against the resolved path (an unread or stale existing file fails before the user is prompted) and then asks `Env.Ask` once. Nothing else can be approved: `Approvable` returns false inside the workdir and for every path outside the ask-write roots, and yolo's `Unjailed` never refuses in the first place (no ask).
- **Shell analysis** (Unix; parses with `mvdan.cc/sh` — unparseable input is refused): every command name is classified (the hard-deny / refused / ask-every-time classes match case-insensitively, since `SUDO`/`RM` are the real binaries on case-insensitive filesystems; an unquoted brace expansion such as `{rm,x}` in a command or target position is refused as non-literal) — **hard-deny** (no override): `sudo su doas dd shred chown` + `mkfs*`; **refused**: `eval source . exec`; builtins: `cd pwd echo printf test [ true false exit`; `rm`: ask every time; anything else: allowlisted or ask-once. Wrapper commands are unwrapped with their options parsed exactly (`env -u/-C/--unset=…`, `command -p`/`-v`, `time`, `nice`, `timeout`, `nohup`); an option the analyser cannot model refuses the command, and `env -S` is always refused. `rtk` is unwrapped too (phase 6): `rtk <tool> …` classifies both `rtk` and the wrapped command name; the runners `test`, `err`, `summary`, `run` and `proxy` classify their first command word (the word after `--` works too); shell-command-string options (`rtk run -c`, `--shell`) and unknown options refuse the command; rtk's own read-only machinery (`read`, `gain`, `json`, `deps`, `log`, `smart`, …) is allowed as plain `rtk`; native-binary proxies (`ls tree find grep rg ast-grep wc diff` — rtk forwards their flags, e.g. `rtk find -exec`) and config-mutating subcommands (`init config trust untrust learn telemetry`) classify the sub word as the wrapped command, so they must pass the allowlist (phase-6 review pass 3) (classes captured from rtk 0.51.0 in `internal/permissions/rtk.go`); wrapper and rtk subcommand names match case-insensitively (a case variant cannot skip the unwrap), and an option-shaped word after `rtk`'s `--` is refused rather than classified (phase-6 review fixes). A command word containing backslashes, globs or `$'…'` strings is non-literal and refused like `$CMD`. Redirect and `tee` targets are jail-checked (`/dev/null|stdout|stderr` exempt; numeric fd dup like `2>&1` exempt); `<>` targets are checked; after a `cd`/`pushd`/`popd` every relative redirect/`tee` target is refused (the cwd can no longer be assumed). Every segment of `|`, `;`, `&&`, `||`, subshells and command substitutions is visited.
- **Windows** — best-effort (no PowerShell parser): first token of each `;`/`|`/`&&`/`||` segment, lowercased with `.exe` stripped; ask-list extended with `Remove-Item rm ri del erase rd rmdir`; `Format-Volume` hard-denied. `rtk` is unwrapped on the same best-effort basis (the sub word, then a runner's first positional word, are classified — no quoting model; phase-6 review fix). Weaker than Unix, by design.
- **Trust store** — `~/.local/share/moca/trust.json` (0600, atomic write; keys are canonical paths): `Lookup`/`Set`. Trust gates `<workdir>/.moca/**` and `AGENTS.md`/`CLAUDE.md`. `-p` rule: explicit flag > yolo > **no** (saved decisions are ignored in `-p`); the TUI uses the saved decisions and asks once on first open of an untrusted workdir with project resources.
- **Yolo** (§7.5) — swaps the injected checkers (`permissions.Unjailed`, `permissions.AllowAll`, `tools.AutoAllow`) — never `if yolo` branches inside tools. Lifts: jail, shell analysis incl. hard-deny, approvals, trust. Stays on: `maxSteps`, read-before-write + staleness, snapshots, shell env hygiene / timeout / process-group kill / truncation. Recorded in the session header (`yolo`) and a `permission_mode` entry per `SetYolo` (between runs only).

## 12. Skills & project instructions

- **SKILL.md frontmatter** — `---`-delimited YAML subset: top-level scalars; quoted scalars unquoted (a well-formed double-quoted value unescapes Go-style; a doubled single quote is one quote); `|`/`>` block scalars (`|` keeps newlines; `>` folds everything — a blank line included — to single spaces); nested maps/lists skipped; BOM + CRLF tolerated; missing frontmatter is an error.
- **Discovery** (`skills.Discover`) — precedence: project `<workdir>/.moca/skills` (trusted runs only), global `~/.config/moca/skills`, builtin `<data>/builtin-skills/<content hash>`; first source wins a name collision; sorted by name; a skill without a description is skipped and reported; symlinked skill directories are reported and skipped (their bodies would fall outside the read jail). Discovery problems surface as `Warning` events (`warning: …` lines in `-p`).
- **Built-ins** — `internal/skills/builtin/**` embedded (`embed`); `ExtractBuiltins(dataDir)` materializes them into `<data>/builtin-skills/<content hash>` (unique temp dir + rename; a lost rename race is success) so the model can `read` them (builtin dir is a read-only jail root); extraction is content-hash keyed, so changed built-in content re-extracts on the next run (MapFS test). Currently: `rtk`. A builtin skill whose external CLI is missing from `PATH` is dropped from the prompt's skills list (`agent.filterSkills` + `builtinTools`), and the token-discipline "Prefer rtk-prefixed …" line is included only when `rtk` is on `PATH` (`PromptInput.RTK`) — moca never advertises a tool the shell cannot run (the first live ship-gate run on a host without rtk derailed on `rtk: command not found` and never read the failing test). The skill's guidance is scoped to command output: for files it defers to read/search/ls, because shell reads (`cat`, `rtk read`, …) do not satisfy the edit guard's tracked-read requirement (the third live ship-gate run drifted to shell `cat`/`ls` and never opened the failing test).
- **Ecosystem compatibility** — the vendored corpus under `internal/skills/testdata/ecosystem/` (graphify's installed skill, `anthropics/skills` skill-creator + frontend-design, npm pi packages pi-subagents + pi-mcp-adapter, an OpenCode-format skill, plus synthetic CRLF/BOM/folded/literal/colon/extra-keys/1,200-char cases) must load unchanged through `Discover` (`ecosystem_test.go`; provenance, licenses and SHA-256 in `SOURCES.md`; byte-exact fixtures pinned `-text` via `.gitattributes`).
- **Instructions** — `LoadInstructions`: global `AGENTS.md`, then (trusted only) `workdir/AGENTS.md`, else `workdir/CLAUDE.md`; each capped at 32K chars with `[… truncated at 32K chars]`.
- **Prompt templates** (phase 3) — `skills.LoadPrompts(dirs)` reads `<dir>/<name>.md` (optional frontmatter `description`/`argument-hint`; first dir wins a collision; sorted); `ExpandPrompt` substitutes `$ARGUMENTS`/`$@` (all args), `$1..$9` (whitespace-split) and `$$` (literal `$`). ## 13. Sessions & snapshots

- **Transcript** — append-only JSONL at `~/.local/share/moca/sessions/<date>-<slug>-<id8>.jsonl` (file 0600, dir 0700); every entry has `id`, `parentId` (chain), `type`, `ts`. Types: `session` (header: workdir, provider, model, **effective** effort, startedAt, mocaVersion, the full system prompt, yolo), `message`, `tool_use`, `tool_result`, `compaction` (summary + `firstKeptEntryId` + `tokensBefore` + `usage` + cumulative `readFiles`/`modifiedFiles`; its usage/cost count toward session totals and are restored on resume), `snapshot`, `error`, `permission_mode`, `model_change` (written by `/model`, `/effort`, `/hard`). `Slug`: first five words, lowercase ASCII, ≤32 chars. `ReadFile` tolerates a truncated last line; `Open` repairs it before appending (a partial line is dropped, a complete line missing only its newline gets one) and continues the chain.
- **Lookup** (`session.Find`/`FindForWorkdir`) — `--resume last` = newest by mtime (stable sort; equal mtimes keep directory-name order); `--resume <id8>` = file-name suffix match (8 hex enforced), a miss lists the 5 most recent ids; `--continue` = newest whose header workdir equals the canonical cwd (`Abs` + `EvalSymlinks`, the jail's comparison); headers are read from the first line only.
- **Rebuild** (`session.Messages`) — with a compaction entry present, the output starts with a user message `"[Summary of earlier conversation]\n<summary>"` (a kept user message merges into it) followed by entries from `firstKeptEntryId` onward; without one, the whole transcript rebuilds as before: an assistant `message` + its `tool_use` entries (by `messageId`) form one assistant message (calls after text/thinking); consecutive user-side entries merge into one user message (results first, append order); non-conversation entries are skipped.
- **Repair** — synthetic error `tool_result`s for every unanswered `tool_use` (`aborted by user` / `interrupted — moca exited before completion`); idempotent. The loop appends them on abort; resume appends them before the first resumed request.
- **Snapshots** — pre-edit content stored at `~/.local/share/moca/snapshot/<sha256>` (0600); git-tracked **clean** files are skipped (`git ls-files --error-unmatch` + empty `git status --porcelain`) and recorded `git:true`. `Undo` pops the newest record: git → message telling the user to `git restore -- <path>`; otherwise refuses if the file changed since moca wrote it, then restores content **and mode** (or deletes a file moca created). `Prune(days)` removes blobs older than `snapshot.retentionDays` (0 = keep forever) at startup.

## 14. Agent loop

- **Turn contract** — request = stored system prompt + rebuilt messages **transformed for the target model** + the seven tool specs + `tool_choice` + `maxTokens = Model.MaxTokens(context.reserveTokens)` + clamped effort. The response persists as an assistant `message` entry (text/thinking only) with `usage`/`model`/`cost`, then one `tool_use` entry per call, then a `TurnEnd` event.
- **Cross-provider transform** (phase 3, §3) — applied when building every request: thinking replays unchanged only when `block.Model == a.model.Qualified()` (adapters stamp the bare id at capture; the agent stamps the qualified id at persist time; the adapters compare against their own qualified model), anything else with text → `[prior reasoning]\n…` text block, empty → dropped; tool-call ids normalized deterministically (`NormalizeToolID`) on both use and result. Input history is never mutated.
- **Control surface** (phase 3) — `SetModel(q, effort)` (credential check first via `Registry.CheckCredential` — env lookup, or a stored login for OAuth; never the network; failure changes nothing), `SetEffort` (clamps, returns effective), `ToggleHard` (saves `{model,effort}` ↔ `modelHard`+high; both directions write `model_change`), `Models()`, `Status()` (model, effort, anchored context tokens, window, usage, cost, `Sub` = provider auth oauth, `Hard`, `Yolo`), `Steer`/`TakeSteering` (mutex-guarded queue), `AddNote` (`!` messages), `Undo`. All state the TUI reads during a run (queue, transcript mirror, usage/cost, anchor) is mutex-guarded; model/effort commands are between-runs only.
- **Loop** — no tool calls → drain steering, else done (`Outcome.Text`). Calls execute sequentially (§10); a `length`-stopped turn executes nothing — each call gets the §6 "cut off — split the work" error result instead, and a call whose arguments were cut off mid-JSON is persisted as `{}` so the run never dies on a marshal error. **Steering** is applied after every complete tool batch (before the next request); on abort the queue is untouched for `TakeSteering`. After `context.maxSteps` tool batches: one wrap-up request (user text "You have reached the step limit…", `tool_choice: none`, tools still listed) → `Outcome{MaxSteps:true}`; calls the wrap-up turn returns anyway get synthetic error results (`session.Repair`). Cancellation appends `aborted by user` results for every unanswered call and returns the ctx error.
- **Context estimate anchor** — after each successful turn: `anchor = UsageTokens(usage)`, `anchorEntries = len(entries)` (usage covers the request+response, so everything appended later is the delta); `SetModel`/`model_change`/compaction invalidate the anchor (fallback: chars/4 of the whole request). `compact.Tokens/MessageChars/RequestChars/UsageTokens` live in `internal/compact`; the status bar's `%` is this estimate vs the catalog window.
- **Compaction (phase 4, DESIGN §6)** — `internal/compact` is provider-free: it works on a neutral `Entry` view and an injected `Summarizer`. Budgets: `NewBudget(window, reserveTokens, keepRecentTokens)` scales both to `window/4` for small windows; trigger = `window − reserve`. `FindCut` may only cut at a user/assistant message (never between a tool call and its result), picks the earliest cut whose kept suffix fits `keepRecent`, falls back to the latest valid cut, and refuses (`ok=false`) when the whole live window already fits `keepRecent` — "nothing to compact". A cut that splits a turn summarizes the prior history and the turn prefix separately (two calls, merged under `## Current turn (in progress)`).
  - **Summary request**: the cheap `model` (not `/hard`), effort `minimal` clamped, `NoCacheWrite`, `max_tokens = min(4096, MaxOutput)`, no tools; the serialized input (`[User]:` / `[Assistant thinking]:` / `[Assistant tool calls]: name(k=v,…)` / `[Tool result]:`, tool results capped at 2K chars, header `COMPACTION NOTE (lossy)`) is capped to the summarizer model's window budget at 3 chars/token (`CapChars` drops the oldest lines with `[… earlier history omitted]`); a summarizer that still overflows is retried once with the newer half of the payload. Tokens spent by a compaction that then fails (e.g. the first of two split-turn calls) are still booked on an `error` entry's `usage`/`cost`. Output format: Goal / Constraints & Preferences / Progress (done · in-progress · blocked) / Key Decisions / Next Steps / Critical Context + cumulative `<read-files>`/`<modified-files>` lists (a repeated compaction updates the previous summary — `find`-style continuity from `firstKeptEntryId`, lists accumulate).
  - **Checkpoints**: `maybeCompact` before every new user prompt (start of `Run`) and after every completed tool batch (after steering); when the estimate is over the trigger it compacts, and if the estimate is *still* over it stops the run with an error naming the largest live entries (`context still over budget after compaction (N > trigger); largest entries: tool_result for read(…) ≈ Nk tokens; fixed overhead (system prompt + tools) ≈ Nk tokens` — the overhead clause appears when it dominates the estimate) — never compacts twice in a row. An indivisible over-trigger tool batch (calls+results must stay together) is the intended case: the guard names it instead of dropping fresh tool data. A summarizer that cannot run at all (cheap-model credential unset, unknown cheap model) **skips** the automatic checkpoint with `warning: auto-compaction skipped: …` — the run continues on the active model; a real provider overflow still surfaces the original error through the retry path.
  - **Overflow recovery**: a turn whose stream fails with `provider.ErrContextOverflow`, or stops `length` with the input within `reserve` of the window, becomes an internal `errOverflow` (**nothing persisted**) and is retried once after a compaction as a fresh turn; a failed compaction or a second overflow surfaces the original error. `Compacted{TokensBefore,TokensAfter}` event; the TUI prints `⋯ compacted: N → M tokens` and sets a `compacting…` transient while a manual `/compact` is in flight.
- **Resume (phase 4)** — `agent.Resume(o, path)` validates everything that can fail without touching the file first (header workdir exists, model resolves, `--model` credential, `--effort` parses), then opens the writer, appends `Repair(entries, Interrupted)` for crash-orphaned calls, reuses the stored system prompt verbatim, restores model+effort from the latest `model_change` (else the header), jails at the header's workdir, rebuilds snapshots from prior entries, restores totals from entry `usage`/`cost`, and honors only the resuming process's `--yolo`. The resuming process's `--model` (even when the stored model is no longer configured) and `--effort` replace the stored pair and are recorded as a `model_change`; a stored model that is gone without `--model` fails with a message naming it and the flag. A session that ended in `/hard` (latest model == `modelHard` ≠ `model`) resumes in hard mode, so `/hard` returns to the default model. **Session files are single-writer**: `session.Create`/`Open` hold a non-blocking `flock` for the writer's life (dropped by the kernel on exit/crash; no-op where unsupported); resuming a session another moca has open fails with `session is open in another moca process` (exit 1, nothing written — repairing its in-flight calls would double-answer them). `Start` and `Resume` share `prepare()` (registry, builtin skills, jail) and `build()`; `Resumed{ID8,Messages}` is emitted once (TUI: `resumed <id8> (<n> messages) — earlier output is in the session file`).
- **Events** — `TextDelta`, `ThinkingDelta`, `StreamReset`, `ToolStart`, `ToolEnd{Call,Result}`, `TurnEnd{Message,Usage,Cost,Stop}`, `Retry{Notice}`, `Warning{Text}`, `YoloChanged`, `SteeringApplied{Texts}`, `Compacted{TokensBefore,TokensAfter}`, `Resumed{ID8,Messages}`.
- **System prompt** — built once per run by `agent.Start`, stored in the `session` entry, never rebuilt: environment (workdir, platform, date, git state — **no hostname**), tool rules (incl. "use read/search/ls for files, not shell cat/grep/find/ls"), working style (incl. "when tests fail, read the failing test file with the read tool before changing code", "locate the cause with the search tool before editing", and "commit when the task asks"), token discipline (the rtk-preference line is scoped to shell command output and included only when `rtk` is on `PATH`), skills list (`- <name>: <desc> (<abs path>)`; builtin skills whose external CLI is missing from `PATH` are omitted), MCP server roster, project instructions. The version stamp ends the core block; core stays ~40 lines.
- **Start wiring / resume** — `Start`: jail (root + global/builtin skills read-only) → shell analyser → builtins extraction → skills discovery → instructions → prompt → snapshot prune → session create (with the prompt) → `build()`. `build(o, jailRoot, w, system, model, effort, prior, snapshotDir)` is shared with `Resume`: registry, jail, shell checker, tool env, snapshots (`NewSnapshots(w, dir, prior)`) and the agent. When `mcp.servers` is non-empty, `build()` loads the persisted index, creates the `Manager` and registers the proxy tool in place of the frozen stub (nothing starts). `Agent.Close()` stops any live MCP servers and closes the session writer — both front ends call it at shutdown, and the TUI also on `/clear` (the replacement agent gets a fresh manager from `m.start.Config`). Yolo applies at construction when requested (header records it; resume reads it only from the flag/config).

### 3.5.1 TUI additions (rev 14)

- **Response rendering (markdown-lite)** — committed response lines are rendered per line with a little state across lines (`renderMarkdown`, `internal/tui/markdown.go`): `**bold**`, `` `code` `` (amber foreground), `#` headings (bold, hashes dropped), `-`/`*`/`+` bullets → `•`, `>` quotes → `│`, and fenced code (` ``` ` / `~~~`): the opener becomes a `─ lang` label row and the closer an empty row, the code lines sit on a darker band (`#16303d` dark / `#b6cdee` light), are **never word-wrapped** (a row wider than the screen is cut at the width, so the band survives) and keep every marker literal. Spans never cross lines; an unmatched marker prints as written; everything else (links, emphasis, tables, nested lists) is untouched. Inline styles are SGR *toggles* (bold on/off, foreground set/default), never a full reset, so the band background survives; `ansi.Wrap`'s full resets at wrap points are rewritten to the same toggles. The input is sanitized first, so model text cannot inject escapes. The fence state (`model.md`) carries across streamed batches and resets at run, turn and stream-restart boundaries; the live partial line previews with a copy of it. `/copy` copies the raw markdown.
- **Spacing and layout** — a response that follows tool/thinking item lines is set off by one blank row (the live partial line carries the same gap); `›` messages hang their wrapped and later lines under the text (two cells in); item lines are clamped to one row (`…`; the full line is the pager title); `!`/`!!` commands echo as `›` messages like `/` commands (the `$ cmd` header above the output is gone).
- **Edit diffs inline** — a successful `edit` item is followed by its changed lines, indented: `-` red, `+` green, headers and context dropped, at most 8 rows, then `… N more changed lines · ctrl+o for the full diff` (`write` carries no diff).
- **Context pressure** — the status bar's percent field turns yellow from 70% of the window and red from the auto-compaction trigger (`compact.Budget.Trigger()`: window − reserve), where line 2 also says `/compact` (dropped before in/out when narrow).
- **Dropdown, generalized** — besides command names, the same panel completes the argument of `/model` (substring match; the current model and `no key` providers are marked), `/effort` (the model's supported levels), `/login`, `/logout` (providers with something stored), `/show` (items, newest first) and `/resume` (sessions): `tab` completes, `enter` on an exact argument runs. **`@path`**: when the draft's last word starts with `@`, the panel lists matching workdir files (gitignore-aware via `tools.ListFiles`, ≤ 5000 files indexed lazily on the first `@` and re-indexed after a turn or a `!` command; ranked basename prefix → path-segment prefix → substring, shallower first, ≤ 50 rows); `tab`/`enter` insert `@path ` (enter never sends while the list is open). Text is sent as written — the model reads the file itself. An email address (`@` not at a word start) never opens it. **`ctrl+r`** searches the prompt history: the draft is the query (substring, newest first, duplicates collapsed); `↑`/`↓` select, `enter`/`tab` put the match in the draft **without sending**, `esc`/`ctrl+c` leave.
- **Prompt history persists** — `history.jsonl` in the data dir (0600; `{"wd":…,"t":…}` per line), recalled per workdir (≤ 500, consecutive duplicates collapsed); messages with control bytes or over 8 KiB are not stored; a file past 4000 lines is trimmed to 2000 on load. Only submitted messages are stored (never key or redirect-URL entry).
- **Resume shows where you left off** — `agent.Resumed` (startup `--resume`/`--continue` and `/resume`) prints `resumed <id8> (N messages)` and replays the last 3 user turns through the normal paths (user bands, markdown responses, numbered thinking and tool items that open in the pager; `… N earlier turns not shown`; a compaction summary shows as `⋯ earlier conversation was summarized`). Replayed tool items summarize the call's operand (`read x.go`) — the live summary is not stored.
- **Activity row** — `⠋ shell go test ./…… 12s · ↓1.2k tok · 1 queued · esc to interrupt`: the running tool's operand (command first line / path / pattern, clamped), a streamed-token estimate (chars/4; runs only) and the number of queued steering messages (`agent.PendingSteering`).
- **Pager** — `/` searches the body (case-insensitive; the title row shows the query being typed, then `n/m`), `n`/`N` step through matches, `esc` cancels a query being typed (and only then closes). When an approval arrives while the pager is open, the title row says `⚠ approval pending — q to answer`.
- **Ollama in the TUI** — with a `providers.ollama` entry, `/model` (no argument) first re-reads the server's models (≤ 6 s, `reading models…` in the bar), then opens the picker; an unreachable server is a warning line and the picker still lists cloud and declared models. Local models are never marked `no key`. `/login` lists `ollama` as “local server; a key is only needed behind an authenticating proxy”.
- **Notifications** — the view requests focus reports; while the terminal is **unfocused** a run that took ≥ 30 s finishing, or an approval waiting, emits `tui.notify` (config; default `osc9` = `ESC ] 9 ; text BEL` desktop notification, `bell`, `off`). A focused terminal is never notified.
- **Colors** — scrollback text is converted to the terminal's color profile before printing (`tea.Println` bypasses the renderer's own downsampling): detected at startup like Bubble Tea does; `NO_COLOR` drops every color (bold/faint stay; `›` still marks user lines), 256/16-color terminals get approximations of the band colors, a non-terminal gets plain text.
- **Known limitation — narrowing the window**: terminals that reflow on shrink (tmux, kitty, iTerm2, WezTerm, VTE, Windows Terminal) re-wrap the old full-width frame rows before the renderer erases them, which can leave one duplicate rule row above the input box; the next frame is correct. Bubble Tea already erases and redraws on resize; compensating needs terminal-specific knowledge (a wrong guess erases scrollback), so it is left alone. Scrollback bands printed at the old width reflow, which is unavoidable inline.
